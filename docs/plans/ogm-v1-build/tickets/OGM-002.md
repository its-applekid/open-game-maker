## Outcome

After `ops/bin/ogm-host-setup.sh` runs as `orangekid` with no sudo, `systemctl --user status 'ogm-*'` shows `ogm-api`, `ogm-rooms`, `ogm-games`, `ogm-voice-host`, `ogm-intake` and `ogm-drive-sync` active under `ogm.slice`, the `ogm-aiur@.service` template installed under `ogm-agents.slice`, and `ogm-backup.timer` waiting for 03:30; services whose code does not exist yet run a logged placeholder instead of failing, and running the script twice changes nothing.

## Context and evidence

Supervision is already `systemd --user` on this host: linger is on, the user manager runs 246 units, and the repo's own `scripts/drive-sync/ogm-drive-sync.service` is the house pattern (E11-2) but is not installed (E11-16). cgroup v2 delegates `cpu memory pids` to the user slice, so `CPUWeight`, `MemoryMax`, `TasksMax` work without root (E11-3) and bound every Codex worker and verify Chromium the aiur daemon spawns (E11-4). Secrets come in through `EnvironmentFile=` from `~/.config/ogm/env/<unit>.env` (E11-10; names are OGM-003's). The aiur daemon becomes a template unit `ogm-aiur@<slug>` running `aiur run --container` in `ogm-agents.slice` (E11-12, D-DAEMONS). Resolved: units never hard-code a service's entrypoint; they call `ops/bin/ogm-run <name>`, which finds the built service or runs a placeholder, so OGM-010/051/007/085/064 land with no unit edit and OGM-009's move of `scripts/drive-sync` to `scripts/py/drive-sync` needs none either.

## Scope

- `ops/systemd/ogm.slice` (`CPUWeight=200`) and `ops/systemd/ogm-agents.slice` (`CPUWeight=50`, `MemoryMax=16G`, `TasksMax=4096`).
- Service units `ogm-api`, `ogm-rooms`, `ogm-games`, `ogm-voice-host`, `ogm-intake`, `ogm-drive-sync` (all `Slice=ogm.slice`), template `ogm-aiur@.service` (`Slice=ogm-agents.slice`), `ogm-backup.service` (oneshot) and `ogm-backup.timer` (`OnCalendar=*-*-* 03:30:00`, `Persistent=true`).
- `ops/bin/ogm-run`: the launcher (table of service → command, placeholder when absent, tolerant path lookup for the Python worker).
- `ops/bin/ogm-host-setup.sh`: idempotent, no sudo; creates `~/.config/ogm/env` (0700), `~/.local/share/ogm/{data,blobs,games,repos}`, `~/.local/state/ogm`; renders units with the repo path; `daemon-reload`; enables and starts the six services and the timer; prints a status table.
- `ops/test/host-setup.sh`: shell tests with a fake `systemctl` and a temp `HOME` (run by `ci / required` through the guarded ops step from OGM-001).

## Contract and invariants

Unit and slice layout (owner: this ticket; consumers: every service ticket, OGM-006, OGM-008, OGM-034):

```
~/.config/systemd/user/ogm.slice              CPUWeight=200
~/.config/systemd/user/ogm-agents.slice       CPUWeight=50 MemoryMax=16G TasksMax=4096
ogm-api ogm-rooms ogm-games ogm-voice-host ogm-intake ogm-drive-sync   Slice=ogm.slice
ogm-aiur@<slug>                                                        Slice=ogm-agents.slice
ogm-backup.timer -> ogm-backup.service (oneshot, 03:30, Persistent)
Each service: EnvironmentFile=-%h/.config/ogm/env/<name>.env  ExecStart=<repo>/ops/bin/ogm-run <name>
              Restart=on-failure  RestartSec=5  UMask=0077  NoNewPrivileges=yes  KillMode=mixed
              LogRateLimitIntervalSec=30  LogRateLimitBurst=1000  WantedBy=default.target
```

Env file names: `api.env`, `rooms.env`, `games.env`, `voice-host.env`, `intake.env`, `drive-sync.env`, `aiur.env` (shared) + `aiur-<slug>.env` (per daemon), `backup.env`. The leading `-` makes a missing file non-fatal so placeholders start; the real service fails loudly through OGM-003's loader when a name is missing.

`ogm-run <name>` resolution table (the stable seam a service ticket relies on; adding a service means the service builds to the path named here, no unit edit):

| name | runs when present | placeholder otherwise |
|---|---|---|
| api | `node $OGM_REPO/services/api/dist/index.js` | log `PLACEHOLDER api`, `sleep infinity` |
| rooms | `node $OGM_REPO/services/rooms/dist/index.js` | same |
| games | `node $OGM_REPO/services/games-host/dist/index.js` | same |
| intake | `node $OGM_REPO/services/intake/dist/index.js` | same |
| voice-host | `$HOME/.local/bin/mise exec -- $OGM_REPO/services/voice-host/_build/prod/rel/voice_host/bin/voice_host start` | same |
| drive-sync | first of `scripts/py/drive-sync`, `scripts/drive-sync`: `<dir>/.venv/bin/python -I <dir>/drive_sync.py run`, only when `~/.config/ogm/drive-sync.toml` and `~/.config/ogm/drive-sa.json` exist | log `PLACEHOLDER drive-sync: waiting for Drive setup`, sleep |
| aiur `<slug>` | `cd $HOME/.local/share/ogm/repos/<slug> && exec aiur run --container` when `.aiur/config` exists there | log, sleep (OGM-034 replaces) |
| backup | `$OGM_REPO/ops/backup/backup.sh` | log `PLACEHOLDER backup`, exit 0 |

Invariants: every unit binds nothing itself (services bind `127.0.0.1`, R69); no unit sets `ProtectHome=` (agents need `$HOME`, T11 §4); no secret value appears in any unit file or in the setup script's output.

## Failure, security, migration and accessibility cases

- A missing env file must not fail a placeholder unit (`EnvironmentFile=-`), but a real service with a missing name must fail at start with the name in the journal (OGM-003).
- Secrets: unit files and the setup script never contain or print values; `~/.config/ogm/env` is created `0700`, files are written by `ogm-env-init` (OGM-003) at `0600`; the agents slice never gets `~/.config/ogm` mounted (that boundary is OGM-037's sandbox, E11-10).
- `aiur run --container` needs `AIUR_ERLANG_COOKIE` (E11-12): the template reads `aiur.env`; without it the placeholder logs and sleeps instead of crash-looping.
- Runaway builds: the slice weights are the only bound (`io` is not delegated, E11-3); recorded, not solved.
- No migrations; no UI.
