## Outcome

When a job row reaches `admitted`, within a few seconds the game repo holds one issue per plan ticket with the `gm-job`/`gm-ticket`/`gm-sig` markers, labels `complexity:N`, `feature:gm-<jobId>` and finally `agent:todo`, a spend cap equal to the reservation set in that repo's daemon, and the daemon nudged with `control todo`; running intake again for the same job creates nothing new; the job row carries `aiurRepo`, `aiurIssueNumber` and `state: filed`.

## Context and evidence

aiur has no job-create API: filing is a GitHub issue, `agent:todo` applied by an allowed actor, and `control todo` to collapse the idle poll (E02-8). The spend cap must be set after the issue exists and before `agent:todo` (E02-4, 404 otherwise). The `feature:` label is captured by aiur telemetry (E02-16). Queued jobs never reach GitHub (E01-12, B8 §3.1). Resolved: the "builder bot credential" is the PAT of a machine user `ogm-intake` listed in `tracker.github.allowed_users`/`trusted_accounts`, distinct from the daemon's `bot_account` (`ogm-builder`), because aiur's bot identity cannot trigger its own work (aiur `website/docs-app/apis/github-auth.md:9`; T02 §6 R7); the GitHub App stays in the commit service only (R64). Admission math and the job row are OGM-013's; this ticket starts at `admitted`.

## Scope

- `services/builder/src/intake/*` in `@ogm/builder` (hosted in the API process): `fileJob(jobId)` runs the sequence: `fleet.ensureDaemon(repo, kind)` (OGM-034; `waiting_capacity` leaves the job `admitted` and reschedules) → `preflight` (OGM-037; failure marks the job `failed` with the reasons for admins, never files) → for each plan ticket: render title and body from structured fields → `issues.findByMarkers(repo, jobId, key)` → create or reuse → ensure labels exist (`feature:gm-<jobId>` created on demand) → `client.setSpendCap(n, usdFromMicro(reservation))` → `issues.addLabel(n, 'agent:todo')` → `client.nudgeTodo([n…])` → job `filed` with `aiurRepo`, `aiurIssueNumber` (first ticket) and `aiurIssueNumbers`.
- `services/builder/src/github/issues.ts`: the only GitHub writer in `@ogm/builder`: `create`, `findByMarkers` (search by `gm-job:` marker in the body via `GET /repos/:o/:r/issues?labels=feature:gm-<jobId>&state=all` then body match), `addLabel`, `removeLabel`, `setStateLabel(n, 'cancelled')` (OGM-033 uses it), `ensureLabel`; authenticated with `OGM_INTAKE_GITHUB_TOKEN`; rate-limit aware.
- Idempotency on `(gm-job, gm-ticket)`: DB first (`job_tickets` rows, timestamped migration), then GitHub by marker; a crash between steps resumes from the first missing step (cap present? label present? nudge is safe to repeat).
- Body rendering: summary, included/excluded scope, acceptance criteria, `## Load skills` from the plan's `skills[]` intersected with the shipped pack, the hidden marker comment; never a raw transcript (B8 §3.2); `gm-sig` = sha256 of the rendered body without the marker.

- The intake identity is a second machine user (`ogm-intake`, in `tracker.github.allowed_users`), distinct from the daemon's `bot_account` (`ogm-builder`), because aiur's bot identity cannot trigger its own work; both are free accounts Kevin creates (GATE-MACHINE-USERS).

## Contract and invariants

Producer. From T02 §4, verbatim:

```json
{ "title": "<validated title>",
  "body": "<summary>\n\n## Scope\n…\n## Acceptance\n…\n## Load skills\n- gm-verify\n\n<!-- gm-job:<uuid> gm-ticket:<key> gm-sig:<hash> -->",
  "labels": ["complexity:2", "feature:gm-<jobid>", "agent:todo"] }
```
Then `PUT /:n/spend-cap {"amount":"<reservation>","currency":"USD"}` and `nudgeTodo([n])`.

Invariants: `agent:todo` is the last label applied and only after the spend cap returned 200; the amount is `reservation.amountMicroUsd / 1e6` formatted with at most 6 fraction digits, never below `0.000001`; the body contains no email, no creator name, no transcript (the renderer takes only `plan.{title,summary,scope,tickets[].acceptanceCriteria,tickets[].skills}` from T01 §4's `POST /api/v1/jobs` body); `gm-ticket` is the plan ticket `key`; a second ticket with `dependsOn` gets a `Blocked by #<n>` line in the body (GitHub blocked-by edges are deferred); intake never runs for a job that is not `admitted`; `feature:gm-<jobId>` is one label per job even when the job files several tickets.

## Failure, security, migration and accessibility cases

GitHub 5xx or rate limit: retry with backoff three times, then leave the job `admitted` and alert; an ambiguous 2xx without a number (`outcome_unknown`) is reconciled by `findByMarkers` before any retry. aiur `spend_cap_exhausted` (409) on a reused issue means the ticket already ran out of budget: the job goes `paused_budget` for an admin. The intake PAT lives in the API env file; it is never written to a daemon directory or an issue. Migrations are timestamped. No UI.
