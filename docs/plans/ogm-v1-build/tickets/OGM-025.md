## Outcome

A game declares `view: 'iso' | 'topdown' | 'side' | 'follow' | 'fps' | 'orbit' | 'fixed'` and gets a camera rig with the right input meaning (stick relative to the camera, pointer lock for `fps` on desktop, touch look for `two-stick`), per-rig occlusion (cutaway walls for `iso`, fade or collide for `follow`), one rig instance per local player, and an editor camera with "view as player"; the simulation reads exactly one `ActionFrame` per player per fixed tick, merged from host frames, in-iframe keys, pointer and canvas touches, with `inject()` feeding the same path.

## Context and evidence

- E04-12: no camera contract existed; C2 §4 fixes the seven rigs, per-rig occlusion (cutaway proven in `dungeon.js`), a separate editor camera plus "view as player", and the view recorded in the lockfile. 2D rigs are Phaser camera presets, 3D rigs are Three controllers; `fps` needs pointer lock, which the OGM-028 iframe allows.
- E04-13: the host sends `input.frame` (pad and overlay); keyboard focus inside the iframe goes to the game, so the SDK reads keys itself and forwards the host's hotkeys as `input.rawKey`; the game never calls `getGamepads()`.
- E07-12, B7 §9: every client has its own rig derived from `localPlayerIndex`; frames carry `playerIndex`; camera state is presence, never design state.
- Resolved: C1's iso numbers (cutaway scale 0.28, follow lerp `dt*5`, closer zoom in play) are the defaults; the prototype is r170 and is not imported (E04-19).

## Scope

- `@gm/sdk/camera`: `createRig(view, dimension, deps)` returning a `CameraRig` (OGM-020 interface); Three rigs `iso`, `topdown`, `side`, `follow`, `fps`, `orbit`, `fixed` in `camera/three/*`; Phaser presets `iso`, `topdown`, `side`, `fixed` in `camera/phaser/*`; `RigSet` keyed by local `playerIndex`; `EditorCamera` (iso/top-down pan, wheel zoom, two-finger pan/zoom) and `viewAsPlayer(index)`.
- Occlusion: `cutaway` (objects tagged `occluder` between camera and target scale to 0.28 in y with a lerp), `fade` (raycast target→camera, hit meshes to opacity 0.25 while hit), `collide` (camera distance shortened to the first hit), `none`.
- Input mapping per rig (`inputMapping` from the contract): keyboard defaults (WASD + arrows, space, E/enter, escape), `touch: 'stick' | 'two-stick' | 'tap'`, gamepad names, `pointerLock` (`fps` only; desktop only until the device spike).
- `@gm/sdk/input`: `InputMerger` collecting host `input.frame` per `playerIndex`, in-iframe `keydown/keyup` (with the iOS/Safari preventDefault set from `dungeon.js:613`), pointer (`fps`/`orbit` look, aim), canvas touches for aiming and taps (the overlay owns sticks and buttons); `sample(tick) → ActionFrame[]` called by the fixed-step clock; `inject(frame)` from `GmTestHooks` enters the same queue; `input.rawKey` sent for `Escape` and the declared host hotkeys while the iframe has focus.
- `worldToScreen` per rig for `editor.screen` and HUD anchors.

## Contract and invariants

Consumer of OGM-020: copy from OGM-020 `packages/contracts/{input}.ts`; do not redefine. The pieces this ticket implements, as T04 §4 states them:

```ts
export type ActionValue = boolean | number | { x: number; y: number };
export type ActionFrame = { playerIndex: number; tick: number; source: 'keyboard' | 'pointer' | 'touch' | 'gamepad' | 'network'; actions: Record<string, ActionValue> };
export type ViewId = 'iso' | 'topdown' | 'side' | 'follow' | 'fps' | 'orbit' | 'fixed';
export interface CameraRig {
  id: ViewId; dimension: '2d' | '3d';
  attach(target: { position(): Vec3 }, playerIndex: number): void;      // one instance per local player
  update(dt: number, frame: ActionFrame): void;                         // stick/look relative to this rig
  occlusion: 'none' | 'cutaway' | 'fade' | 'collide';
  inputMapping: { keyboard: Record<string, string>; touch: 'stick' | 'two-stick' | 'tap'; gamepad: Record<string, string>; pointerLock: boolean };
  worldToScreen(p: Vec3): { x: number; y: number } | null;
}
```

Invariants: the simulation never reads DOM events, only `ActionFrame`s sampled at the fixed tick; a frame's `playerIndex` from the host is kept, in-iframe sources are stamped with `localPlayerIndex`; rigs are pure functions of `(dt, frame, target)` so `renderAt` reproduces them; camera state is never serialized into the design or the save; `pointerLock` is requested only from a user gesture inside the iframe.

## Acceptance and verification

### Agent gate
- Vitest (three math runs in Node): each 3D rig's `update` places the camera as specified from a fixed target and frame (snapshots); `iso` cutaway selects exactly the walls between camera and target and restores them when the target moves; `follow` fade sets opacity on the hit mesh only; `InputMerger.sample` merges a host gamepad frame and a keyboard frame for `playerIndex 0` into one frame with gamepad winning on tie, keeps a host frame for `playerIndex 1` separate, and delivers an `inject`ed frame on the next tick; `Escape` produces `input.rawKey` and no action; `fps` requests pointer lock only on `pointerdown` and never on coarse pointers. Each fails without the change.
- Playwright on the GPU flags with `GM_VERIFY_SOFTWARE_GL=1` fallback: the fixture boots with each of the seven views (`?view=`), `renderInfo().calls > 0`, `hitTest` on the player's `worldToScreen` returns true, and `renderAt(1000)` twice gives byte-equal `renderGameToText()`.
- Phaser presets: Vitest with the Phaser camera stubbed (`startFollow`, `setBounds`, `setZoom`, `setDeadzone` called with the preset values).

## Failure, security, migration and accessibility cases

- A view the family does not support (e.g. `fps` with Mini Dungeon) is a creation-flow concern (OGM-074); the rig still boots.
- Pointer lock refused → `fps` falls back to drag-look; `pointerlockerror` logged once.
- A host frame with a `playerIndex` above the local player count is dropped and counted (never crashes the sim).
- Keys are read only while the canvas has focus; the merger never attaches to `window` of the host.
- Accessibility: `reduceMotion` from `settings` disables camera shake and shortens follow lerps to a snap; no UI, no migrations, no secrets.
