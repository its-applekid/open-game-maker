## Outcome

A creator types into a job's chat and the text reaches the aiur worker; the worker's stills and clips, written from inside its no-network sandbox, appear in the same chat within seconds with media served from the blob store; aiur phase and check-in events show as system rows; the panel follows all of it over one SSE stream per job.

## Context and evidence

aiur gives the build chat text-in (`POST /api/v1/:issue/messages`), progress-out (`GET /api/v1/:issue/progress`) and events, but no attachment, image or screenshot field anywhere in its contracts (E06-13, E10-13). So the chat is OGM-owned (D-BUILD-CHAT): one message store, media in the blob store (D-BUCKET), one SSE stream, creator text mirrored to aiur messages, aiur events projected into system rows.

Contradictions already resolved: (1) T06 §4 wrote "`gm chat post` → OGM store" as an HTTP call; the game-builder sandbox runs with `networkAccess: false` in a private network namespace (E03-4: only `lo`; D-SBX), so a sandboxed command cannot reach `127.0.0.1:<api>` on the host. This ticket therefore defines the agent→OGM channel as an append-only outbox file in the job workspace that a host-side relay ships to the API (the same file-sink pattern E05-19 fixes for `$GM_EVENTS_FILE`). (2) Decision events are not in aiur's exported feed (E02-6 lists lifecycle/usage/cancel/progress only); OGM-082 polls, this ticket does not. (3) Spec v0.4 §5.5 "no raw agent messages" is superseded by D-BUILD-CHAT: agent text posts are shown as written.

## Scope

- `packages/contracts/chat.ts`: `BuildChatMessage` (T06 §4, quoted below), `AgentOutboxLine` (the outbox envelope) and the stream route shapes, as Zod schemas with emitted JSON Schema and fixtures.
- `services/api/src/build-chat/`: message store (Drizzle table, timestamped migration), routes `GET /api/v1/jobs/:jobId/chat` (SSE, `?since=<seq>`), `GET /api/v1/jobs/:jobId/chat/messages?since=` (JSON catch-up), `POST /api/v1/jobs/:jobId/chat` (creator text, mirrored through `AiurClient.message` when the job has a ticket, else held until it does).
- Outbox relay: watches `<builder workspaces root>/**/.gm/outbox/*.jsonl`, validates each line, copies media into the blob store, inserts agent rows, broadcasts on the stream; other `type`s dispatch to `services/api/src/<context>/outbox.ts` handlers found by directory scan (OGM-082 `checkpoint.open`, OGM-088 `scope.agreed`, OGM-087 `narration.render`).
- aiur progress and lifecycle → `kind: "progress"` system rows deduplicated on `aiur.event_id`, via a 10 s `AiurClient.progress()` poller for running jobs (replaced by OGM-032's feed subscriber when it lands; same dedupe key).
- Media served through the blob store's signed GET (OGM-005); `media.url` is minted at read time.

## Contract and invariants

Producer. T06 §4 "Build chat message", quoted verbatim (this is the contract; consumers copy it):

```ts
type BuildChatMessage = {
  id: string; job_id: string; at: string;
  actor: "creator" | "agent" | "system";
  kind: "text" | "image" | "clip" | "checkpoint" | "progress";
  text?: string;
  media?: { url: string; poster?: string; width: number; height: number; duration_ms?: number };
  checkpoint?: { decision_id: string; question: string; options: { id: string; label: string; media_id?: string }[]; recommend?: string; status: "open" | "answered" | "moot" };
  aiur?: { ticket: string; event_id?: number; topic?: string };
};
```
Stream: `GET /api/jobs/:job_id/chat?since=<id>` (SSE). Post: `POST /api/jobs/:job_id/chat` (creator text or dictated final transcript) → mirrors to aiur messages.

Additions this ticket fixes (append-only to the above): routes live under the API prefix as `/api/v1/jobs/:jobId/chat…`; `since` is the integer `seq` carried in the SSE `id:` field; `checkpoint.decision_id` is `""` until OGM-082 correlates it, and `checkpoint.options[].media_id` refers to a `BuildChatMessage.id` in the same job. Outbox envelope (producer: this ticket; writers: OGM-081, OGM-088, OGM-087):

```ts
type AgentOutboxLine = { v: 1; id: string /* ULID minted by the writer; becomes BuildChatMessage.id for chat.post */;
  job_id: string; at: string; type: "chat.post" | "checkpoint.open" | "scope.agreed" | "narration.render" | `${string}.${string}`;
  payload: Record<string, unknown> };
// chat.post payload: { kind: "text"|"image"|"clip"; text?: string; file?: string; poster?: string }  (paths relative to the workspace, inside .gm/outbox/media/)
```
Invariants: rows are append-only and ordered by `seq`; a line id already stored is ignored (idempotent relay); media paths must resolve inside the job workspace or the line is rejected and logged (no traversal); creator posts are accepted only for the job's creator (`authorize(actor, "job.create", {gameId})` from `packages/policy`); a creator post never blocks on aiur (mirror failures are retried, the row is stored first); the stream never emits secrets, tokens or workspace paths.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/contracts test`: fixtures validate against `chat.ts`; a fixture with an unknown `kind` fails (proves the schema is enforced).
- `pnpm --filter @ogm/api test -- build-chat`: (a) creator `POST` stores a row and calls `AiurClient.message` with `messageId = row.id` (fake client asserts headers `Origin` and `X-Aiur-Request: 1` are the client's job); (b) SSE replays rows with `seq > since` then live rows; (c) relay: appending a `chat.post` line with a PNG under a temp workspace yields an agent row whose `media.width/height` match and whose blob exists; appending the same line twice yields one row; a line whose `file` escapes the workspace is rejected; (d) poller: a fake `progress()` returning two `checkin` events yields two `progress` rows and a repeat poll adds none. Each test fails without the production change (store, relay, poller).

## Failure, security, migration and accessibility cases

- aiur down: creator rows are stored with a pending mirror flag and retried with backoff; the stream shows the row at once.
- Relay crash or restart: offsets per outbox file are kept under `OGM_DATA_DIR`; replay is idempotent on line id.
- Oversized lines (> 64 KiB) or media over 25 MiB are rejected with a logged reason, never partially stored.
- Secrets: the relay runs in the API process (host side); the sandbox holds no API token, no blob key and no aiur token. Workspace paths never appear in responses.
- Migration: one timestamped file adding `build_chat_messages`; no backfill.
- Accessibility: not a UI ticket; `media.width/height` are stored so the panel can reserve space and avoid layout shift.
