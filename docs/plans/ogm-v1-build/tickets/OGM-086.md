## Outcome

In a voice session the agent knows today's remaining allowance, the reset time, free slots and a rough size-class table, stays quiet about money when a request fits, and otherwise offers exactly trim / split / queue for the reset / ask an admin; a confirmed draft reaches admission as a job with `start: now` or `at_reset`, and when a running build hits its reservation the next `get_status` says so; all of it proven with `FakeProvider`.

## Context and evidence

The package's tool set is fixed (`get_status`, `get_details(section)`, `list_open_commands`, `propose_instruction`, `ask_agent`, `record_summary`, `end_conversation`); there is no host-defined tool, so `budget_status` becomes a briefing section plus `extra` lines and `queue_change` becomes a confirmed draft delivered through `AgentChannel.instruct` (E06-8, E06-10). Ports have 100/300 ms deadlines, so the host serves from a cache the API pushes (E06-9). The backend owns `GET /api/v1/budget/status`, `POST /api/v1/budget/estimate` and `POST /api/v1/jobs` with `start` (E01-14, T01 §4); a request that does not fit gets four offers (R12).

Contradictions already resolved: (1) C2 §5's `estimate_change(summary, game_id)` cannot be a tool; the briefing carries a coarse size-class table and the agent estimates in prose; admission is the backstop (E06-8). (2) `Config.roles`/`roles_dir` are accepted but unread at the pin (verified in OGM-085), so the creator role text is delivered as the first `extra` block of the briefing and as the text Kevin pastes into the ElevenLabs Agent prompt when a key exists. (3) The session has no host-pushed refresh at the pin (`session.ex` handles no briefing-change message; `Briefing.diff/2` is unused by the session), so a mid-build overrun cannot interrupt the agent; it is announced through `waiting_on` and the role text's rule to call `get_status` after every confirmed draft and whenever the creator asks about progress. A live push is filed upstream.

## Scope

- `services/voice-host/lib/ogm_voice/ports/briefing_source.ex`: sections `budget` (remaining in the friendly unit, reset time, free slots, queued jobs, size-class table), `progress` (job stage words, current task), `estimate` (the size-class table alone); `brief/1` adds `extra: [{title: "How to talk about budget", text: <role>}, {title: "Budget", text: <one line>}]` and `waiting_on` when a job is paused at its reservation; `limits.briefing_token_budget` 2,500 so `extra` survives rendering (`Briefing.render` drops `extra` first when over budget).
- `services/voice-host/roles/creator.md` (≤ 400 tokens): quiet when it fits; the four offers when it does not; never invent numbers; use `[later]` at the start of a draft the creator wants queued for the reset; call `get_status` after each confirmed draft and when asked about progress; summarise with `record_summary` before ending.
- `services/api/src/voice/briefing-push.ts`: builds `BriefingPush` for every live voice target from budget status (OGM-018), the job row's stage/progress (OGM-032 projection when present, else `unknown`) and queued jobs; pushes on session start (token mint), on job state change, on budget change, and every 30 s while a session is live; `observed_at` always set.
- `services/api/src/voice/instruct.ts`: `POST /internal/voice/instruct` (loopback, `X-OGM-Internal`): `build` targets → `AiurClient.message(ticket, text, idempotency_key)` and a creator row in the build chat (OGM-080 store, actor `creator`, text prefixed by nothing, `aiur.ticket` set); `scope` targets → if the scope session has a live ticket (OGM-088) → the same message path; else admission: `POST /api/v1/jobs` semantics with `start` = `at_reset` when the text starts with `[later]` (stripped), `idempotencyKey = "voice:" + idempotency_key`; a 402 becomes `waiting_on: "Doesn't fit today: trim, split, queue for <reset>, or ask an admin"` in the next push and the response `{ delivery_id, status: "needs_choice" }`.
- Overrun: when a job enters `paused_budget` (OGM-013/033), the push sets `waiting_on` and the `budget` section's first line.
- ExUnit and Vitest coverage with `FakeProvider` and fake budget responses.

Shapes this ticket fixes:

```
# briefing text the agent reads (section "budget"), one line each, friendly unit from unitLabel:
Remaining today: 2.0 stars (40%). Resets at 12:00 am. Free slots: 1 new game, 2 edits. Queued: none.
Rough sizes: small ≈ 0.5 star, medium ≈ 1–2, large ≈ 3–5, huge ≈ 6+ (low confidence).
# instruct response: { delivery_id: string; status: "delivered" | "queued_at_reset" | "needs_choice" | "failed" }
```
Invariants: the voice agent never reserves money or starts a job by itself; only a confirmed draft reaches admission (E06-10), and admission re-checks the allowance (E01-14); `idempotency_key` makes a retried delivery a no-op; the briefing never contains secrets, raw dollar figures beyond the friendly unit, or another member's data; `waiting_on` is set only from job state the API already holds; the role text contains no numbers (they come from the sections).

## Failure, security, migration and accessibility cases

- Budget endpoint down: the push omits the budget section and adds `gaps: ["Budget unavailable"]` so the agent says it does not know (never "nothing is queued").
- Admission down: instruct returns `failed`; the draft shows `failed` to the creator (package draft states) and can be re-confirmed.
- Stale cache: `observed_at` older than 60 s renders as stale in `Briefing` lines.
- Secrets: the internal route checks the shared header; no tokens in briefings; the role text is public content.
- Migration: none. Accessibility: not a UI ticket.
