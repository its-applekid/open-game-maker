## Outcome

`GET /api/v1/budget/status` and `POST /api/v1/budget/estimate` answer in the friendly unit and in micro-dollars from OGM-013's ledger and a seeded size-class table that refines itself from completed jobs; `POST /api/v1/jobs` with `start: 'at_reset'` is verified end to end as the `queue_change` path; and `services/api/src/voice/briefing-push.ts` pushes the T06 §4 briefing payload (summary, budget `extra`, `budget` and `progress` sections) to the voice host's loopback `/internal/briefing` whenever a voice session starts or the creator's budget or job state changes, within the host's deadlines.

## Context and evidence

E01-14 and C2 §5: the voice agent needs `budget_status()`, `estimate_change(summary, gameId)` and `queue_change(plan, start)`, all read-only except queue, which is ordinary admission; the estimate model has no history at launch, so a seeded size-class table with low confidence is the start. E06-8: `voice_converse` has no host-defined tool port, so `budget_status` rides on the briefing's `extra`/`sections`, `queue_change` on a confirmed draft routed by OGM-086, and `estimate_change` cannot be a tool in V1; the briefing therefore carries a coarse size-class table so the agent estimates in prose, with admission as the backstop. E06-9: port deadlines are 100 ms (`brief`) and 300 ms (`details`), so the Elixir host must serve from a cache the backend pushes, never call the backend inside a port. D-BUDGET-UNIT: amounts are api-equivalent micro-dollars shown in a per-family friendly unit. Resolved: the upstream "host tool port" is filed (decisions.md upstream list); V1 does not wait for it.

## Scope

- `services/api/src/budget/routes.ts`: `GET /api/v1/budget/status?userId=` (self, or any family member for admins) → `BudgetStatus`; `POST /api/v1/budget/estimate` → `Estimate` (`fits` = p80 ≤ remaining today).
- `services/api/src/budget/estimate.ts`: `estimate({ familyId, gameId, summary, kind?, complexity? })` → size class by the deterministic rule (explicit `complexity` wins; else a keyword and length table over `summary`), range `[p50, p80]` from `size_classes`, confidence from `samples`; `refineSizeClasses(db)` recomputes `p50`/`p80`/`samples` per `(kind, sizeClass)` from `jobs` in `done` with `usageMicroUsd > 0`, nightly and after each terminal job, never dropping below 5 samples before overriding the seed.
- `services/api/src/voice/briefing-push.ts`: `buildBriefing(target)` and `pushBriefing(target)` (`POST ${OGM_VOICE_HOST_INTERNAL_URL}/internal/briefing`, `Authorization: Bearer ${OGM_VOICE_INTERNAL_SECRET}`, 300 ms timeout, best effort); subscriptions on `budget.changed` and `job.changed` for creators with an active voice target (a small in-memory registry filled by OGM-085's token route via `registerVoiceTarget(target)` exported here).
- Unit formatting helper `toUnits(microUsd, settings)` → `{ units: number (1 decimal), label }` used by both routes and the briefing.

## Contract and invariants

Consumer of OGM-010: copy `BudgetStatus`, `EstimateRequest`, `Estimate`, `SizeClassRow`, `FamilyBudgetSettings` from `packages/contracts/budget.ts`; the T01 §4 budget block quoted in OGM-010 is this ticket's route contract; do not redefine. Producer (this ticket, "briefing push", copied from T06 §4 verbatim):
```
POST http://127.0.0.1:<port>/internal/briefing body { target_key, summary, current_task, next_steps[], waiting_on, questions[], extra: [{title:"Budget", text:"…"}], sections: [{id:"budget", text}, {id:"progress", text}] }
```
with `VoiceTarget` as in T06 §4 (`{ kind: "scope"; game_id; session_id; creator_id } | { kind: "build"; game_id; job_id; ticket; creator_id }`), `target_key = kind + ':' + (session_id | job_id)`.

Defined here:
```ts
export type Briefing = { target_key: string; summary: string; current_task: string; next_steps: string[]; waiting_on: string | null; questions: string[]; extra: { title: string; text: string }[]; sections: { id: 'budget'|'progress'; text: string }[]; observed_at: string };
export function buildBriefing(deps, target: VoiceTarget): Promise<Briefing>;
export function registerVoiceTarget(target: VoiceTarget, ttlSec?: number): void;   // OGM-085 calls after minting a token
```
Size-class rule from `summary` (when `complexity` is absent): `huge` if it matches `/multiplayer|new (world|game)|rewrite|whole/`; `large` if `/new (enemy|level|system|boss|mode)|cutscene|inventory|dialog/` or > 60 words; `medium` if `/add|new|another|more/` or > 20 words; else `small`; `kind` defaults to `feature`. Budget `extra.text` is one sentence in the friendly unit: `"<units> <label> left today (<percent>%); resets <local time>; <n> free edit slots; <k> queued."` plus a second sentence listing the size-class table in units (`small ≈ a–b, …`). Invariants: no dollars appear in any text the creator or agent sees unless the caller is an admin (`?unit=usd` admin-only); the push never blocks a request (fire-and-forget with a timeout) and failures are logged once per minute per target; `refineSizeClasses` never writes a class with fewer than 5 samples.

## Failure, security, migration and accessibility cases

The voice host being down degrades to no push (status route still works); the secret comes from the env file and is sent only to a `127.0.0.1` URL (refuse any other host at startup). Estimates are integers; `fits` compares p80 to remaining. Refinement runs in a transaction and is idempotent. No migration (uses OGM-013's tables). No UI.
