## Outcome

`bash scripts/sandbox/seed-store.sh` fills `~/.local/share/ogm/pnpm-store` from every `templates/game-*` lockfile so that, inside `codex sandbox` with network disabled, `pnpm install --offline` in a scaffolded game completes; `bash scripts/sandbox/proof/run.sh` runs the adapted B4 §6 tests on this host and writes a dated results table into `docs/ops/sandbox.md`, which also documents the new-dependency request path and the credential-boundary fallback from OGM-037's probe.

## Context and evidence

With `networkAccess: false` every agent command is network-less (E03-4), so `npm install` from the registry cannot happen inside a build; the engine templates' lockfiles plus a seeded content-addressable pnpm store are the only way builds complete, and a new dependency becomes an explicit request (E03-15). The spec demands evidence of sandboxing, not claims (E03 §3 last row); B4 §6 lists the tests, written for E2B VMs, which this ticket adapts to bwrap/Codex on one uid (E03-13). Resolved: no registry allowlist in V1 (E03-14, S3 optional); resource caps come from `systemd-run --user` scopes and the agents slice (E03-2), not from the sandbox.

## Scope

- `scripts/sandbox/seed-store.sh`: for each `templates/game-*/pnpm-lock.yaml` (and `packages/sdk` as the SDK is a workspace dependency of templates) run `pnpm fetch --store-dir ~/.local/share/ogm/pnpm-store`; accept extra `<pkg>@<version>` arguments to add single packages; print the store size and the package count; idempotent.
- Template convention (one line in each `templates/game-*/.npmrc`, added by OGM-023/024 from this ticket's text): `store-dir=${HOME}/.local/share/ogm/pnpm-store`, `offline=true`, `prefer-offline=true`; `pnpm install --offline` is what `gm new` and the build skill run.
- `scripts/sandbox/proof/run.sh` plus one script per test: `t03-cross-workspace.sh` (two workspaces, A cannot write or list B), `t06-secret-reads.sh` (E03-9 paths unreadable; `env` has no `*_TOKEN`/`*_KEY`), `t09-egress.sh` (`curl https://1.1.1.1`, `getent hosts github.com`, `/dev/udp/1.1.1.1/53` all fail; `/proc/net/dev` lists only `lo`), `t11-write-boundary.sh` (`$HOME`, `/tmp`, another daemon dir, `/usr` unwritable; workspace writable), `t13-no-git-push.sh` (`git push` from the sandbox fails: no network, no credential), `t14-resource-caps.sh` (fork bomb and a 4 GB `malloc` inside `systemd-run --user --scope -p TasksMax=256 -p MemoryMax=2G` are contained; `systemctl --user is-active ogm-api` unchanged when the API is running). Each prints PASS/FAIL/SKIP with the observed line; `run.sh` writes the table.
- `docs/ops/sandbox.md`: the boundary as built (two layers, same uid), the probe result from OGM-037 and the fallback actually in force, the proof results table (dated, host, Codex version), the seed/offline procedure, and the new-dependency request path: worker raises an aiur Command (`decision.requested`, the `aiur-agent` skill's own tool) "needs `<pkg>@<ver>` because …" → Executor or admin runs `seed-store.sh <pkg>@<ver>` and adds it to the template lockfile through a platform PR → answers the Command → worker reruns `pnpm install --offline`.

## Acceptance and verification

### Agent gate
- `bash scripts/sandbox/proof/run.sh` on this host: t09, t11, t13 PASS; t03 PASS or a recorded FAIL with the fallback named (depends on OGM-037's `deny_read` finding); t06 lists every E03-9 path with its result; t14 PASS (fork bomb contained in a scope; the scope's `memory.max` read back). A `--self-test` flag runs each script against a deliberately wrong invocation (no `--sandbox-state-disable-network`) and must then report FAIL for t09, proving the tests can fail.
- `bash scripts/sandbox/seed-store.sh` prints a non-zero package count; `pnpm install --offline` in a copied template succeeds inside the sandbox (or SKIP with reason when no template lockfile exists yet).
- `shellcheck scripts/sandbox/**/*.sh` clean if `shellcheck` is on PATH (optional).
### At-merge gate
- `ci / required` green on current main (scripts are not run in CI; they need this host).
### Human or e2e evidence
- None beyond the results table pasted into the PR and committed in `docs/ops/sandbox.md`.

## Failure, security, migration and accessibility cases

A test that cannot run (no template, `codex` missing, API not running for t14's latency check) reports SKIP with the reason, never PASS. The store is world-readable by design (no secrets in it) and lives outside any repo; `seed-store.sh` refuses to run with network disabled (it needs the registry) and refuses to write anywhere but `OGM_PNPM_STORE`. The fallback for a failed credential boundary is documented, not hidden: `docs/ops/sandbox.md` states which paths remain readable (E03-8 residual) and Kevin's optional `adduser` fix (E03-18). No migrations, no UI.
