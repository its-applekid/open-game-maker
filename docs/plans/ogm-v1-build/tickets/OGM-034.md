## Outcome

On the first admitted job for a game repo, `ogm-aiur@<slug>.service` starts from a daemon directory rendered by OGM-037, answers `GET http://127.0.0.1:<port>/healthz` within 120 s, is listed in `~/.aiur/remote-instances.yaml`, and `aiurdev --instance <slug> status` shows the repo; after 30 min with no active job the unit stops; a fifth daemon is refused with `waiting_capacity` while four are live.

## Context and evidence

One aiur daemon serves one repository (E02-12), and per-user game repos (A11) mean one daemon per active repo, capped at 4 live (D-DAEMONS; E11-4 measured a loaded host). Daemons run `instance.mode: local`, `deployment_kind: operator` on the Codex subscription (D-AIUR-MODE, E02-11), as `systemd --user` units in `ogm-agents.slice` with `aiur run --container` (E11-2, E11-12). Each daemon needs its own write token (E02-3), Erlang cookie (E11-12) and a bot PAT for `GITHUB_TOKEN` (E03-8). Resolved: no `~/.aiur/config` sharing; the T11 default "one daemon" (T11 §6 risk 8) is superseded by D-DAEMONS; `aiurdev` from the pinned checkout, not npm `aiur` (E02-17).

## Scope

- `services/builder/src/fleet/*` in `@ogm/builder` (hosted in the API process): `ensureDaemon(repo, kind)`, `stopIdleDaemons()`, `daemonFor(repo)`, `listDaemons()`; a `game_daemons` table (timestamped migration) holding the `GameDaemon` record minus the token.
- Daemon directory `~/.local/share/ogm/daemons/<slug>/` with `.aiur/{config,hooks,prompt.md}` (config from OGM-037's `renderAiurConfig`; hooks/prompt from a `DaemonFiles` provider with a built-in default until OGM-036's template package is present), `workspaces/` (the workspace root).
- Secrets per daemon: `~/.config/ogm/env/ogm-aiur@<slug>.env` (0600): `AIUR_ERLANG_COOKIE` (generated), `GITHUB_TOKEN` (`OGM_BUILDER_BOT_TOKEN` copied from the API env), `AIUR_SECRETS_FROM_ENV=1`, `AIUR_GITHUB_ALLOW_PAT=1`, `OGM_HOOK_SECRET_FILE`; `~/.config/ogm/daemons/<slug>/{client-token,read-token,hook-secret}` (0600).
- Token mint: `aiurdev token create ogm-api --scope write` and `aiurdev token create operator --scope read` run in the daemon dir; the write token feeds `createAiurClient`; the read token is referenced from `remote-instances.yaml`.
- `ops/systemd/ogm-aiur@.service`: template unit (`%i` = slug), `ExecStart=/home/orangekid/github/aiur/scripts/aiurdev run --container`, `WorkingDirectory=%h/.local/share/ogm/daemons/%i`, `EnvironmentFile=%h/.config/ogm/env/ogm-aiur@%i.env`, `Slice=ogm-agents.slice`, `Restart=on-failure`, `KillMode=mixed`, `TimeoutStopSec=65`, `UMask=0077`, `NoNewPrivileges=yes`.
- Capacity: live = `starting|running|idle` count ≤ 4; otherwise `ensureDaemon` returns `{status:'waiting_capacity'}` and the job stays in OGM-013's "waiting for robot capacity"; `max_concurrent_agents` per daemon = 1, or 2 when a creation and an edit job are admitted on the same repo (fleet total never exceeds 1+3).
- Health: poll `/healthz` every 10 s while `starting`, every 60 s while `running`; three misses → `systemctl --user restart`, then alert.
- Preflight before every start: OGM-037's `preflight(daemonDir, input)`; `{ok:false}` refuses the start and records the reasons on the daemon row.

## Contract and invariants

Producer. From T02 §4, verbatim:

```ts
type GameDaemon = { repo: "owner/name"; checkoutPath: string; unit: "aiur@<slug>.service";
  envFile: string /* GITHUB_* or token, AIUR_ERLANG_COOKIE, AIUR_OUTBOUND_WEBHOOK_SECRET? */;
  port: number; clientToken: string; status: "stopped" | "starting" | "running" | "idle" };
```

`.aiur/config` rendered from a template: `tracker.github.repo`, `base_branch`, `allowed_users: [<intake login>]`, `agent.priority: [codex, claude]`, `agent.max_concurrent_agents`, `max_turns_by_complexity`, `max_agent_duration_minutes` (45 edit / 90 new game, B8 §5), `max_dispatches_per_ticket: 3`, `hooks.after_create`, `events.export.enabled: true`, `server.host: 127.0.0.1`, `server.port: <n>`, `instance.mode: local`.

Resolved against the verbatim text: the unit name is `ogm-aiur@<slug>.service` (D-DAEMONS; `unit` carries that string); `checkoutPath` is the daemon directory (aiur reads `./.aiur/config` from its cwd; `tracker.github.repo` is explicit so no clone is needed there); `agent.priority` is `[codex]` in V1 (T03 §4 template wins: Codex-only for creators' builds until Kevin confirms the Claude fallback, T03 §6); `clientToken` is held in memory and in the 0600 file, never in the DB row. Invariants: slug = `<owner>-<name>` lower-cased, `[a-z0-9-]`, ≤ 48 chars, unique; ports allocated from 4101 upward and stored; a daemon is never started without a passing preflight; stopping never deletes `workspaces/`; `status` transitions `stopped→starting→running→idle→stopped` only.

## Failure, security, migration and accessibility cases

The unit dies on a bad cookie or missing `GITHUB_TOKEN`: `Restart=on-failure` with `StartLimitBurst=3`, then the row goes `stopped` with `lastError` and OGM-016 notifies admins. Port collision: aiur keeps running without its dashboard (configuration-daemon.md:348) but OGM's health check would fail, so ports are allocated from the table and verified free with a bind probe before render. Secrets: the bot PAT is readable by agents (E03-8 residual, accepted; the machine user is a collaborator on game repos only); the hook secret file sits under `~/.config/ogm/` which OGM-037's profile denies to sandboxed commands. Migration: one timestamped file. No UI.
