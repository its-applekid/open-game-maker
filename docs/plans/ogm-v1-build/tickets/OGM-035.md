## Outcome

`services/commit` runs as `ogm-commit.service` on `127.0.0.1:${OGM_COMMIT_PORT}`; `curl -X POST http://127.0.0.1:$OGM_COMMIT_PORT/internal/commit` with the service token and a `CommitOp` performs `create_repo`, `fold_design`, `fork`, `release`, `merge` or `set_visibility` in a creator's repo through a GitHub App installation token, with a compare-and-set ref update, and appends one audit line per op; `packages/contracts/commit.ts` exports `CommitOp`, `CommitResult`, `BoundaryVerdict`.

## Context and evidence

aiur workers push branches and open PRs themselves and nothing on main returns a patch to an orchestrator (E03-12), so the write boundary is the merge: nothing reaches `main`, a tag, a fork or a visibility flip except through this service (D-COMMIT narrows the architecture doc's "only writer" wording). aiur already mints App installation tokens in Elixir (E03-11; `app_credentials.ex`, `app_token.ex`); this service mirrors that shape in TypeScript with `@octokit/auth-app`. The App key lives only in this unit's env file (architecture §1); the game-builder daemons use a machine-user PAT as `bot_account` (E03-8). Resolved: a PAT is not acceptable here (long-lived, attributes writes to Kevin); A7 R07 CAS on the ref plus retry on 422 replaces advisory locks; repo-per-game (A11) removes the per-repo mutex.

## Scope

- `packages/contracts/commit.ts` with the verbatim types below and zod schemas; one appended line in `packages/contracts/src/index.ts`.
- `services/commit`: Hono app bound to `127.0.0.1`; `POST /internal/commit` requires `Authorization: Bearer ${OGM_COMMIT_SERVICE_TOKEN}`; `GET /healthz` per T11 §4.
- App auth: `createAppAuth({appId, privateKey})`; installation id per repo owner resolved through `GET /app/installations` and cached; installation tokens cached until 5 min before expiry; never logged.
- Operations over the Git Data API: `create_repo` (create, initial commit from a `TemplateSource`, labels, ruleset requiring `ci / required` and `ogm/boundary`, invite the builder bot as collaborator), `fold_design` (blobs → tree on `base` → commit → update `refs/heads/main` with `force: false`; 422 → re-read base and retry up to 3×), `fork` (read tree at `sourceSha`, write it as one commit into the new repo with a `Forked-From:` trailer and opaque ids), `release` (tag ref `refs/tags/gm/<gameId>/v<semver>` on `sha`), `merge` (`PUT pulls/:n/merge` with `sha` = expected head, `merge_method: squash`), `set_visibility` (`PATCH repos/:o/:r`).
- A `BoundaryGate` interface called before `fold_design`, `release`, `merge` and `set_visibility`; the default implementation refuses `set_visibility: public` and `release` on a public repo with `code: 'denylist', detail: 'content gate not installed (OGM-039)'` and allows everything else; OGM-039 replaces it.
- Audit: one JSON line per op to `${OGM_DATA_DIR}/commit/audit.jsonl` (`at, op.kind, gameId, repo, result, verdict?, actor`).
- Unit file `services/commit/ops/ogm-commit.service` (house pattern: unit beside its code, like `scripts/drive-sync/ogm-drive-sync.service`).

- `CommitOp` additionally carries `file_issue` (platform bug reports from OGM-015's `IssueWriter`), `create_branch` (OGM-043) and a `visibility` field on `fork` (OGM-048); `ogm-commit.service` ships beside the code with its own env file holding the App key.

## Contract and invariants

Producer. From T03 §4, verbatim:

```ts
type CommitOp =
  | { kind: 'create_repo'; gameId: string; owner: string; visibility: 'public'|'private'; templateRef: string }
  | { kind: 'fold_design'; gameId: string; base: string /* sha */; files: { path: string; content: string }[] }
  | { kind: 'fork'; sourceGameId: string; sourceSha: string; newGameId: string; owner: string }
  | { kind: 'release'; gameId: string; sha: string; semver: string; changelog: string }
  | { kind: 'merge'; gameId: string; prNumber: number }
  | { kind: 'set_visibility'; gameId: string; visibility: 'public'|'private' };
type CommitResult = { ok: true; sha: string } | { ok: false; verdict: BoundaryVerdict };
type BoundaryVerdict = { allowed: boolean; reasons: { code: 'path'|'size'|'secret'|'pii'|'rights'|'denylist'; path?: string; detail: string }[] };
// route: POST /internal/commit  (loopback only, backend service token); check run name: "ogm/boundary"
```

Invariants: every ref update is fast-forward only (`force: false`), so a moved `main` yields 422 and a retry from the new base, never an overwrite; commit author and committer are the App bot (`<app-slug>[bot]`), never a human name (A7 leakage); `files[].path` is normalized and must not contain `..`, a leading `/`, or a symlink target outside the tree; `gameId → repo` resolution is the API's (`GET /internal/games/:id/repo`, OGM-010/012) cached per request; a `BoundaryVerdict` with `allowed: false` is returned as HTTP 200 `{ok:false}` so callers can show reasons; the audit line is written before the response.

## Failure, security, migration and accessibility cases

The App private key is read from `GITHUB_APP_PRIVATE_KEY_PATH` (0600, under `~/.config/ogm/env/`) and never from an inline env value; installation tokens and JWTs are never logged or audited; rate-limit 403 → `Retry-After` honored once, then `{ok:false, code:'denylist', detail:'github rate limited'}`; a partial `fork` (blobs written, ref not updated) is retried from the tree step; the service refuses to start if `OGM_COMMIT_SERVICE_TOKEN` is shorter than 32 bytes. No DB migrations (audit is a file); no UI.
