## Outcome

A report routed `game_repair` by the API is replayed headless within a minute and classified `reproduces_with_error`, `reproduces_no_error` or `not_reproducible`; only the first class produces a repair ticket whose body holds the release, signature, class and an opaque `gm-report:<id>` (no bundle content), a generated `promises/<sig>.spec.ts` that fails on the current build, and diagnostics that reach the worker only through the `after_create` bundle; editor-fixable complaints come back as an `editor_hint` payload naming the control; attempt count (2) and reservation fraction (1/3) live in one config file; after the repair merges the promise test runs in `gm test` forever.

Resolved, do not reopen: no LLM in triage; a failed repair never replaces the published release; not-reproducible reports spend nothing and are stored; the bundle shape is A9 §5's (T10 §4); the ring buffer and keyframe recorder in the SDK are not this ticket's (see Sibling boundaries for the gap).

## Scope

- `packages/gm-verify/replay.ts`: `replay(bundle, buildDir): ReplayResult` — opens the build through OGM-090's driver, `setSeed`, `restore(keyframe)`, replays `actions: [[tick, action, phase]]` as `inject(ActionFrame)` between `advanceTime` steps, captures console errors and the final `renderGameToText()`, compares against the bundle's `state`/`errors`, returns the class and a replay script path.
- `services/repair/`: a worker (`127.0.0.1`, no listener needed: it polls the API) that takes reports with `route: game_repair` or `editor_hint`, fetches the bundle from the blob store through the API's signed URL, runs replay, writes the triage result back, merges a report into an open repair job when the post-replay signature matches (dedupe across equivalent reproductions), builds the `editor_hint` payload when a control covers the complaint (manifest `controls` × a keyword table), composes the repair ticket body, writes `diagnostics` for the hook bundle, generates `promises/<sig>.spec.ts`, and reads `repair.config.json` (`attempts`, `reservationFraction`, `wallClockMinutes`).
- `skills/gm-repair/SKILL.md` (≤80 lines): read `.gm/context/diagnostics.json` first, run the promise test to see it fail, "fix the first new console error first", triage order (majid debug playbook idea in our words), the Phaser-3-in-Phaser-4 and old-three fixers point at vendored migration references, keep L0–L1 green, never touch the published release, state in `.gm/changes/<jobId>.md` what behaviour changed.
- The repair ticket body and attempt-2 rework comment text; acceptance text `the promise test promises/<sig>.spec.ts passes; gm check and gm test green`.

## Contract and invariants

Consumes OGM-015's reports API (`POST /api/v1/reports` → `{ reportId, signature, route, jobId? }`; copy from `packages/contracts/reports.ts`), OGM-036's bundle shape (`{ skillPackVersion, gameContext, diagnostics? }`), OGM-031's ticket filing JSON (T02 §4) and OGM-093's `GateResult`. The bug bundle consumed (T10 §4, A9 §5 shape): `{ game, version, sdk, device, seed, keyframe: state, actions: [[tick, action, phase]], state, errors[], probes, events[], editorOps[], screenshot, words }`.

This ticket defines, quoted from T10 §4: "Repair ticket body: Title from the signature class; body: release, signature hash, reproduction class, `gm-report:<id>`, `gm-job:<uuid>`, 'Load skills: gm-repair, gm-verify', acceptance 'the promise test `promises/<sig>.spec.ts` passes; L0–L1 green'. Diagnostics arrive via the hook bundle, never in the body."

```ts
export type ReplayClass = 'reproduces_with_error' | 'reproduces_no_error' | 'not_reproducible';
export interface ReplayResult { class: ReplayClass; reason?: 'no_actions' | 'no_keyframe' | 'state_mismatch' | 'timeout';
  errorsSeen: string[]; finalState: unknown; scriptPath: string /* replay.json for the promise test */; durationMs: number }
export interface TriageResult { reportId: string; replay: ReplayResult; dedupedInto?: string /* jobId */;
  editorHint?: { controlId: string; suggestion: 'increase' | 'decrease' | 'toggle'; reason: string };
  ticket?: { title: string; body: string; labels: string[] }; diagnosticsKey?: string; promisePath?: string }
export interface RepairConfig { attempts: number /* 2 */; reservationFraction: number /* 0.333 */; wallClockMinutes: number /* 10 */ }
```

Invariants: `ticket` is set only for `reproduces_with_error`; the body never contains `words`, `screenshot`, `state` or frames; `diagnosticsKey` points at private storage the bundle endpoint resolves; `editorHint` is set only when the complaint text matches a declared control and never spawns a job; `not_reproducible` writes nothing to GitHub; the promise test imports only `@gm/sdk/test` and `replay.json` (no bundle data beyond seed, keyframe, actions, expected error); config is read at start, never hard-coded.

## Acceptance and verification

### Agent gate
- `replay.browser.test.ts`: crash bundle → `reproduces_with_error` with the error text; same bundle without `actions` → `not_reproducible` with `reason: 'no_actions'`; a bundle whose final state matches → `reproduces_no_error`; a tick that never arrives → `timeout` within `wallClockMinutes`.
- `services/repair` tests: ticket body contains the five required lines and none of the forbidden fields (a fixture with `words: "my name is …"` must not leak); `editor-hint.test.ts` ("enemy too fast" with a control `enemySpeed` → `decrease`); `dedupe.test.ts` (two bundles with the same error and equivalent final state → second `dedupedInto` first's job); `promise-gen.test.ts` (generated spec runs under Vitest against the stub and fails, then passes when `?crashAt` is removed); `config.test.ts` (missing file → the documented defaults with a warning, not a crash).

## Failure, security, migration and accessibility cases

- Bundle fetch fails or exceeds 200 KB: triage result `stored` with reason; no job.
- Replay nondeterminism (third-party randomness): compare probes with tolerances, not hashes (A9 §3.2); a mismatch is `reproduces_no_error`, never a crash of the worker.
- Prompt-injection surface: `words` is never placed in any ticket or workpad; the diagnostics file marks it as untrusted creator text in a fenced block.
- Secrets: the worker holds only its API token from `packages/config`; it never sees GitHub or aiur credentials; it binds no port.
- Migration: none in this ticket (OGM-015 owns the tables; triage results are columns OGM-015 reserved or a `report_triage` migration added here as a timestamped file if absent, named in the PR).
- Accessibility: the `editor_hint` card copy is OGM-075's.
