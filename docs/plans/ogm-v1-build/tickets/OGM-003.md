## Outcome

`@ogm/config` is the only place a service reads `process.env`: `loadEnv('api', spec)` returns typed values or throws one error naming the missing or malformed variables and never a value; `packages/config/src/names.ts` is the append-only registry of every environment name with its owning unit; `.env.example` at the root lists the same names with empty values; `README.md` documents `~/.config/ogm/env/<unit>.env` (0600, one per unit, `EnvironmentFile=`), and `ogm-env-init <unit>` creates that file with generated secrets.

## Context and evidence

Secrets on this host already live in `~/.config/ogm` (0700, files 0600) and `~/.aiur/.env`; units take `EnvironmentFile=` (E11-10). Because agents run as the same uid, file permissions are not the boundary; the boundary is the sandbox (OGM-037) plus the rule that no service logs a value and no `.env` file is committed (E03-9, E03-13, D-SECRETS). aiur's rule, copied here: validate presence by name, never print values, `.env.example` carries names only. T11 §4 names the variables; T01 adds `AIUR_API_URL`/`AIUR_API_TOKEN`; the commit service adds `GITHUB_APP_*`. Resolved: the loader reads `process.env` only (no dotenv), because systemd injects the file and local runs source it explicitly; D-API's non-TS callers (Elixir voice host, curl hooks) read the same env file directly and use the same names.

## Scope

- `packages/config`: `loadEnv(service, spec, source?)`, `ConfigError` (names only), kinds `string|secret|port|url|path|int|bool`, `redact()`.
- `packages/config/src/names.ts`: the registry `OGM_ENV_NAMES` (name, unit, kind, doc) seeded with the T11/T01/T03 names; append-only.
- `.env.example` at the repo root: every registered name as `NAME=` with a one-line comment; a test keeps it in sync with the registry and asserts no values.
- `packages/config/bin/ogm-env-init.mjs`: creates `~/.config/ogm/env/<unit>.env` at 0600 from the registry (the unit's rows plus the `shared` rows; a `secret` is reused from any existing unit file that already has it, else generated as 32 random bytes in hex; other kinds blank), refusing to overwrite.
- `packages/config/README.md`: the convention, how to source a file for local runs, the lint rule from OGM-001 (`process.env` only inside this package).

## Non-goals

- Reading or rendering env for the aiur daemons' `.aiur/config` (OGM-037, OGM-034).
- The values themselves and Kevin's hand steps (GitHub App, OAuth client: GATE-GITHUB-APP, GATE-GOOGLE-OAUTH, consumed by OGM-035/011).
- Unit files (OGM-002), ingress hostnames (OGM-006), the sandbox `deny_read` list (OGM-037).
- Any secret handling beyond presence and shape (no vaults, no rotation code; rotation is a runbook step in OGM-008).

```ts
// packages/config/src/index.ts
export type EnvSpec = Record<string, { kind: EnvKind; required?: boolean; default?: string }>;
export type EnvValues<S extends EnvSpec> = { [K in keyof S]: S[K]['kind'] extends 'port' | 'int' ? number : S[K]['kind'] extends 'bool' ? boolean : string };
export function loadEnv<S extends EnvSpec>(service: string, spec: S, source?: Record<string, string | undefined>): EnvValues<S>;
export class ConfigError extends Error { readonly service: string; readonly missing: string[]; readonly invalid: string[] }
export function redact(name: string, source?: Record<string, string | undefined>): '<set>' | '<unset>';
```

Invariants: every key in a `spec` must exist in `OGM_ENV_NAMES` (`loadEnv` throws otherwise, so new names are registered first); `ConfigError.message` contains names only; `path` kinds expand a leading `~`; `port` is an integer 1–65535; `url` parses with `new URL`; `secret` must be ≥ 16 characters.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/config test`: loader returns typed values for a complete source; throws `ConfigError` listing the missing names (and only names) when one is absent; rejects a bad port, a non-URL, a short secret; expands `~`; refuses a spec key not in the registry; `.env.example` has exactly the registry's names, in order, each `NAME=` with nothing after `=`; `ogm-env-init` writes mode `0600`, fills `secret` kinds with 64 hex chars, refuses to overwrite, and refuses a target inside the repo.
- `pnpm --filter @ogm/config typecheck && pnpm --filter @ogm/config lint`.
- Each test fails without its production change (delete `names.ts` rows or the `0600` chmod and watch the matching test fail).
### At-merge gate
- `ci / required` green on current main.
### Human or e2e evidence
- None.

## Failure, security, migration and accessibility cases

- A thrown `ConfigError` is the service's startup failure: the unit (OGM-002) restarts on failure with the names in the journal, never the values.
- `ogm-env-init` must never write inside the repository (`realpath` check against `git rev-parse --show-toplevel`) and never print the generated value; it prints the path and the names set.
- The sandbox (OGM-037) must not inherit `~/.config/ogm/env`; this package only documents it.
- `~/github/aiur/.env` at 0664 and Kevin's PAT in `~/.aiur/.env` (E03-8/E03-9) are Kevin actions recorded in OGM-008's remind entries, not code here.
- No migrations; no UI.
