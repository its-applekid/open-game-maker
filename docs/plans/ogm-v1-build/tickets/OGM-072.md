## Outcome

A new visitor on a phone sees a neutral birth month and year screen before any sign-up control, then signs in with a magic link, a passkey or Google through the Netlify-proxied `/auth` routes, connects their GitHub account and picks a default repo visibility, and lands on `/games`; a refused visitor sees one neutral line and nothing is stored about them beyond the backend's cookie.

## Context and evidence

Sign-in is email-mandatory with passkey and Google through Better Auth, magic link as recovery, no passwords (A10, E01-7, D-AUTH); spec v0.4's Google-only wording is superseded (E09-15). The age gate must precede sign-up and the OAuth start, so it is a backend cookie issued by `POST /auth/age` and this ticket only renders the screen and routes around the 403 (E01-9, T01 §4). Cookies stay first-party because `/auth/*` is a Netlify 200 rewrite (E01-8, E11-6, D-ORIGIN), so the client is created with a relative `baseURL`. Each creator connects their own GitHub so the platform can create one repo per game (A11, R6); which credential the commit service uses is OGM-035's and does not change this screen. The Google button depends on GATE-GOOGLE-OAUTH; passkey and magic link work without it (T01 §6 item 5).

## Scope

- `src/routes/age/`: `/age` with month and year selects, neutral wording (no "must be 18" before the answer), `POST /auth/age` → 204 continues to `?next` (default `/signin`); 403 renders the refused state and keeps nothing client-side.
- `src/routes/signin/`: `/signin` with email magic link (`signIn.magicLink`), passkey (`signIn.passkey`, conditional UI when available), Google (`signIn.social({ provider: 'google' })`, hidden when the backend reports it unconfigured), the "check your email" state, passkey registration offer after a magic-link sign-in, and the `?next` return.
- `src/routes/connect/`: `/connect/github` with `linkSocial({ provider: 'github' })`, connected status from `listAccounts()`, the default visibility pick (public / private; private forced when the account's family has paid packs is OGM-074's concern at creation), Continue → `?next` or `/games`.
- `src/lib/api/auth.ts`: the Better Auth client instance (`createAuthClient` with `passkeyClient()`, `magicLinkClient()`), `useSession`, `requireAge(next)`, `signOut`, `getGitHubStatus()`, `repoVisibilityDefault` get/set, and the replacement of OGM-070's stub `useSession`.
- The 403 `age_required` handling: any auth call that returns it navigates to `/age?next=<current>`.

## Contract and invariants

**Age gate (T01 §4, verbatim; OGM-011 produces, this ticket consumes).**
```http
POST /auth/age { "birthMonth": 1-12, "birthYear": 1900-2026 } → 204 + cookie `ogm_age=<signed band>` | 403 (nothing stored)
```
Sign-up, magic-link and the Google OAuth start require the cookie.

**Auth client (this ticket defines the app-side module; shapes are Better Auth's, not redefined).**
```ts
// apps/web/src/lib/api/auth.ts
export const authClient: ReturnType<typeof createAuthClient>;          // baseURL: '/auth' (same origin via the proxy)
export function useSession(): { data: Session | null; isPending: boolean };
export async function requireAge(next: string): Promise<void>;        // navigates to /age?next= on ApiError 403 'age_required'
export async function getGitHubStatus(): Promise<{ connected: boolean; login?: string }>;   // from authClient.listAccounts()
export function getRepoVisibilityDefault(): 'public' | 'private';     // localStorage 'ogm.repoVisibility', default 'private'
export function setRepoVisibilityDefault(v: 'public' | 'private'): void;
```
Invariants: no password field anywhere; the age screen never names the threshold before the answer; the client never reads or writes the `ogm_age` cookie; `useSession` is the single session source for the router's `RequireSession`; every auth request is same-origin (`/auth/...`), never the backend hostname.

## Failure, security, migration and accessibility cases

- 403 from any auth route with `age_required` → `/age`; other 4xx → inline message naming the failed step; network failure → retry button.
- Google unconfigured (GATE-GOOGLE-OAUTH open) → button not rendered; passkey unsupported (`PublicKeyCredential` absent) → passkey controls hidden, magic link stays.
- No tokens or secrets reach the client beyond the session cookie the browser holds; the GitHub link flow is an OAuth redirect handled by the backend.
- The age form uses native `<select>`s (64 px tall on phones), submit is a 64 px primary target; labels are explicit; the refused state is a single `<p role="status">`.
- No migration.
