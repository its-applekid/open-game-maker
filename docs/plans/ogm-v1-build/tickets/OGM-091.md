## Outcome

`gm new game-2d my-game` produces a game repo that boots headless and passes the hooks, carries `.claude/skills/gm-*`, `.codex/skills/gm-* -> ../../.claude/skills/gm-*`, `.agents/skills/gm-*`, `skills.lock` and an `AGENTS.md` whose first line points at `gm-core`; `gm skills sync` refreshes that pack in an existing repo without touching anything else; a Codex worker started in that repo lists `gm-core` among its skills (one dry run). `gm-core` is at most 120 lines and `gm-build` tells an agent how to install and build with no network.

## Context and evidence

aiur installs a fixed skill bundle per workspace and links only its own skills for Codex, never a repo's (E10-6, E02-9), so the `gm-*` pack must ship inside each game repo with the Codex and `.agents` links committed (D-SKILLS-IN-REPO); `gm new` writes them and OGM-036's `after_create` refreshes them. The six existing skills are Kevin-facing dogfooding skills whose rules are decided (assets first, lineup before choosing, options before the final build, look before sending, clone never edit) but whose tooling and audience are wrong for a sandbox (E10-1); `gm-core` is a rewrite, not a copy. B15 fixes `gm new` as scaffold-only (boot, hooks, input map, grey-box level, no entities) and three anti-sameness rules for `gm-core` (E10-9). Sandboxed builds cannot reach the npm registry (E03-15), so `gm-build` teaches `pnpm install --offline` from OGM-038's seeded store and the new-dependency request path. Show-as-you-go is decided for the build chat and the media path is `gm chat post` (E10-13, OGM-081). The activity taxonomy is `gm-core`'s (C2 §1).

Resolved, do not reopen: no per-ticket skill injection in aiur; `agent-sprite-forge` never enters a game repo (E10-14); `landing-page-design` and other user-level skills never reach workers (E10-11); templates are OGM-023/024/055's, this ticket copies them.

## Scope

- `skills/gm-core/SKILL.md` (≤120 lines): tier order (installed packs → mirrors → variants → made from scratch), the `gm` cheat sheet (one line per command this pack uses), done = `gm check`, `gm test`, `gm run` green, show-as-you-go (one `gm chat post` after every `gm run`), B15's three anti-sameness rules, the nine-activity taxonomy and the start/end markers, the "load when…" router table to every other `gm-*` skill and the vendored sets.
- `skills/gm-build/SKILL.md` (≤60 lines): `pnpm install --offline`, `gm build`, the new-dependency request (aiur native question, never `npm install`), where artifacts go, what to do when the store lacks a package.
- `packages/gm-cli/src/commands/new/`: `gm new <template> <dir> [--family <id>] [--pov <id>]` copies `templates/<template>` (OGM-023/024/055), installs the skill pack, writes `skills.lock`, `AGENTS.md`, `gm.lock.json` (creation choices, R20).
- `packages/gm-cli/src/commands/skills/`: `gm skills sync [--check]` (idempotent refresh of the pack and links), `gm skills list`.

## Contract and invariants

This ticket owns the skill-pack layout. Quoted verbatim from T10 §4:

> `.claude/skills/gm-*/SKILL.md`, `.claude/skills/vendor/{phaser,threejs,gamedev}/...`, `.codex/skills/<name> -> ../../.claude/skills/<name>`, `.agents/skills/<name>` (same link), `skills.lock` (`{ pack: "1.3.0", vendored: { "phaserjs/phaser": "<sha>", "CloudAI-X/threejs-skills": "0e18186", "gamedev-skills/awesome-gamedev-agent-skills": "184b72b" } }`), `AGENTS.md` pointing at `gm-core`.

```ts
export interface SkillsLock { v: 1; pack: string /* gm-cli version */; installedAt: string;
  skills: Record<string, { sha256: string }>;                // every gm-* SKILL.md and reference file
  vendored: Record<string, string> }                         // repo → commit SHA, copied from skills/vendor/skills.lock
```

Invariants: links are relative and committed; `gm skills sync` never overwrites a file whose `sha256` differs from the lock (a local edit) without `--force`, never deletes files it did not install, and is a no-op when the lock matches (`--check` exits 1 on drift); `gm new` refuses a non-empty directory; `AGENTS.md` first line is `Load .claude/skills/gm-core/SKILL.md first.`; the pack contains no user-level skill, no plugin, no hooks. Consumers: OGM-036 (`after_create` runs `gm skills sync`), OGM-092 (vendored sets copied under `.claude/skills/vendor/`), OGM-094/095/055/096 (each adds a `skills/<name>` directory; the pack is "every directory under `skills/` whose name starts with `gm-`").

## Failure, security, migration and accessibility cases

- Symlinks on a filesystem that cannot link: fall back to a copy and record `linkMode: "copy"` in `skills.lock`.
- The pack must never include `~/.claude/skills`, plugins or `agent-sprite-forge`; a test greps the installed tree for `sprite-forge` and `landing-page`.
- `gm new` writes no secrets, no `.env`; `AGENTS.md` names no hostnames.
- `gm skills sync` inside a sandbox runs with network off; it reads only the pack directory bundled with the CLI.
- No migrations; no UI.
