## Outcome

`packages/asset-cards/data/style-families.json` lists the seven C2 families with their packs, views and a measured coverage block; in a game repo whose lockfile says `family: chunky-low-poly`, `gm assets search barrel` returns only chunky-low-poly and `any` cards unless `--any-family --reason "…"` is given (which logs an `assets.family_exception` event); `GET /api/catalog/style-families` returns the families the creation flow (OGM-074) renders.

## Context and evidence

Style families exist only as a table in C2 §2; no `style-families.json`, no pack labels, and Synty rows have no category (E05-15). Collection cards carry `describe.style_family` from filename seeds (`build_collection_cards.py`), unchecked for completeness. FBX conversion is impossible here, so the two Synty-only families (detailed low poly, simple low poly) cannot be creation choices yet; Kenney families go first (E05-5, D-FAMILIES). C2 §2: a family needs characters, environment, props, UI and SFX before it is offered; one family per game, enforced in search by default with a logged exception; the creation flow offers families, not packs, each with a preview sheet. T09 §4 names the route this ticket owns: `GET /api/catalog/style-families`.

Resolved already: family ids are C3 §4's `style_family` enum (not B11's `--style` values; C3 §17.2); `photoreal` and `any` are not creation choices; `creation_choice` is set by curation (this file), never by a tagger.

## Scope

- `packages/asset-cards/data/style-families.json` and `src/families.ts` (Zod schema, loader, `familyFor(packId)`, `isCreationChoice(family)`): the seven families with `id`, `label`, `dimension`, `fidelity`, `packs: {primary, extras}` (catalog ids, verified against `catalog.json` by a test), `views`, `license_note`, `coverage` (computed), `creation_choice` (curated; Kenney families true when coverage holds, Synty families false until conversion exists).
- Coverage report: `gm packs index --families` (the flag lives in OGM-067's command; until it merges, `pnpm --filter @ogm/asset-cards families:coverage`) recomputes `coverage` from the index: `characters` (any `model/character|creature` or `sprite/character` card in the family's packs), `environment` (`model/kit|nature|building` or `sprite/tile`), `props`, `ui`, `sfx` and `music` (from `any`-family audio packs count as satisfied); writes the block back and fails when a `creation_choice: true` family lacks characters, environment or props.
- `gm assets search` default: when run inside a game repo with `assets.lock.json`, `family` defaults to the lock's family and the filter is `style_family ∈ {family, 'any'}`; `--family <id>` overrides for a lineup; `--any-family --reason "<text>"` lifts the filter and emits `assets.family_exception {family, reason, query}` (R55 "logged exceptions"); outside a game repo no default applies.
- `services/api/src/catalog/routes.ts`: `GET /api/catalog/style-families` → `[{ id, label, dimension, fidelity, views, creationChoice, coverage, packs: [{ id, name, thumbnailUrl }] }]` from the data file plus collection-card titles; `thumbnailUrl` is a signed blob URL when OGM-067 has imported the collection thumb, else `null`; public read (no auth; the data is not private), cached in memory, ETag.

## Contract and invariants

Style families (producer T05; consumers OGM-074 creation flow, OGM-091 `gm-core`, OGM-062 `use` family rule), quoted from T05 §4:

> `style-families.json`: `[{id, dimension: '2d'|'3d', fidelity, packs: {primary: [], extras: []}, views: PovId[], license_note, coverage: {characters, environment, props, ui, sfx, music}}]`

```ts
// packages/asset-cards/src/families.ts
export type StyleFamily = { id: StyleFamilyId; label: string; dimension: '2d' | '3d'; fidelity: string; packs: { primary: string[]; extras: string[] };
  views: PovId[]; license_note: string; coverage: { characters: boolean; environment: boolean; props: boolean; ui: boolean; sfx: boolean; music: boolean }; creation_choice: boolean };
export const StyleFamilySchema: z.ZodType<StyleFamily>;
export function loadFamilies(): StyleFamily[];
export function familyFor(packId: string): StyleFamilyId | undefined;
export function computeCoverage(index: CardIndex, f: StyleFamily): StyleFamily['coverage'];
```

API (consumer OGM-074): `GET /api/catalog/style-families` → `StyleFamilyApi[]` where `StyleFamilyApi = { id; label; dimension; fidelity; views; creationChoice; coverage; packs: { id: string; name: string; thumbnailUrl: string | null }[] }`, declared in `packages/asset-cards/src/families.ts` (not in `packages/contracts`, which stays OGM-010's) and re-exported by the route; OGM-074 imports the type from `@ogm/asset-cards`.

Invariants: every pack id in the file exists in the catalog (test); the seven ids are exactly `chunky-low-poly`, `detailed-low-poly`, `simple-low-poly`, `pixel-art`, `flat-cartoon`, `isometric-2d`, `sketch`; `creation_choice` requires `coverage.characters && environment && props`; the search default never widens rights; the exception event carries the reason text and nothing else from the game.

## Failure, security, migration and accessibility cases

The route exposes only ids, labels, titles and signed thumbnail URLs (never library paths or private previews: Synty thumbs are `private/` and return `null` until a signed URL exists for authenticated members); the exception event stores the reason text only; a malformed `style-families.json` fails the package build, not the CLI at runtime; no migration; the UI consumer (OGM-074) keeps 64 px tiles.
