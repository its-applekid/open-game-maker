## Outcome

`pnpm --filter @ogm/tools-skills eval -- --config with_skill,baseline --confirm` builds ten briefs twice on the signed-in Codex or Claude CLI inside scratch game repos made by `gm new`, runs `gm check`, `gm test` and `gm run` on each, computes M1 (jscpd leakage %), M4 (unasked mechanics from the checklist against `renderGameToText()` keys and a grep) and M5 (card-default fingerprint from the exported tunables) per run, and writes `evals/skills/results/<date>/benchmark.md` with pass rate, time, tokens and the three metrics per config; it never runs in CI and refuses to start without `--confirm`.

## Context and evidence

B15 §5 defines the metrics and §6 ships the eval with the first genre skill: 10 briefs × 2 configs (`with_skill`, `baseline`; an optional `full_reference` config answers Kevin's reference-game question once), scripted per-run assertions M1/M4/M5 now, set metrics M2/M3/M7 after ten games exist (E10-9). It plugs into skill-creator's shape (`evals.json`, `grading.json` with `text/passed/evidence`, `benchmark.md`) but shells out to the local agents, so the cost is subscription quota, not money; it runs on demand before a skill change merges, never on every PR (T10 §6). `jscpd` (6.4k stars, MIT) is the M1 tool. M4 reads `render_game_to_text()` keys plus a grep checklist (double jump, coins/score, lives counter, dash, wall-jump, health bar, top-left score HUD, "Game Over" title). M5 counts tunables equal to card example values, which is why OGM-094's cards give ranges and `tunables` data (D-SKILLS-IN-REPO keeps the pack in repos; the eval runs on the platform copy).

Resolved, do not reopen: no paid judges, no embeddings in V1 (M3 is deferred), no CI gating, scratch repos are local directories (no GitHub), briefs are text only.

## Scope

- `evals/skills/briefs/*.md`: 10 briefs spread across genres with at least 3 that fit no template ("a cooking rhythm game", "a lighthouse-keeper puzzle"), plus 2 near-duplicates for a later M7; `evals/skills/evals.json` in skill-creator's prompt shape; `evals/skills/configs/{with_skill,baseline,full_reference}.json` (which skills are installed, `full_reference` points at an operator-provided corpus path and is skipped when absent).
- `evals/skills/checklists/unasked-mechanics.json` (M4) and the M5 rule (tunables equal to any card's example value from the card's `## Test` or prose numbers).
- `tools/skills/eval.ts`: runner (scratch dir per run via `gm new`, config applied by removing skill dirs, the brief passed to `codex exec` or `claude -p` with a fixed system line "build the game described; finish with gm check, gm test, gm run"), per-run `grading.json`, timing and token capture from the CLI's own usage output where available, `results/<date>/benchmark.md` table, `--dry-run` (everything except the agent call), `--confirm` gate, `--agent codex|claude`, `--max-parallel 1` default.
- `evals/skills/README.md` (≤30 lines): when to run, what the ship gate is (pass rate not lower, M1 under threshold, M4 zero, M5 under half), how to read the sheet.

## Contract and invariants

Consumer of OGM-090's `VerifyReport`, OGM-093's `GateResult`, OGM-094's card format (`tunables`), OGM-091's `gm new`. This ticket defines the eval record:

```ts
export interface EvalRun { brief: string; config: 'with_skill' | 'baseline' | 'full_reference'; agent: 'codex' | 'claude';
  dir: string; startedAt: string; durationMs: number; tokens?: { input: number; output: number };
  gates: { check: boolean; test: boolean; run: 'pass' | 'fail' | 'error' };
  m1: { duplicatedPct: number; largestClone?: { file: string; lines: number } };
  m4: { unasked: string[] }; m5: { total: number; equalToCardExample: number };
  passed: boolean /* gates green ∧ m1 < threshold ∧ m4 empty ∧ m5 < total/2 */ }
```

Invariants: no agent call without `--confirm`; scratch dirs live under `evals/skills/.runs/` (gitignored by `evals/skills/.gitignore`); results commit only `benchmark.md` and `grading.json` per run (no game source, no media); the M1 corpus is the card snippets plus a fresh `gm new` scaffold diffed out; thresholds live in `evals/skills/thresholds.json` (`m1Pct: 15`), never in code.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/tools-skills test`: M1 over the fixture with a planted copy of a card snippet → `duplicatedPct` > 0 and the clone named; M4 with a `doubleJump` key in the dump and no "double jump" in the brief → `['double jump']`; M5 as the worked example; `passed` logic; the runner in `--dry-run` creates a scratch dir via `gm new`, applies the `baseline` config (no `gm-genre-*` dir present), and writes a `grading.json` with `agent: 'skipped'`; starting without `--confirm` and without `--dry-run` exits 2.
- `pnpm -r typecheck && pnpm -r lint`.
### At-merge gate
- `ci / required` green on current main; CI must not invoke `eval` (a test asserts no workflow or package script other than `eval` references it).
### Human or e2e evidence
- One real run of 2 briefs × 2 configs on this machine with Kevin's go (quota), results committed under `evals/skills/results/<date>/`; the sheet of `gm shot --sheet` across the four games attached to the PR for the "do these look alike" glance (B15 §5.2 human check).

## Failure, security, migration and accessibility cases

- The agent CLI is rate-limited or signed out: the run records `gates.run: 'error'` with the CLI's message and continues; the summary marks the config incomplete.
- Briefs are untrusted-shaped text sent to a coding agent in a scratch dir with no secrets and no network beyond the agent's own; the runner passes `--sandbox workspace-write` to Codex and the equivalent permission mode to Claude; never `danger-full-access`.
- No provider keys; subscriptions only (R14); the README says the cost in builds.
- No migrations, no UI.
