## Outcome

`sdk.achievements.award('first-dungeon')` called 1,000 times concurrently from a published build yields exactly one `achievement_awards` row and one `newlyAwarded: true`; the same call from a draft build records nothing and the SDK shows a "(test)" toast; `sdk.analytics.attemptStart/attemptEnd/marker/complete` events land pseudonymised, draft sessions are excluded from `GET /api/v1/games/:g/analytics/overview`, the nightly rollup fills `creator_analytics_daily`, and raw events older than 90 days are deleted.

## Context and evidence

Achievements are permanent account awards keyed by stable slugs in `achievements.json`, idempotent on `(user, game, key)` with `INSERT … ON CONFLICT DO NOTHING`, validated against the catalog of the session's published release, never awarded in drafts; removing a key needs `retired: true` and retired keys cannot be reused (E08-13; A5 §4.3; spec §5.18). Creator analytics are first-party events plus daily rollups with a four-call SDK vocabulary, `pseudoUserId` = HMAC of the user id with a rotating per-game salt, no IPs, free text or UA, `env='draft'` excluded, 90-day raw retention; separate from T01's build analytics and from T07 presence (E08-14; A5 §5.2–5.5; A12 drops cell suppression). Rooms as awarding authority stay later; `source: 'room'` is allowed in the column (E08-13). Resolved here: a catalog is registered per release by OGM-045 at publish through this ticket's `registerCatalog`; an award whose `releaseId` has no registered catalog is a draft and returns 422 `not_published` (the SDK never sends one from a draft build anyway).

## Scope

- Tables (timestamped migrations): `achievement_defs (game_id, key, title, description, icon_path, hidden, target NULL, first_release_id, retired_release_id NULL, PK(game_id, key))`, `achievement_awards (user_id, game_id, key, release_id, source, awarded_at, PK(user_id, game_id, key))`, `achievement_progress (user_id, game_id, key, value, PK(user_id, game_id, key))`, `creator_analytics_events (id, ts, game_id, branch_id, release_id NULL, env, pseudo_user_id, session_id, name, scope NULL, marker NULL, outcome NULL, props JSON ≤ 1 KB)`, `creator_analytics_daily (game_id, day, release_id NULL, metric, scope NULL, value, PK(game_id, day, release_id, metric, scope))`, `analytics_salts (game_id, salt, rotated_at)`.
- `services/api/src/achievements/{routes,lint,catalog,store}.ts`: `registerCatalog(gameId, releaseId, defs)` with `lintCatalog(prev, next)` (missing key without `retired` → error; reuse of a retired key → error); `POST /api/v1/games/:g/achievements/award {key, releaseId}` → `{newlyAwarded}`; `POST …/progress {key, value, releaseId}` → `{value, newlyAwarded}` (monotonic max, auto-award at target); `GET /api/v1/games/:g/achievements` (catalog with the caller's awards; hidden shown as `???` until earned); admin `DELETE …/awards/:userId/:key` with an audit row.
- `services/api/src/creator-analytics/{routes,ingest,rollup,query,pseudonym}.ts`: `POST /api/v1/games/:g/play-events {events: Omit<AnalyticsEvent,'pseudoUserId'|'gameId'>[]}` (server stamps `pseudoUserId`, caps 1 KB props, 200 events per request, 5 requests/min per session); nightly `rollup` script (`pnpm --filter @ogm/api rollup`) computing plays, players, attempts and clear rate per scope, median active time, completion rate, drop-off (furthest marker), stuck, version adoption; retention delete of raw rows older than 90 days; creator query routes `GET /api/v1/games/:g/analytics/{overview,funnel,attempts,releases}?from&to` (`env='published'` only).
- `packages/sdk/src/achievements.ts` (`award`, `progress`; client-side dedupe; draft/test builds emit nothing and raise a local `toast('(test)')` hook) and `packages/sdk/src/analytics.ts` (`attemptStart`, `attemptEnd`, `marker`, `complete`; emits `event {kind:'analytics'}` over the bridge); platform events (`session_start/end`, `active_heartbeat`, `game_load_failed`, `error`, `bug_report`, `update_offered/accepted`, `save`, `load`) are named in the contract comment for the host app (OGM-075) to emit.

## Contract and invariants

Consumer: copy `AchievementDef` and `AnalyticsEvent` from OGM-040's `packages/contracts/src/saves.ts`; copy the `event` envelope from OGM-020's `packages/contracts/src/bridge.ts`; do not redefine. Invariants: an award is `INSERT … ON CONFLICT DO NOTHING` and `newlyAwarded` is `changes() === 1`; the key must exist, not be retired, in the catalog registered for `releaseId`; progress stores `max(old, new)` and awards when `value >= target`; no award or progress row is written for a release without a registered catalog; `pseudoUserId = hex(HMAC-SHA256(salt_game, userId))`, salt rotated by the rollup every 30 days (events before a rotation stay under the old pseudonym; rollups already aggregate); raw events never hold free text (the schema forbids any `props` key not in the allow-list `{device, input, tier, release}`); `env='draft'` is stored for the creator's own "test runs" counter only and excluded from every creator metric; raw rows older than 90 days are deleted by the rollup job; `achievements.json` lint runs at publish via `registerCatalog`.

```http
POST /api/v1/games/:g/achievements/award {key, releaseId}       → 200 {newlyAwarded: boolean} | 422 {error:'unknown_key'|'retired'|'not_published'}
POST /api/v1/games/:g/play-events {events: [...]}               → 202 {accepted: n, rejected: n}
GET  /api/v1/games/:g/analytics/overview?from=2026-11-01&to=…   → {plays, players, medianActiveSec, completionRate, testRuns, byRelease: [...]}
```

## Acceptance and verification

### Agent gate
- Achievements API: 1,000 concurrent awards → one row, one `newlyAwarded:true`; unknown or retired key → 422; unregistered `releaseId` → 422 `not_published` and zero rows; progress monotonic and auto-award; lint rejects a vanished key and a reused retired key, accepts title changes; admin revoke writes an audit row.
- Analytics API: `pseudoUserId` is stamped server-side and differs across games for the same user; a `props` key outside the allow-list is rejected per event; a 1.1 KB `props` is rejected; 201st event in a request → 413; rollup on a fixture day yields the expected plays, players, clear rate, drop-off and stuck values; `overview` excludes `env='draft'`; rows older than 90 days are deleted by the rollup and rollup rows remain; salt rotation changes new pseudonyms only.
- SDK: `award` in a `published` build emits one `event {kind:'achievement'}` even when called every frame; in `draft` emits nothing and calls the toast hook with `(test)`; `attemptEnd` without `attemptStart` is dropped with a console warning; events carry `scope`/`marker`/`outcome` only.
- `pnpm -r typecheck`, `pnpm lint`.

- `ci / required` green on current main.

## Failure, security, migration and accessibility cases

The client is trusted plus validation, catalog check, rate limit and admin revoke (invite-only product; A5 §4.3 "Trust"); no anti-cheat. Per-game salts live in the database, not in env; no IP, UA or free text is stored; deleting an account deletes its raw events (hook for OGM-012's deletion flow, exported `deleteUserEvents(userId)`). Rollup is idempotent per day (upsert) so a rerun is safe. Two timestamped migrations. Toast and dashboard accessibility belong to OGM-075/OGM-079.
