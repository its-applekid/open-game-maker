## Outcome

With `services/api` running on `127.0.0.1`, an editor can acquire the edit lease for `(gameId, branchId)`, `POST` a transaction with `baseRev` and receive `{rev}`; a stale `baseRev` gets 409 `{headRev}`, a stale lease 423; `GET …/transactions?after=N` streams every later transaction as SSE; `GET …/design?rev=N` returns the effective design doc at that revision; a second device of the same owner takes the lease over silently.

## Context and evidence

The transaction stream is persisted, undone, replayed and relayed from one record (E08-1); watchers receive the stream after the backend accepted it and catch up from a snapshot at a revision (E07-5, R73), which is why `GET …/design?rev=` exists here and not in the rooms service. The lease is a single writer per branch draft fenced by `(leaseToken, baseRev)` with a 15 s heartbeat and 2–3 min expiry; same-user devices take over silently; admins never take over (E08-16, release plan §6 Q5). Store: SQLite WAL through Drizzle, owned by the single API process (E01-2, D-DB), so the append is one `BEGIN IMMEDIATE` transaction with no advisory locks. Resolved: `/api/v1` is the mount prefix (OGM-010); T07 §4.2 wrote `/api/games/...` and is served at the `/api/v1` path.

## Scope

- Tables (timestamped migration): `branches`, `design_transactions` (unique `(branch_id, rev)`), `edit_leases` (PK `(game_id, branch_id)`); `ensureMainBranch(gameId)` creating the `main` row lazily.
- `POST /api/v1/games/:g/branches/:b/transactions` body `Omit<Transaction,'id'|'rev'|'createdAt'>` → 200 `{rev}` | 409 `{headRev}` | 423 `{lease}` | 413 | 422 (validation from OGM-040).
- `GET /api/v1/games/:g/branches/:b/transactions?after=<rev>` → `text/event-stream` of `Transaction`, `id:` = rev, `Last-Event-ID` honoured, 25 s keepalive comments.
- `GET /api/v1/games/:g/branches/:b/transactions?after=<rev>&format=json` → array (watcher resync, tests).
- `GET /api/v1/games/:g/branches/:b/design?rev=N` → `{ rev, buildId, doc }` effective doc at rev ≤ N.
- `POST /api/v1/games/:g/branches/:b/lease` `{sessionId}` → `{token, expiresAt}`; `POST …/lease/heartbeat`; `DELETE …/lease`.
- `BaseDocSource` interface with an fs implementation reading the build's `design/*.json` from the release directory (OGM-007 layout) and an in-memory one for tests.

## Contract and invariants

Consumer of OGM-040: copy `Transaction`, `DesignDoc`, `Branch` from `packages/contracts/src/{design-log,branches}.ts`; do not redefine. Routes above are this ticket's contract (consumers: OGM-042/043/044/045, OGM-053, OGM-075). Invariants: `rev` assigned by the server as `headRev + 1` inside one SQLite transaction; a write is accepted only if `baseRev === headRev` and `leaseToken === edit_leases.token` for the caller's session (or `kind: 'system' | 'merge'` with the service token, `leaseToken: 0`); transactions are never updated or deleted; the SSE stream emits only committed rows in rev order; `design?rev=N` is `replay(chain, upTo N)` on the base doc of the branch's `latestBuildId` (empty doc `{schemaVersion:1, globals:{}, entities:{}}` when no build exists).

```http
POST /api/v1/games/:g/branches/:b/lease {sessionId}       → 200 {token, expiresAt} | 403 (not the owner)
POST /api/v1/games/:g/branches/:b/transactions             → 200 {rev} | 409 {headRev} | 423 {holder:'other-session'} | 413 | 422
GET  /api/v1/games/:g/branches/:b/transactions?after=N     → SSE  event: tx  id: <rev>  data: <Transaction JSON>
GET  /api/v1/games/:g/branches/:b/design?rev=N             → 200 {rev, buildId, doc}
```

## Failure, security, migration and accessibility cases

Lease expiry on a dead tab: the next heartbeat from a new session takes over; the dead session's writes get 423 and OGM-075 discards its undo stack. SQLite busy under a concurrent reader: `busy_timeout` 5 s, writes serialized by `BEGIN IMMEDIATE`. SSE behind the Netlify proxy: keepalive comments every 25 s; the client reconnects with `Last-Event-ID`. Patches are validated (`validatePatches`) so no path outside `globals`/`entities` is stored or relayed (R76). Service-token writes (`kind: 'system' | 'merge'`) come only from loopback callers with the token from `packages/config`; no secret is in a route body. Migration is one timestamped file; no UI.
