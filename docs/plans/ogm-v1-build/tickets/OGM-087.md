## Outcome

A game's dialogue lines are rendered once each (keyed by content hash) into Opus files plus alignment JSON in the blob store, and the SDK's `SpokenText` plays a line with its caption highlighted sentence by sentence; the whole path runs today against `FakeProvider` (silent audio, 250 ms per word) and switches to real speech when a provider key and an upstream `render_speech` adapter exist.

## Context and evidence

`VoiceConverse.Narration.render/2` and `render_to_file/3` exist in the core and return PCM plus `alignment: [{text, start_ms, end_ms}]`, write WAV atomically, cap `max_chars` at 5,000 and deadline at 60 s; only `FakeProvider` implements `render_speech/1`, the two live adapters do not, so a real render returns `{:error, :unsupported}` today (E06-5). Captions are zero-cost; rendered narration needs a key (E06-12). The fake provider makes the path testable now (E06-18). Audio for games is MP3 for samples (iPhone), with Opus acceptable for narration as a second file (E05-17, T04 audio).

Contradictions already resolved: (1) "Narration rendered once and cached by content hash" (release plan) is implementable now except the adapter: the cache key is `sha256(JSON{text, voice, engine, version, speed, lang})` (B2 §5.1); the adapter request is upstream (decisions.md upstream list 4). (2) The sandboxed agent cannot call the API; a render request from inside a build is an outbox line (`narration.render`, OGM-080's envelope) handled by this ticket; the actual trigger in V1 is the API after a tested build registers (OGM-045) and `gm narrate` (T10's namespace) writing that line. (3) The SDK must not depend on `@ogm/voice-client`; `SpokenText` carries its own 10-line `speechSynthesis` fallback.

## Scope

- `services/voice-host/lib/ogm_voice/http/narration.ex`: `POST /internal/narration { text, voice_id, format: "pcm_24000" }` (loopback, `X-OGM-Internal`) → `Narration.render_to_file(text, <OGM_VOICE_RENDER_DIR>/<sha>.wav, provider:, privacy:, credentials: {OgmVoice.Ports.Credentials, provider_id}, format:, voice_id:)` → `{ wav_path, format, alignment }`; `{:error, :unsupported}` → 501 `{ error: "provider_has_no_render" }`; `:provider_auth` → 503.
- `services/api/src/narration/{routes,render,cache,outbox}.ts`: `POST /api/v1/games/:gameId/narration/render { lines: [{ id, text, voice?, lang? }] }` (creator or build service) → per line: key → blob exists? skip : host render → `ffmpeg -i <wav> -c:a libopus -b:a 48k` → `BlobStore.put` as `narration/<key>.opus` and `narration/<key>.json` (alignment + meta) → response `[{ id, key, audio_url, alignment_url, cached }]`; outbox handler `narration.render` with the same payload from a job workspace; concurrency 2; 25 lines per request.
- `packages/sdk/src/audio/spoken-text.ts`: `SpokenText.load({ key, audioUrl, alignmentUrl })`, `play({ onSentence, onEnd, bus: "voice" })` through the SDK audio module (OGM-027: `voice` bus, SDK-owned context, unlock rules), sentence grouping from word alignment, `cancel()`, and a `speechSynthesis` fallback when no audio is available (`SpokenText.fromText(text)`).
- Manifest entry shape for narration assets consumed by the loader (OGM-026) documented here; the build pipeline that lists them is OGM-063's.

## Contract and invariants

Producer. T06 §4, quoted verbatim:

**Narration render (this track; key-gated).** `POST http://127.0.0.1:<port>/internal/narration` `{ text, voice_id, format: "pcm_24000" }` → `{ wav_path, alignment: [{text,start_ms,end_ms}] }`; OGM transcodes to Opus and stores at `narration/<sha256>.{opus,json}` in the bucket (T05).

Fixed here (append-only):
```ts
type NarrationKeyInput = { text: string; voice: string; engine: "fake" | "elevenlabs" | "openai"; version: 1; speed: number; lang: string };  // key = sha256(JSON.stringify(sorted))
type NarrationMeta = { key: string; text: string; voice: string; engine: string; lang: string; duration_ms: number; format: "opus"; alignment: { text: string; start_ms: number; end_ms: number }[] };
type NarrationManifestEntry = { kind: "narration"; key: string; audio: string /* content-hashed file */; alignment: string };  // for assets/manifest.json (OGM-063 writes it)
// SDK
export class SpokenText { static load(e: { key: string; audioUrl: string; alignmentUrl: string }): Promise<SpokenText>; static fromText(text: string, lang?: string): SpokenText;
  play(o?: { onSentence?: (i: number, s: string) => void; onEnd?: () => void }): { cancel(): void }; sentences(): string[] }
```
Invariants: a key is rendered at most once per engine (blob existence is the check); `text` ≤ 5,000 chars (package cap) and one line per request item; the host never stores WAV beyond the render dir (cleaned after upload); the privacy policy from OGM-085 applies to renders (`ProviderPolicy.check`); no provider key in the API process; `SpokenText` never autoplays before the SDK audio unlock; alignment segments are monotonic (package guarantee) and sentences are built only from them.

## Failure, security, migration and accessibility cases

- Host returns 501 (no adapter): the API records `unsupported` and the game falls back to captions plus `SpokenText.fromText()`; nothing is cached.
- ffmpeg failure: the WAV is deleted, the line reported `failed`, nothing partial in the blob store (content-addressed put is atomic).
- Secrets: provider credential only in the host env; the API holds none; render requests carry text only.
- Migration: none (blob store keys only). Accessibility: captions are always available (R21); sentence highlighting is text-based; the player exposes `sentences()` for screen readers.
