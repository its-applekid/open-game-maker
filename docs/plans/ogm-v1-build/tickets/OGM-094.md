## Outcome

`gm docs pattern jump` prints the jump-buffer-and-coyote card (TypeScript, role names, tunables as ranges, when-not-to-use, a 3-line `advanceTime` test); `skills/gm-genre-platformer/SKILL.md` routes a platformer brief to four to six such cards and the vendored `gamedev/platformer` and `phaser/physics-arcade` references; every card's test passes in Vitest against the SDK's fixed-step clock.

## Context and evidence

B15 decided: no whole games in context; themeless TypeScript pattern cards of 300–800 tokens with tunables as ranges and a 3-line `advanceTime` test, under each genre skill's `references/`, fetched with `gm docs pattern <topic>`; `gm new` is scaffold-only and the genre comes from the skill (E10-9). The awesome-gamedev platformer skill has the knob table (apex 0.30–0.40 s, coyote 0.08–0.12 s, buffer 0.10–0.15 s, fall gravity 1.5–2×, corner correction; derive gravity from height and time) and is Apache-2.0, vendored by OGM-092 (B14 pipeline §4.2). C1 names the prototype patterns that become cards: hit-feedback tiers, deadzone camera (iso + cutaway was 3D; the 2D deadzone camera is this ticket's) (C1 §9 row 5). The eval (OGM-097) ships with this first genre skill; M5 counts how many tunables equal card example values, so cards give ranges, never one number.

Resolved, do not reopen: cards are written by us from MIT sources and ideas; nothing copied from no-licence or copyleft repos; the 2D base is Phaser 4.2 (OGM-024); the sameness eval is OGM-097's, this ticket only makes cards evaluable.

## Scope

- `skills/gm-genre-platformer/SKILL.md` (≤60 lines): when to load, the core loop of a platformer brief (read the scope's feel words → pick values from card ranges → build grey-box → `gm run --rig side`), the card index, the vendored references to open (`vendor/gamedev/platformer`, `vendor/gamedev/feel-tuning`, `vendor/phaser/physics-arcade`, `vendor/phaser/tilemaps`, `vendor/phaser/cameras`), pitfalls (tunnelling at high speed, one-way platform re-entry, camera snapping).
- Cards in `skills/gm-genre-platformer/references/cards/`: `jump-buffer-coyote.md`, `deadzone-camera.md`, `one-way-platforms.md`, `hit-feedback-tiers.md`, plus optionally `variable-jump-height.md` and `corner-correction.md`. Each: front matter (`topic`, `engine: phaser|three|both`, `tunables: [{ name, range, unit, from: 'brief feel words' }]`, `license`, `source` when a source was read), one TS snippet against `@gm/sdk` types, "when to use / when not", "no obvious extras" note, a 3-line test.
- Card tests as runnable files: `skills/gm-genre-platformer/references/cards/*.test.ts` run by `pnpm --filter @ogm/skills-tests test` (a tiny Vitest package under `skills/` is OGM-091's pack dir; see plan U4 for where the runner lives without a new root glob).
- `packages/gm-cli/src/commands/docs/pattern.ts`: `gm docs pattern <topic> [--engine phaser|three] [--max 3]` prints 1–3 cards whose `topic` or front-matter `aliases` match, from every installed skill's `references/cards/`; `gm docs pattern --list`.

## Contract and invariants

Consumer of OGM-091's skill-pack layout and OGM-020's `ActionFrame` (copy, do not redefine). This ticket defines the card format that OGM-095 and OGM-097 read:

```yaml
---
topic: jump-buffer-coyote          # gm docs pattern <topic>
aliases: [jump, coyote, buffer]
engine: phaser                      # phaser | three | both
tokens: ~520
tunables:
  - { name: jumpBufferMs, range: [100, 150], unit: ms, from: "snappy vs forgiving" }
  - { name: coyoteMs, range: [80, 120], unit: ms, from: "forgiving ledges" }
  - { name: apexSeconds, range: [0.30, 0.40], unit: s, from: "floaty vs weighty" }
license: Apache-2.0                 # when adapted; MIT for our own with sources named
source: gamedev-skills/awesome-gamedev-agent-skills@184b72b… genres/platformer (ideas; knob ranges)
---
```

Invariants: role names only (`Player`, `Hazard`, `Pickup`); no theme, colours or fiction; no card adds a mechanic beyond its topic; tunables are exported as data (`export const tunables = { jumpBufferMs: /* pick from range */ 0 }` with a `// pick from the brief` comment, never a filled default); every card has a test whose body is three statements using the SDK clock (`advanceTime`); `gm docs pattern` prints cards verbatim and never summarises.

## Acceptance and verification

### Agent gate
- Card tests pass (each fails when its snippet's logic is broken: delete the coyote window and the coyote test fails).
- `pnpm --filter @ogm/gm-cli test`: `docs-pattern.test.ts` (topic match, alias match, `--max`, `--list`, unknown topic → exit 2 with the list hint, verbatim output).
- A format test over `skills/*/references/cards/*.md`: front matter keys present, every tunable has a two-element range, no fenced block language other than `ts`, token estimate 300–800 (chars/4), no word from a theme blocklist (`goblin`, `knight`, `coin`, `castle`, colour names).
- `wc -l skills/gm-genre-platformer/SKILL.md` ≤ 60.
- `pnpm -r typecheck && pnpm -r lint`.
### At-merge gate
- `ci / required` green on current main.
### Human or e2e evidence
- None (the sameness eval in OGM-097 is the product-level check).

## Failure, security, migration and accessibility cases

- A card with a filled default value: the format test fails (M5 guard).
- `gm docs pattern` in a game repo with no cards: exit 2 and "run gm skills sync".
- No network, no secrets, no UI, no migrations.
