## Outcome

Five directories `skills/gm-{input,ui-hud,audio,scope-options,editor-tuning}/` each hold a `SKILL.md` of at most 80 lines written against the merged SDK (`ActionFrame` and the manifest's action map, the HUD model and the platform HUD, the audio module with ZzFX and Tone 15 `getTransport()`, the creation options and the scope ticket, the manifest's `controls`), each with one test that fails if the skill names an SDK export or `gm` command that does not exist, and `gm-core`'s router has one row per skill.

## Context and evidence

B14 §2 fixed per skill what to adapt, borrow or write: `gm-input` adapts awesome-gamedev `input-systems` plus Phaser's input skill and majid's "input intents" idea, adding touch and gamepad; `gm-ui-hud` adapts `game-ui-ux` (anchors, safe areas, gamepad focus, event-driven HUD) with the game-studio HUD budget (≤20–25% of the screen, centre clear) and majid's HUD state checks; `gm-audio` adapts `audio-design` plus majid's Web Audio manager shape and writes the ZzFX part; `gm-scope-options` borrows majid's "Scope" paragraph and adapts `prototype-fast`/`game-jam` (three clearly different takes for a vague brief, B15 §2 item 5); `gm-editor-tuning` borrows lil-gui live tuning ideas and "tune by outcome" knob tables with CCGS tunables-as-data. `game-ui-ux` measured low value in C1 and `landing-page-design` must stay out (E10-11), so `gm-ui-hud` is short and points at the platform HUD the host owns (OGM-075). The skills target the SDK that now exists: `ActionFrame` merge and the seven rigs (OGM-025), audio buses, `unlock()`, `zzfx`, `song` (OGM-027), `GameManifest.controls` (OGM-020), the scope ticket and checkpoints (OGM-088, OGM-081/082).

Resolved, do not reopen: `gm-multiplayer-ready` moved to OGM-055 with the room protocol (E10-18); `gm-saves-achievements`, `gm-vfx`, `gm-kitbash-3d`, `gm-sprites-2d`, `gm-music-compose`, `gm-dialogue-narration` are not in V1's build order; no majid files are vendored, only ideas in our words.

## Scope

- `skills/gm-input/SKILL.md`: actions over keys (the manifest's declared actions), edge vs held, deadzones, buffering (points at the platformer card), touch overlay is host-owned (64 px primary targets), gamepad read by the host only, `ActionFrame.source`, per-player index; one card `references/cards/action-map.md` in OGM-094's format.
- `skills/gm-ui-hud/SKILL.md`: the host's platform HUD vs the game's HUD, `HudModel` per player, safe-area insets from the `viewport` envelope, reference-resolution scaling, text ≥ 16 px at phone DPR, ≤25% coverage with the centre clear, read-along defaults, state inventory (title / play / paused / won / lost) and a still of each in `gm run --frames`.
- `skills/gm-audio/SKILL.md`: buses `music|sfx|amb|voice`, `unlock()` on first `pointerup`, `audioSession` playback, ZzFX presets with pitch variation for repeats, MP3 samples from packs through `gm assets use`, Tone 15 `getTransport()` and `song.json` for music, `renderCue` to check peak/RMS, iOS `audio.relay`, "sound is `unchecked` in V1".
- `skills/gm-scope-options/SKILL.md`: read the creation choices (`gm.lock.json`), when a brief is vague offer three clearly different takes as a `gm checkpoint open` with ≤3 options, user words set the bar, a narrow edit stays narrow, ask only when a choice materially changes the result, write the agreed scope back as the job's acceptance list.
- `skills/gm-editor-tuning/SKILL.md`: every tunable in `src/tunables.ts` as data, declared in `manifest.controls` (`ControlDecl`) with ranges from the cards, scope labels, `applyDesign` must read tunables from the design doc not from constants, "tune by outcome" table (feel word → which knob), no lil-gui in production builds.
- One Vitest test per skill (`skills/<name>/skill.test.ts`) that extracts backticked `gm …` commands and `@gm/sdk` identifiers from the SKILL.md and asserts each exists (commands against the CLI registry, identifiers against `@gm/sdk`'s exports).
- One router row each in `skills/gm-core/SKILL.md`.
