## Outcome

`provisionGameRepo({gameId, owner, visibility, kind})` leaves a new repo on GitHub whose initial commit holds `.github/workflows/ci.yml` (check `ci / required`), `.claude/skills/gm-*`, `.codex/skills/gm-*` and `.agents/skills/gm-*` links, `AGENTS.md`, `skills.lock`, labels from aiur's list and a ruleset requiring `ci / required` and `ogm/boundary`; the same call renders that repo's `.aiur/{config,hooks,prompt.md}` into its daemon directory; and the `after_create` hook, run by aiur, fetches `GET /internal/jobs/by-ticket/<id>/bundle` with the per-daemon secret and writes `.gm/context/`.

## Context and evidence

`aiur init` is an interactive wizard (E02-14); OGM creates repos programmatically, so it must reproduce init's outputs from a template. aiur installs only its own skills and links only those for Codex (E02-9, E10-6), so the `gm-*` pack ships inside each repo with its own links (D-SKILLS-IN-REPO). Hooks receive the ticket id and branch (E02-10), which is how the job bundle reaches the worker (R65). Resolved: R62's `.aiur/*` are rendered per repo but written to that repo's daemon directory on this host, not committed, because a committed config carries absolute host paths and the intake login (E03-10 shows exactly that; A7's leakage list names paths); `human_mergers: []` because OGM merges through its App (E02-13); the intake login in `allowed_users` is a machine user distinct from `bot_account` (aiur `github-auth.md:9`: the bot identity cannot trigger its own work).

## Scope

- `packages/game-repo-template` (`@ogm/game-repo-template`): `renderRepoTemplate(ref, ctx)` → `{files, labels, requiredChecks}` implementing OGM-035's `TemplateSource`; `renderDaemonFiles(ctx)` → `{hooks, prompt}` implementing OGM-034's `DaemonFiles`; fixtures for both.
- Repo files: `.github/workflows/ci.yml` (job `required`, `pnpm install --frozen-lockfile`, `pnpm run check`, `pnpm run test`, `GM_VERIFY_SOFTWARE_GL=1`), `AGENTS.md` (points at `gm-core`, names `gm check`/`gm test`/`gm run`, the `## Local tests` rule), `.claude/skills/gm-*/` copied from `skills/gm-*/` at the pack version, `.codex/skills/<name> -> ../../.claude/skills/<name>` and `.agents/skills/<name>` symlinks (git mode 120000), `skills.lock`, `.gitignore` (`node_modules/`, `.gm/`, `dist/`), `README.md`, plus the engine scaffold from `templates/game-{2d,3d,multiplayer}` when present (OGM-023/024/055; a `gm new`-shaped placeholder otherwise).
- Labels: aiur's required set (`agent:<state>`, `agent:<reason>`, `agent:watch`, `agent:paused`, `complexity:1..5`, `flake`) plus `feature:*` is created per job by OGM-031.
- `.aiur/hooks`: `after_create` = clone, branch `aiur/<issue>`, `curl` the bundle with the secret from `$OGM_HOOK_SECRET_FILE`, write `.gm/context/bundle.json`, refresh `.claude/skills/gm-*` when `skills.lock.pack` differs from the bundle's `skillPackVersion`; `before_remove` = `git status --short`. `.aiur/prompt.md`: the Liquid template from aiur's starter with OGM's rules (read `AGENTS.md`, load the skills the issue names, post to the build chat, never touch `.gm/`).
- `services/builder/src/provision.ts`: `provisionGameRepo(input)` = commit service `create_repo` (OGM-035) → `fleet.ensureDaemon` is *not* called here (OGM-031 does on first job) but the daemon directory files are rendered so OGM-034 finds them → record `games.repo` on the API row.
- `services/api/src/internal/bundle.ts`: `GET /internal/jobs/by-ticket/:identifier/bundle` and `GET /internal/skills/:version.tgz`, authenticated by `Authorization: Bearer <hook secret>` resolved to one daemon (and so one repo); refuses a ticket from any other repo.

## Contract and invariants

Producer. From T02 §4, verbatim:

**after_create hook contract (T02 → T10)** — `GET <ogm>/internal/jobs/by-ticket/$AIUR_HOOK_TICKET_IDENTIFIER/bundle` (per-daemon secret) → `{skillPackVersion, gameContext, diagnostics?}` written to `.gm/context/`; never provider keys.

Bundle shape this ticket fixes:

```ts
type JobBundle = { v: 1; jobId: string; gameId: string; repo: string; kind: 'new_game'|'feature'|'repair';
  skillPackVersion: string; skillPackUrl: string /* loopback, same bearer */;
  gameContext: { title: string; family: string; pov: string; genre: string; multiplayer: boolean; branch: 'main'; lockfilePath: 'assets.lock.json' };
  diagnostics?: { reportId: string; bundleKey: string /* private bucket key, fetched by gm-repair through gm */ } };
```

Invariants: the bundle route resolves the bearer to exactly one daemon row and refuses (404, no detail) any ticket whose job is not in that daemon's repo; the bundle never contains tokens, keys, cookies, email addresses or the creator's name; the hook writes only under `.gm/context/` and `.claude/skills/gm-*`; `skills.lock` is `{ pack: "<semver>", vendored: {...} }` as T10 §4 defines; symlinks are relative; `AGENTS.md` names the exact commands CI runs; rendering is deterministic for a given `templateRef`.

## Acceptance and verification

- `pnpm --filter @ogm/game-repo-template test`: rendered file list equals the fixture; every `.codex/skills/*` and `.agents/skills/*` entry is a relative symlink to an existing `.claude/skills/*` path; `skills.lock.pack` equals the pack version; `ci.yml` names job `required`; hooks text equals the fixture and contains no absolute host path; prompt renders through a Liquid engine with a sample issue. Each fails without its rule.

- `pnpm --filter @ogm/builder test`: `provisionGameRepo` posts one `create_repo` op with the rendered template, renders the daemon files, updates the game row; a commit-service `{ok:false}` propagates the verdict.
### At-merge gate

### Human or e2e evidence
- One Codex dry run (E10-6, T10 risk): on a provisioned scratch repo, a ticket whose body says "Load skills: gm-core"; the PR or workpad shows the skill was read. Done with OGM-100 if the daemon is not up yet.

## Failure, security, migration and accessibility cases

The hook's `curl` failing (API down) must not abort the clone: the hook writes `.gm/context/bundle.missing` and exits 0 so the worker can still read the issue; `gm-core` treats a missing bundle as "ask for context". The hook secret is readable only outside the sandbox (OGM-037's profile denies `~/.config/ogm`); its scope is one repo's bundles, read-only. Public repos: `.gm/` is gitignored so bundles never land in Git; OGM-039 also denies the path. No migrations (uses `games.repo` from OGM-012). No UI.
