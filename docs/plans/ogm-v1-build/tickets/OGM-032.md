## Outcome

While a daemon runs, every `ticket.*.lifecycle.changed`, `usage.*`, `cancel.result` and `agent.progress*` record it emits lands as a row in `aiur_events`, the matching job row's `stage`, `stageText`, `phase`, `progressPercent` and `lastEventSeq` update within one second, and an admin can read `GET /api/v1/jobs/:id` and see "Building" or "Out of budget" where aiur says `running` or `budget-exhausted`; open aiur Commands for a job appear as `checkpoints` rows within 15 s.

## Context and evidence

Job state is a projection of aiur lifecycle events into creator words (R27). aiur exports those events on a loopback WebSocket feed with replay from a cursor (E02-6); the signed webhook needs HTTPS and waits for local TLS (E02-6, R2). Progress is the agent's own 10 %-step estimate (E02-5); the spend cap trips inside aiur and ends in `budget-exhausted` (E02-4); cancel confirmation arrives as `cancel.result` (E02-7). Direction checkpoints are aiur Commands that are not on the outbound feed, so they are polled (E06-15). Resolved: B8's "GitHub webhooks as the authoritative record" is replaced by the feed plus `GET /api/v1/:issue` polling (D-JOB-BUS); no watchdog.

## Scope

- `services/builder/src/events/*`: `startFeedConsumers(fleet)` subscribes (`@ogm/aiur-client` `subscribeEvents`) to every `running` daemon with patterns `ticket.*.lifecycle.changed`, `ticket.*.usage.*`, `ticket.*.cancel.result`, `ticket.*.agent.progress*`, from the persisted cursor per daemon; handles `reset` by re-reading `GET /api/v1/:issue` for every active job of that daemon; stops when the daemon stops.
- Polling fallbacks per active job: `progress(issue)` every 30 s (phase, percent), `issue(issue)` every 60 s (tracker state label, waiting reason) and immediately after a `reset`; `decisions()` every 15 s per daemon while any job of it is `running|paused` (supervisor token).
- `services/api/src/jobs/projection.ts`: pure `projectStage(input)` and the creator-word table; `applyAiurEvent(db, daemon, record)` writes `aiur_events` (dedupe on `(daemon, seq)`), updates the job row, emits an in-process `job.stage.changed` event (consumed by OGM-033 for reservation release and OGM-016 for notifications), and writes/updates `checkpoints` rows from decisions.
- Migrations (timestamped): `aiur_events(daemon_slug, seq, topic, ticket, job_id, payload, observed_at)`, `aiur_cursors(daemon_slug, last_seq, epoch)`, `checkpoints(decision_id, job_id, version, question, options, recommend, status, opened_at, answered_at)`; job columns `stage`, `stage_text`, `phase`, `progress_percent`, `last_event_seq`, `aiur_run_id`.

## Contract and invariants

Producer. From T02 §4, verbatim:

**job state projection (T02 → T01/T09)** — aiur `lifecycle.changed`/labels → OGM stage: `queued|waiting(capacity|provider_limited)` → "Waiting for robot capacity"; `running` → "Building"; `ci-wait` → "Running final tests"; `rework` → "Fixing a problem"; `human-review` → "Ready to try"; `budget-exhausted` → "Out of budget" (admin decision); `error|cancelled` → friendly failure.

**event intake (T02)** — WebSocket `events:feed` subscription per daemon (token from `POST /api/v1/events/token`), patterns `ticket.*.lifecycle.changed`, `ticket.*.usage.*`, `ticket.*.cancel.result`, `ticket.*.agent.progress*`; optional `POST <ogm>/internal/aiur/webhook` verifying Standard Webhooks headers (E02-6) once TLS exists.

Projection type this ticket fixes (consumers OGM-013, OGM-076, OGM-079 copy it):

```ts
type JobStage = 'queued_ogm' | 'waiting_capacity' | 'waiting_provider' | 'building' | 'final_tests' | 'fixing' | 'ready' | 'out_of_budget' | 'paused' | 'done' | 'failed' | 'cancelled';
type ProjectionInput = { ogmState: 'queued'|'admitted'|'filed'|'running'|'paused_budget'|'done'|'failed'|'cancelled'; lifecycle?: 'queued'|'retrying'|'allocated'|'running'|'paused'|'waiting'|'replaced'|'completed'|'cancelled'; trackerState?: string; reasonLabels?: string[]; spendCapReached?: boolean; prMerged?: boolean };
export function projectStage(i: ProjectionInput): { stage: JobStage; text: string };
```

Invariants: `projectStage` is pure and total (every input yields a stage; unknown combinations map to the last known stage with `text` unchanged, never to "failed"); precedence: `ogmState` terminal states win, then `spendCapReached`, then `trackerState`, then `lifecycle`; `budget-exhausted` is "Out of budget" and never auto-retried; `error` text is friendly and never contains aiur's reason string; events are idempotent on `(daemon_slug, seq)` and applied in `seq` order per daemon; a `reset` never deletes rows; the cursor is advanced only after the transaction commits.

## Failure, security, migration and accessibility cases

Feed down (`events_unavailable`, socket closed): the consumer backs off and the 60 s `issue()` poll keeps the stage moving; the daemon being `stopped` ends the consumer cleanly. `feature_disabled` is a config bug (OGM-037 renders `events.export.enabled: true`) and is logged as an alert, not retried silently. Decisions polling uses the supervisor token only; it reads, never answers (OGM-033). Payloads are stored as received (no prompt text is on these topics; `agent.progress` carries phase and percent only). Migrations are timestamped. No UI.
