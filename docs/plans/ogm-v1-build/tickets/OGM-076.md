## Outcome

While a build runs, a 64 px FAB with a progress ring sits over every screen; a tap opens the bar ("2 builds · about 3:00 left"), another opens the list of jobs, and a job opens its chat: the agent's stills, clips and one-line captions arrive as they are posted, the creator replies by typing, by push-to-talk dictation with review before send, or by two-way voice when a provider is configured; each job row shows the creator-words phase, friendly progress and usage in the family's unit; jobs queued for the daily reset show their start time with Edit and Cancel; the FAB glows when something finished; on a phone the chat is a full-height sheet.

## Context and evidence

The prototype tracker (`studio-v0/app.js:561-615`, `index.html:632-643`) is a fake timer with three states (collapsed → open → expanded) and a "something finished" glow; D-BUILD-CHAT turns it into a per-job chat with agent-authored posts (E09-6, E06-19). The message shape `BuildChatMessage` and the streams `GET /api/jobs/:job_id/chat?since=` (SSE) and `POST /api/jobs/:job_id/chat` are OGM-080's (E06-13). Dictation is the browser Web Speech API with push-to-talk and review-before-send; read-aloud is `speechSynthesis`; two-way voice is wired against the voice host and turns on when a key exists (D-VOICE-ZERO, E06-11, E06-12). Resolved: spec v0.4 §5.5's "no raw agent messages" is superseded (E09-6); the app never talks to aiur directly (E09-11); amounts are api-equivalent micro-dollars shown in a friendly unit (D-BUDGET-UNIT).

## Scope

- `BuildChatDock`: FAB (ring = combined progress of active jobs, count, green glow until opened when a job finished) → bar (summary line, combined bar, chevron) → list (one row per job: kind, title, phase in creator words, progress, usage, time left) → per-job chat. Mounted once by the app shell; hidden when there are no jobs.
- Job list source: the jobs list route from `packages/contracts/jobs.ts` (OGM-010/013) filtered to the signed-in creator, refreshed by the notifications SSE (OGM-016) and a 30 s poll while any job is active.
- Per-job chat: `MessageList` over `GET /api/jobs/:job_id/chat?since=<id>` with reconnect from the last id; rows by `actor` and `kind`: `text` (agent text gets a read-aloud button), `image` (webp with width/height reserved), `clip` (mp4 with poster, inline, muted until tapped), `progress` (system row), `checkpoint` (read-only row: question, options with media thumbnails, status; answering is OGM-082's card, swapped in through `rows/index.ts`).
- Composer: text; dictation through `@ogm/voice-client` `dictation` (push-to-talk, partial captions, final text shown for review, Send/Discard); voice mode through `@ogm/voice-client` `client` with a token from `POST /api/voice/token` and `VoiceTarget { kind: 'build', game_id, job_id, ticket, creator_id }`, shown only when the token route answers 200 (503 `voice_unavailable` hides it).
- Post: `POST /api/jobs/:job_id/chat { text }` for typed and dictated-final text; optimistic row, reconciled by id.
- Usage: `formatUnits(microUsd, unit)` where `unit` comes from the budget status route (`unitLabel`), e.g. "1.5 of 4 coins"; progress and phase strings come from the job row's projected fields (OGM-032), never computed here.
- Queued-at-reset rows (`state: 'queued'`, `start: 'at_reset'`): the reset time, Edit (navigates to `/new?job=<id>`, OGM-074) and Cancel (`POST /api/v1/jobs/:id/cancel`, OGM-033; hidden on 404).
- Phone layout: bottom sheet with safe-area insets and `svh`; landscape-phone rule at `max-height: 540px`; `prefers-reduced-motion` disables the ring animation and glow pulse.
- `window.__ogmHost.jobs` (behind `?test`): `{ dockState, jobs, messagesByJob }`.

## Contract and invariants

Consumer. Copy from OGM-080 `packages/contracts/chat.ts`; do not redefine:
```ts
type BuildChatMessage = { id: string; job_id: string; at: string; actor: "creator" | "agent" | "system";
  kind: "text" | "image" | "clip" | "checkpoint" | "progress"; text?: string;
  media?: { url: string; poster?: string; width: number; height: number; duration_ms?: number };
  checkpoint?: { decision_id: string; question: string; options: { id: string; label: string; media_id?: string }[]; recommend?: string; status: "open" | "answered" | "moot" };
  aiur?: { ticket: string; event_id?: number; topic?: string } };
```
Copy `VoiceTarget` and the token response from OGM-085 (`packages/contracts/voice.ts`); the dictation and client APIs from OGM-083 `packages/voice-client`. Invariants: messages are ordered by `id` and deduplicated; `since` is always the last rendered id; unknown `kind` renders as a text row with its `text` or nothing; the panel never holds an aiur URL or token; no prompt text is sent anywhere but `POST .../chat`.

## Failure, security, migration and accessibility cases

SSE drop → reconnect with `since`, no duplicate rows; media that fails to load keeps its reserved box and shows the caption; the token route down → text and dictation still work; dictation permission denied → the button explains once and stays text. Media URLs are signed blob URLs from the API (D-BUCKET); the app never embeds a bucket secret. No migrations. Live region (`aria-live="polite"`) on the list for new agent rows; clips never autoplay with sound; captions on every media row; 64 px FAB and Send, 44 px secondary buttons; `prefers-reduced-motion` honoured.
