## Outcome

`ogm-backup.timer` (installed by OGM-002) runs `ops/backup/backup.sh` nightly: a consistent SQLite snapshot (`VACUUM INTO` through Node's `node:sqlite`, no CLI needed) plus an exact incremental tar of new blobs, shipped over Tailscale SSH to the other node (or to a local path) with checksums and a manifest; `ops/backup/restore.sh <stamp>` rebuilds a data directory from them and is proven once by a test that backs up, adds a blob, backs up again, restores and compares; `ops/bin/ogm-status` prints units, placeholders, listeners (flagging anything not on 127.0.0.1), disk, journal and state sizes, last backup; `docs/ops/runbook.md` and `docs/ops/hand-steps.md` tell an operator how to run, rotate, restore, and what only Kevin can do.

## Context and evidence

No rclone, restic, borg, rsync, psql or sqlite3 CLI exists; `tar`, `zstd`, `openssl`, `ssh` do; one NVMe holds everything, and a second tailnet Linux node (`orangekid`) is online with Tailscale SSH enabled (E11-13). The database is SQLite in WAL mode owned by the API (D-DB); Node 24's `node:sqlite` loads (E11-9), so `VACUUM INTO` gives a consistent online copy with no install. Blobs are content-addressed and never change (OGM-005), so "files newer than the last run" is an exact delta. Stray `0.0.0.0` listeners exist and IPv6 is global on the NIC (E11-11); journald holds 2 GB and `~/.aiur` 21 GB (E11-14). Kevin's free hand steps are listed in T11 §7 and T03 §7. Resolved: no weekly `VACUUM` of the live DB (the API owns it); backup content is data + blobs + env file names (never values); retention of releases is OGM-045's.

## Scope

- `ops/backup/backup.sh`: `OGM_DATA_DIR`, `OGM_BLOB_ROOT`, `OGM_BACKUP_TARGET` (`ssh:<host>:<path>` or `local:<path>`), state in `~/.local/state/ogm/backup/`; snapshot, delta tar, ship, verify far-side sha256, manifest, stamp.
- `ops/backup/sqlite-backup.mjs`: `node:sqlite` `VACUUM INTO` helper (skips cleanly when the DB does not exist yet).
- `ops/backup/restore.sh <stamp> --to <dir>`: fetches the snapshot and every delta tar up to the stamp, restores in order, verifies.
- `ops/test/backup-restore.sh`: the drill with a `local:` target in temp dirs (runs in CI through OGM-001's ops step).
- `ops/bin/ogm-status [--json]`: units (`ogm-*`), `PLACEHOLDER` lines from the journal, `ss -tlnp` listeners with `STRAY` flags, disk, journal and `~/.aiur`/`~/.local/share/ogm` sizes, last backup stamp and size, `tailscale serve status` summary (skipped if not operator).
- `docs/ops/runbook.md`, `docs/ops/hand-steps.md` (the `remind`-format list the Executor copies into `~/remind.md`).

## Contract and invariants

Backup set layout at the target (owner: this ticket; consumer: `restore.sh`, the runbook):

```
<target>/ogm-backups/
  db-<STAMP>.sqlite            VACUUM INTO snapshot (STAMP = UTC yyyymmddTHHMMSSZ)
  blobs-<STAMP>.tar.zst        files under $OGM_BLOB_ROOT newer than the previous successful stamp (first run: all)
  manifest-<STAMP>.json        { stamp, previous, files: [{name, bytes, sha256}], blobCount, dbBytes, host, repoSha }
state (local): ~/.local/state/ogm/backup/{last-stamp, last-ok}   written only after far-side sha256 matches
```

`ogm-status` output (text; `--json` mirrors it): sections `units`, `placeholders`, `listeners` (each OGM pid's socket; `STRAY` when the address is not `127.0.0.1`, and any `python3 -m http.server` on `0.0.0.0`), `disk`, `sizes`, `backup`, `ingress`. Exit 0 always; `--check` exits 1 when any unit is failed, any STRAY exists, or the last backup is older than 48 h.

Invariants: env values never appear in the backup set or the status output (the set contains data files, not env files); `backup.sh` never deletes anything at the target; `restore.sh` never writes into a non-empty `--to` directory; both scripts run without sudo.

## Acceptance and verification

### Agent gate
- `bash ops/test/backup-restore.sh`: seeds a temp `OGM_DATA_DIR/ogm.db` (table + 3 rows via `node:sqlite`) and a temp blob root with 3 blobs; runs `backup.sh` with `OGM_BACKUP_TARGET=local:<tmp>`; adds a 4th blob and a row; runs again; asserts the second `blobs-*.tar.zst` holds exactly the 4th blob's two files; runs `restore.sh <stamp2> --to <empty dir>` and asserts the restored DB has 4 rows and the restored blob root's sha256 list equals the source; asserts `restore.sh` refuses a non-empty `--to`; asserts `last-ok` is not advanced when the far-side checksum check is forced to fail (`OGM_BACKUP_FAKE_CORRUPT=1`).
- `bash ops/test/status.sh`: with fake `systemctl`, `journalctl`, `ss`, `df`, `du` on PATH, `ogm-status` prints every section, flags a fake `0.0.0.0:8792 python3` line as `STRAY`, and `--check` exits 1 on it and 0 without it.
- `node --no-warnings ops/backup/sqlite-backup.mjs <missing.db> <out>` exits 0 with `no database yet`.
### At-merge gate
- `ci / required` green on current main (both shell tests run in the ops step).
### Human or e2e evidence
- After GATE-BACKUP-TARGET: `OGM_BACKUP_TARGET=ssh:orangekid:~/ogm-backups ops/backup/backup.sh` on this host; paste the manifest summary and `ssh orangekid ls -l ~/ogm-backups`; then `ops/backup/restore.sh <stamp> --to /tmp/ogm-restore-drill` and its verify line (the once-only drill, B6 §6).

## Failure, security, migration and accessibility cases

- Partial ship (network drop): the stamp advances only after the far-side sha256 matches; the next run re-ships the same delta (idempotent by stamp).
- The DB may not exist before OGM-010 merges: the helper skips with a message and the blob part still runs.
- SSH keys: Tailscale SSH needs no key file; if a key is used it lives in `~/.ssh` (already 0600, E03-9) and is never copied into the backup.
- `ogm-status` reads only names and sizes; it never prints env file contents.
- `~/github/aiur/.env` at 0664 and Kevin's PAT in `~/.aiur/.env` (E03-8/9), `tailscale --operator`, Funnel approval, backup node, GitHub App, Google OAuth client, optional `journald SystemMaxUse`, optional Blender: all in `docs/ops/hand-steps.md` for the Executor's `remind` entries.
- No migrations; no UI.
