## Outcome

`POST /api/v1/analytics/events` accepts batches of nine-activity events with allow-listed `meta` from job tokens (gm CLI, skills, SDK) and sessions (editor), rejecting anything else per event; `GET /api/v1/analytics/builds/:jobId/timeline` returns aiur phases merged with OGM activities for one build; `GET /api/v1/analytics/rollups?scope=game|member` returns counts and durations per activity over a date range; admins only on reads; no prompt or source text is ever stored.

## Context and evidence

C2 §1: guessing activity after the fact from tool logs failed three times; record at the source with a fixed nine-activity taxonomy, join to aiur by run id, show per-build timelines and roll-ups, and never store prompt or source text (E01-18, mirroring aiur's `lifecycle.ex` privacy rule). E01-5: aiur accepts no custom events; its join keys are `{repo, issue}`, `run_id`, `attempt_id` (E02-5 `sessions[].run_id`, E02-16 `feature:` labels), so OGM keeps its own stream keyed by `jobId` plus optional `aiurRunId`/`attemptId`. E05-19: the `gm` CLI emits JSONL to `$GM_EVENTS_FILE` inside the sandbox; the ship to this route happens outside it (OGM-036/OGM-090's `after_create`/verify side), so this route must accept batches with past timestamps. Resolved: A12 drops cell suppression and reading-grade limits for adults; admin visibility is family-scoped.

## Scope

- Table `activity_events` (all `ActivityEvent` fields plus `family_id`, `principal_kind`, `received_at`), indexes on `(job_id, ts)` and `(game_id, ts)`.
- Table `aiur_phase_events(job_id, phase, transition, at, source, UNIQUE(job_id, phase, at))` and the exported `recordAiurPhase(jobId, phase, at, transition?)` that OGM-032 calls from its projection.
- `POST /api/v1/analytics/events`: principal `job` → every event's `gameId` must equal the token's, `jobId` defaults to the token's; principal `user` → `actor` must be `human`, `jobId` absent, `resolveGame(gameId)` must return the user's family (else 403 `game_unresolved`); `IngestRequest` validated per event, with per-event `rejected[]` and never a whole-batch failure for one bad event; duplicate `(jobId|gameId, ts, activity, boundary, source)` within a batch collapsed.
- `GET /api/v1/analytics/builds/:jobId/timeline` → `BuildTimeline`: phases from `aiur_phase_events`; activities paired `start`→`end` by `(activity, actor, source)` in order, open starts get `endedAt: null`; `usageMicroUsd`/`retries` from the `jobs` row when the table exists, else `null`.
- `GET /api/v1/analytics/rollups?scope=game|member&id=&from=&to=` → `Rollup` for the admin's family; `member` scope joins events to jobs by `creatorId` when the `jobs` table exists, else by `principal` user id.
- Authorization: reads require `authorize(actor, 'admin.analytics.read', { familyId })` from `packages/policy` when present (phase-4 sibling); until it exists, reads require `platformRole === 'admin'` on the principal.

## Contract and invariants

Consumer of OGM-010: copy `ActivityEvent`, `IngestRequest`, `IngestResponse`, `BuildTimeline`, `Rollup`, `Activity`, `ALLOWED_META_KEYS`, `AiurPhase` from `packages/contracts/analytics.ts`; do not redefine. The T01 §4 ingestion block quoted in OGM-010 is this route's contract.

Defined here:
```ts
export function recordAiurPhase(db, e: { jobId: string; phase: 'brainstorm'|'plan'|'work'|'review'; at: string; transition?: string; source: 'events_feed'|'progress_poll' }): void;
```
Invariants: `meta` is stored exactly as validated (`.strict()`), so no key outside `ALLOWED_META_KEYS` ever reaches disk; `meta.command` is truncated to 120 chars and must match `/^gm(\s|$)/` or be absent when `source === 'gm_cli'`; a job-token principal cannot write another game's events; `ts` may be in the past but not more than 7 days nor in the future by more than 5 minutes (per-event reject `ts_out_of_range`); batch size ≤ 500; reads are family-scoped; `usageMicroUsd` unknown is `null`, never `0`.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/api test -- analytics`: the worked fixture both ways; a job token for game A posting game B's event → that event rejected `game_mismatch`; a user principal with `actor: 'agent'` → rejected; a user principal with no registered game resolver → 403 `game_unresolved`; timeline pairs start/end into one activity with the right duration and leaves an open start `endedAt: null`; `recordAiurPhase` twice with the same key inserts once; rollup over a range sums `count` and `durationMs` per activity and excludes the other family; a non-admin read → 403. Every test fails without its production module.

## Failure, security, migration and accessibility cases

Free text cannot enter: only the allow-listed keys with bounded lengths; the route logs counts, never event bodies. Job tokens are verified by OGM-010 (`timingSafeEqual`, expiry). A batch is written in one transaction after validation; a DB error returns 500 and nothing partial. Retention: raw events older than 90 days are deleted by a daily job in this context (`retention.ts`, `OGM_ANALYTICS_RETENTION_DAYS` default 90); roll-ups are computed on read in V1 (no materialized table). Timestamped migration. No UI.
