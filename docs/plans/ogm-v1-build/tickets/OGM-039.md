## Outcome

Every PR in a game repo gets a check run named `ogm/boundary` within a minute of its head changing, `success` or `failure` with a summary listing each reason; a PR that adds `.github/workflows/x.yml`, a 60 MB file, an asset not in `assets.lock.json`, a string shaped like a token, or a file whose sha256 is on the blocklist fails with the matching `BoundaryVerdict` code; `Publish` and `set_visibility: public` run the same gate over the whole tree plus the rights rules, and a public repo holding a Synty asset is refused with `rights` naming the asset (AE5).

## Context and evidence

Agents push branches and open PRs themselves (E03-12), so the enforcement point is a required check plus the commit service's own gate at merge, publish and visibility flips (D-COMMIT). Nothing in the repo scans content today; publish-time rights enforcement is name-based (`rm -f art/packs/synty-*`) and the only hash blocklist covers ProFantasy (E03-16, E05-14). A7 lists the leakage vectors: paths and slugs, author identity, agent artifacts, names in content, Actions logs, attachments, source maps. Resolved: no model-based or paid visual check at publish (spend; E03-16); the V1 gate is the adult/public-source one (child publication gate is V3); the lockfile is the rights source of truth (R53, OGM-062).

## Scope

- `services/commit/src/boundary/*`: `evaluateDiff(ctx)` for PRs and `evaluateTree(ctx)` for publish/visibility, both returning `BoundaryVerdict`, each rule a pure function over `{path, bytes, content?}` plus `{lockfile, visibility, blocklist, profileNames}`:
  - `path`: denies `.github/**` changes except by the platform (template refresh), `.gm/**`, `assets-local/**`, `**/.env*`, `**/*.pem`, `node_modules/**`, symlinks that escape the tree, `..` segments, and any path outside the game's own tree (repo-per-game makes that the root); file names containing an email or a profile display name.
  - `size`: per-file 25 MB, per-PR 200 MB, binary file types limited to the build-manifest formats (`glb gltf bin png webp ktx2 mp3 ogg json`); source maps (`*.map`) denied on public visibility.
  - `secret`: token patterns (`ghp_`, `github_pat_`, `aiur_`, `whsec_`, `sk-`, `AKIA`, PEM headers, `OGM_*=` env lines), high-entropy strings in `.json`/`.ts`/`.md` over a threshold.
  - `pii`: creator names and emails from the API's profile list (`GET /internal/games/:id/pii-terms`, pseudonymous handles allowed), phone-number and street-address patterns in text files.
  - `rights`: every file under `assets/` must be in `assets.lock.json` with `rights.uses` including `in-game` (or `placeholder` on a draft PR); on publish/public: no `placeholder`, no `rights.audience: 'private'`, `redistribution` compatible with the visibility; calls OGM-062's `assertUsageRights(lockfile, {publish, visibility})` and maps its findings to `rights` reasons naming the asset id and the rule.
  - `denylist`: sha256 of every added/modified blob against the blocklist from `gm packs blocklist` (OGM-067's file, `sha256 bytes path` lines, read at start and on change); agent artifacts (`*.workpad.md`, transcripts, `plan.md` at root) on public repos.
- Check-run poster: on a game-repo `pull_request`/`synchronize` (GitHub webhook to `POST /internal/github/webhook` when OGM-006 gives TLS; until then a 60 s poll of open PRs per active repo) → `POST check-runs {name:'ogm/boundary', head_sha, status, conclusion, output:{title, summary, text}}` through the App (OGM-035's `octokitFor`).
- `services/commit/src/publish-gate/*`: `BoundaryGate` implementation replacing OGM-035's default: `fold_design` and `merge` → `evaluateDiff` of the PR or the fold files; `release` and `set_visibility` → `evaluateTree` at the sha with publish rules.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/commit test`: the `clean` fixture passes both evaluators; each other fixture fails with exactly its code and a path; the token fixture's summary text contains the path and `token-like string` but not the token; the Synty-public fixture passes on `private` and fails on `public` with `rights`; a 25 MB+1 file fails `size`; the blocklisted blob fails `denylist`; `evaluateTree` reports all families (a fixture with two problems yields two reasons); the check-run poster posts once per head sha and `failure` carries the summary; an I/O error yields `allowed:false`. Each test fails if its rule is removed.
- `pnpm -r typecheck`, `pnpm -r lint`.
### At-merge gate
- `ci / required` green on current main.
### Human or e2e evidence
- AE5 end to end on a scratch public repo once the App exists (OGM-100 otherwise): `gm check assets --publish` exits 1 naming the asset and the commit service refuses the fold with the same asset in `reasons`.

## Failure, security, migration and accessibility cases

Blocklist missing → fail closed on public repos (`denylist`, `detail: 'blocklist unavailable'`), pass on private with a logged warning. GitHub check-run API errors → retry 3×, then an admin alert; the ruleset still blocks the merge because the check is absent. The PII term list is fetched over loopback and held in memory, never written to disk or logged. Secrets never appear in verdicts or audit lines (OGM-035's audit stores the verdict). No migrations. Verdict wording is plain language because OGM-077 shows `detail` to the creator.
