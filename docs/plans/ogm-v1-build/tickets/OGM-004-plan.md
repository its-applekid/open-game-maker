# OGM-004 plan — Contracts package bootstrap with asset-card schemas and rights engine

## 1. Problem frame

The usage-rights policy exists once, as a 111-line Node script under `docs/` with 20 fixtures (E12-7, E05-9). V1 needs it as a typed library in the CLI, the backend and the commit gate, and needs the package it lives in to be the home of every shared contract family with an emit pipeline later tickets copy (R121, E04-18). The port must be exact (the fixtures prove it), the Python callers must keep working across the move, and the one rule the model lacks, no cloud processing of paid assets, enters as `rights.processing` (E05-10).

Requirements trace: R121 → `packages/contracts`, one file per family, append-only barrel, schemas and fixtures emitted from Zod and committed (`health.v1` proves the pipeline). R51 → C3 schemas moved unchanged, `effective()` ported with the negatives as tests, `processing: local-only | any` with the vendor-licence default.

### U3 Rights engine

Goal: `effectiveRights` is the exact port of `effective()`; `processing` rules added.

Files: Create `src/rights.ts`. Test `test/rights.test.ts`.

Approach: port lines 30–57 of validate.mjs: ceiling = first `license` entry with `confirmed_by`, else the `default` entry, else throw `RightsError('no confirmed license and no default entry')`; `forbids` = union over all `license` entries (confirmed or not); each `interpretation` may add uses not in `forbids` (else throw `interpretation adds forbidden use(s) …`); each `decision` intersects uses and takes the minimum audience/redistribution by the orders `private < public`, `none < in-build < free`. `rightsAgree` compares audience, redistribution and the use set. `defaultProcessing(license, status)`: `local-only` when `status === 'quarantined'` or `license` is undefined, `NOASSERTION`, or starts with `LicenseRef-`; else `any`. `processingAllowed(card)`: if `card.rights?.processing === 'any'` then require `defaultProcessing(card.license, card.status) === 'any'`, else ok.

Test scenarios:
- Given the basis of `collection-kenney-mini-dungeon.json`, when `effectiveRights` runs, then uses = the five listed, `public`, `free`.
- Given the basis of `interpretation-adds-forbidden-use.json`, then it throws `RightsError` mentioning `vision-input`.
- Given a `license` entry without `confirmed_by` and a `default` entry, then the ceiling is the default (unconfirmed licences never widen) but its `forbids` still bind.
- Given a `decision` with fewer uses and `audience: private`, then uses shrink and audience is `private`; a decision can never widen (audience `public` over a `private` ceiling stays `private`).
- Given `defaultProcessing('LicenseRef-synty-personal','tagged')` → `local-only`; `('CC0-1.0','tagged')` → `any`; `('CC0-1.0','quarantined')` → `local-only`.
- Given the new negative fixture (a `LicenseRef-sidetrax-royalty-free` collection with `processing: 'any'`), then `processingAllowed` is `{ok:false}`.

Execution note: characterization-first: run the old `validate.mjs` once over the fixtures, save its stdout to `test/__snapshots__/validate-mjs.txt`, and assert the port's CLI output equals it line for line (minus the new `processing-rule` lines).
