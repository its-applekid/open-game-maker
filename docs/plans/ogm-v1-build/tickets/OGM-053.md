## Outcome

`apps/web/src/net` connects the host app to a room with a grant, keeps a `useRoom` store (phase, members, presence, ended reason) in step with the server, brings a watcher's effective design up to the editor's at every rev (snapshot at a revision plus relayed `design.tx`, `resync` on gaps), forwards `net.*` messages between the room and the game iframe through `@gm/host`, survives socket drops and grant expiry, and exposes itself under `window.__ogmHost.room` behind `?test` so Playwright can drive it.

## Context and evidence

E07-4: the Colyseus client lives in the host app, never in the game iframe; the grant is a bearer secret and the game sees only `net.*` messages over the validated bridge (`@gm/host`, OGM-028). E07-5/E08-17: watchers receive the same transaction stream the log persists; the room remembers only `lastRev`; a late watcher fetches the design snapshot at `rev ≤ lastRev` (OGM-041 `GET /api/games/:g/branches/:b/design?rev=N`) and applies room transactions with `rev > snapshotRev`; a gap re-fetches, never guesses. E07-10: Play is "on receipt of one message"; peers switch phase on the state change and load the pinned build at `playRev`. E07-8: host-left is an end state with the last autosave time. Resolved, do not reopen: the owner's editor writes to the backend first and re-sends the acked transaction to the room (`publishTransaction`); the room never sees a lease token (E07-14); bridge wire names for multiplayer are the `net.*` kinds of T07 §4.3 (build-order names them; T04 §4's `mp.*` sketch is superseded for these kinds, see Contract).

## Scope

- `apps/web/src/net/room-client.ts`: `RoomClient` over `colyseus.js` (`new Client(roomsUrl)`, `joinById(roomId, {grant, buildId, protocol})`), `JoinRejection` parsing, `ServerMessage` dispatch, state-change subscription, reconnection with the room's reconnection token, re-grant through `GET /api/rooms/:roomId/grant` (OGM-052) when `expiresAt` nears or on `GRANT_EXPIRED`, `ping`/`pong` RTT sample, `leave(consented)`.
- `apps/web/src/net/room-store.ts`: zustand `useRoom` store: `status`, `you`, `role`, `phase`, `phaseAt`, `playRev`, `members`, `presence`, `pin`, `draft`, `ended`, `rttMs`; actions `play()`, `edit()`, `kick(userId)`, `setPresence(p)`, `loadDraft(buildId,url)`, `publishTransaction(tx)`.
- `apps/web/src/net/watcher-sync.ts`: catch-up and ordering (`snapshotRev`, `appliedRev`, pending buffer, `resync` handling, gap detection), applying each transaction with `@ogm/design-log` `apply` and pushing `design.apply {rev, doc, patches}` through the bridge; `draft.ready` after the iframe reports `ready`.
- `apps/web/src/net/bridge-forwarding.ts`: room → iframe `net.players`, `net.role`, `net.input` (editor session only), `net.snapshot`, `net.event` (peers), `phase`; iframe → room `net.input` (peer) and `net.snapshot`/`net.event` (host); byte caps checked client-side before sending.
- `apps/web/src/net/index.ts` and the `window.__ogmHost.room` test handle (`?test` only): `join`, `state()`, `received()` (ring buffer of every `ServerMessage` the client got, for the canary assertion), `play()`, `leave()`.

## Contract and invariants

Consumer. Copy `ClientMessage`, `ServerMessage`, `RoomState`, `JoinOptions`, `JoinRejection`, `LIMITS` and the `net.*` payloads from OGM-050 `packages/contracts/src/room.ts`; the bridge envelope from OGM-020 `packages/contracts/src/bridge.ts`; the snapshot route from OGM-041 (`GET /api/games/:g/branches/:b/design?rev=N → { rev, doc }`); the rooms routes from OGM-052. Do not redefine any of them. The bridge additions this ticket needs, verbatim from T07 §4.3:

```ts
// host → game
{ t: 'net.players',  local: number; players: Array<{ playerIndex: number; name: string; connected: boolean }> }
{ t: 'net.role',     role: 'host' | 'peer' }
{ t: 'net.input',    f: InputFrame & { playerIndex: number } }   // host only: peers' inputs
{ t: 'net.snapshot', seq: number; tick: number; data: ArrayBuffer }   // peers only
{ t: 'net.event',    seq: number; data: ArrayBuffer }
{ t: 'phase',        phase: Phase }
// game → host
{ t: 'net.input',    f: InputFrame }                                   // peer: its own input
{ t: 'net.snapshot', seq: number; tick: number; data: ArrayBuffer }   // host: the authoritative snapshot
{ t: 'net.event',    seq: number; data: ArrayBuffer }
```
If `bridge.ts` as merged by OGM-020 lacks these kinds (T04 §4 sketched `mp.snapshot`/`mp.inputs`/`mp.input`), append them to the `HostToGame`/`GameToHost` unions as new members (append only, nothing renamed, schema re-emitted) and say so in the PR; `mp.*` members stay. Invariants: watcher effective design equals the editor's at every applied rev (AE4); a transaction is applied only when `rev === appliedRev + 1`, otherwise buffered, and a buffer older than 2 s or a `resync` triggers a snapshot fetch at `lastRev`; the grant is held in memory only; `role === 'host'` is true only for the session that equals `state.editorSessionId`; outgoing `snapshot` > 64 KiB or `input` > 256 B is dropped client-side with a console warning once.

## Failure, security, migration and accessibility cases

The grant is never written to storage, the URL, or the iframe; `RoomClient` redacts it in errors. A rejected join leaves the store in `rejected` with the code for OGM-078 to render. A snapshot fetch failure retries 3× then marks `status: 'desynced'` (no silent divergence). Bridge messages are validated by `HostBridge` before forwarding; unknown kinds are dropped. No migration. No UI in this ticket; the test handle exists only when `?test` is present.
