## Outcome

From a game checkout, `gm run --headless --viewport both --record 10s --out shots/` opens the game on this machine's Intel GPU through ANGLE/EGL, drives it through `window.__gm`, and leaves stills at desktop and phone sizes, one tiled timeline PNG, one H.264 MP4 that plays on an iPhone, and `shots/report.json` (the verify report) whose `renderer` names the real GPU; `gm shot --sheet shots/` tiles the stills and `gm perf` prints phone-profile load times and bytes against the tier budget. At most two captures run on the host at once.

## Contract and invariants

This ticket produces the verify report and the `gm run` surface. Quoted verbatim from T10 §4:

```
gm run --headless [--url http://127.0.0.1:PORT/] [--viewport desktop|phone|both] [--tier mobile|desktop]
       [--inputs script.json] [--frames 0,2,5] [--timeline 0:10:0.5] [--record 15s] [--rig iso] [--out shots/]
gm shot --sheet shots/            # one tiled image
gm perf [--device iphone13 --cpu 4] # load first/cached, bytes by type, draw calls, tris, texture memory vs tier budget
```

```json
{ "runId": "…", "jobId": "…", "aiurIssue": 123, "renderer": "ANGLE (Intel, …)",
  "viewport": "phone", "tier": "mobile", "rig": "iso",
  "frames": [{ "t": 0, "path": "shots/phone/t0.png" }], "timeline": "shots/phone/timeline.png", "clip": "shots/phone/run.mp4",
  "console": [{ "level": "error", "text": "…", "count": 3 }],
  "budgets": { "downloadBytes": [4100000, 6000000, "ok"], "drawCalls": [180, 250, "ok"], "triangles": [410000, 300000, "over"], "textureBytes": [0, 0, "ok"] },
  "probes": { "alive": true, "won": false }, "clients": 1,
  "unchecked": ["iPhone Safari", "sound"], "verdict": "fail" }
```

Invariants: `renderer` is always the WebGL `UNMASKED_RENDERER_WEBGL` string and `software: true` is set when it matches `/swiftshader|llvmpipe|lavapipe|softpipe|mesa offscreen/i`; `unchecked` always contains `"iPhone Safari"` and `"sound"` in V1; `verdict` is `fail` when any budget is `over` or any console `error` is new, else `pass`; the report is written even when the run fails (`verdict: "error"`, `error` field); file paths are relative to `--out`. The hook driver consumes OGM-020's `GmTestHooks` (T04 §4) by name and never defines hooks. Activity event (T10 §4): `{ jobId, aiurIssue, aiurRunId, activity: "playtesting", source: "gm run" | "skill:gm-verify", phase: "start" | "end", at }`, one JSON line per event in `$GM_EVENTS_FILE`.

### At-merge gate
- `ci / required` green on current main; the browser test runs in CI on the host runner with the GPU flags (SwiftShader fallback allowed in CI, flagged in the report).
### Human or e2e evidence
- Kevin opens one `run.mp4` from the stub page on his iPhone and it plays (one-time check that the encode settings survived the port).

## Failure, security, migration and accessibility cases

- SwiftShader fallback: fewer frames (`--frames` capped at 6, no `--record` above 5 s), warning line, `software: true`.
- Page error before `ready`: exit 1 immediately with the error text (`capture.mjs` pattern), report written with `verdict: "error"`.
- ffmpeg missing: refuse with exit 2 and the install hint; stills still written.
- Loopback only: `gm run` refuses any `--url` not on `127.0.0.1`/`localhost` (T11 rule); its own static server binds `127.0.0.1`.
- Queue mode: the sandboxed caller only writes `.gm/verify/<runId>/request.json` inside its workspace and polls for `report.json`; the host runner never executes anything from the request (paths are validated to be inside the workspace; `url` must be a workspace-relative dir, not a URL); timeouts: 10 min per run.
- No secrets: the package reads no env but `GM_EVENTS_FILE`, `GM_VERIFY_SOFTWARE_GL`, `GM_VERIFY_QUEUE`, `PLAYWRIGHT_BROWSERS_PATH`.
- Resource bounds: captures run `nice 10`; the semaphore (2) is a lock directory under `$XDG_RUNTIME_DIR/ogm-verify/` with stale-lock reaping by PID.
- No migrations, no UI.
