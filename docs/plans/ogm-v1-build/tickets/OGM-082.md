## Outcome

When a worker raises a direction checkpoint, the creator sees a card in the build chat with 2–5 tappable previews (the recommended one first), taps one, and within one poll the worker receives the answer through aiur's normal Command delivery while `gm checkpoint wait` prints the option id; a checkpoint the worker abandons shows as moot, and the card shows how many of the build's checkpoints are used.

## Context and evidence

aiur Commands are read at `GET /api/v1/decisions` and answered at `POST /api/v1/decisions/:id/decide` with a separate supervisor bearer token (E02-2, E02-3); options are `{id, label, description, …}`, no media (E06-15). Decision events are not in the exported event feed (E02-6 lists lifecycle, usage, cancel and progress topics only; the catalog at `0f692a45b` has no `executor.decision.requested` entry), so this ticket polls. A blocking Command holds only its worker (E06-15). The budget is ≤3 per creation build and ≤1 per feature build, candidates from lineups, presets or ≤10 s clips (E06-16, D-BUILD-CHAT).

Contradictions already resolved: (1) The supervisor `/decide` route refuses `authority: human_required` Commands and any `kind` not listed in the daemon's `decisions.supervisor_allowed_kinds` (`src/lib/aiur/decision_authority.ex`: `human_required` is absolute; `decision_delegation.ex` allowed fields). So checkpoints are emitted as `authority: supervisor_allowed`, `reversibility: reversible`, `kind: "direction_checkpoint"` (OGM-081 prints exactly that), the game-builder daemon config carries `decisions.supervisor_allowed_kinds: ["direction_checkpoint"]` and `AIUR_SUPERVISOR_TOKEN` (rendered by OGM-034/037; this ticket states the requirement), and OGM answers as the supervisor with a `rationale` naming the creator's choice. (2) `executor.relay_operator_answers` / `operator-relay-answer` are CLI-only paths for human-required Commands; not used. (3) The worker cannot call aiur from the sandbox, so the answer reaches `gm checkpoint wait` through an inbox file this ticket writes.

## Scope

- `services/api/src/checkpoints/outbox.ts`: `checkpoint.open` handler → stores a `kind: "checkpoint"` row (`decision_id: ""`, `status: "open"`, options and media ids from `CheckpointOpenPayload`), publishes it, counts the job's checkpoints.
- `services/api/src/checkpoints/poller.ts`: every 5 s per daemon with tickets in running states, `GET /api/v1/decisions?ticket=<n>&limit=50` (supervisor token, `Origin`, `X-Aiur-Request: 1`); correlates open Commands to checkpoint rows by the `gm-checkpoint:cp_…` marker in `context.long_context_markdown`; Commands without a marker (native `AskUserQuestion` captures) become cards too, from the Command's question and options; resolved or expired Commands flip cards to `answered` (with the option) or `moot`.
- `services/api/src/checkpoints/routes.ts`: `POST /api/v1/jobs/:jobId/checkpoints/:id/answer {option_id}` (creator only) → `POST /decide {option_id, expected_version, idempotency_key, rationale}`; 409 from aiur → refresh and report; `GET /api/v1/jobs/:jobId/checkpoints/budget` → `{used, max}` (max 3 for `new_game`, 1 otherwise).
- `services/api/src/checkpoints/inbox.ts`: on answer or moot, write `<workspace>/.gm/inbox/checkpoints/<cp_id>.json` and `<decision_id>.json` (`{checkpoint_id, decision_id, option_id, status, at}`), workspace from OGM-080's `recordWorkspace`.
- Notification: emit `checkpoint.open` on the job's notification feed when OGM-016's emitter exists; otherwise the chat row alone (the panel badges it).
- `apps/web/src/features/build-chat/checkpoint-card.tsx`: the card (question, media tiles from referenced chat messages, recommended first and marked, 64 px targets, open/answered/moot states, blocking note, budget line).

## Contract and invariants

Consumer: copy `BuildChatMessage` from OGM-080 `packages/contracts/chat.ts` and `CheckpointOpenPayload` from OGM-081; do not redefine. aiur shapes consumed verbatim (`0f692a45b`): list `GET /api/v1/decisions` params `ticket`, `kind`, `blocking`, `authority`, `limit`, `cursor` (`src/lib/aiur/decision_api/legacy_pagination.ex` line 41); decide body fields `option_id | custom_response`, `expected_version`, `idempotency_key`, `rationale` (+ optional `confidence`, `alternatives_considered`, `reversibility_belief`; `src/lib/aiur/decision_delegation.ex` line 16); responses `202` with `status`, `decision`, `action`, `dispatch_status`, or `409 decision_conflict`. Routes this ticket produces:

```ts
POST /api/v1/jobs/:jobId/checkpoints/:checkpointId/answer  { option_id: string }
  → 200 { status: "answered", decision_id, option_id } | 409 { status: "answered"|"moot", by: "other" } | 425 { status: "not_linked" }
GET  /api/v1/jobs/:jobId/checkpoints/budget → { used: number, max: 1 | 3 }
// inbox file (consumer OGM-081): { checkpoint_id: string; decision_id: string; option_id?: string; status: "answered" | "moot"; at: string }
```
Invariants: a card is answerable only once its `decision_id` is linked (until then 425 and the card says "waiting for the builder to ask"); `idempotency_key = "ogm:" + checkpointId + ":" + version`; the creator's choice is never silently dropped on 409 (the card refreshes to the winner); only the job's creator may answer (`authorize(actor, "job.create", …)`); supervisor tokens never reach the web app; media ids are resolved to rows of the same job only; budget counts open + answered checkpoints per job and never blocks a card (R23: the cap is enforced in the skill text and shown on the card).

## Failure, security, migration and accessibility cases

- aiur unreachable: cards stay as they are; the poller backs off to 30 s and logs once; no card is invented.
- Supervisor token missing for a daemon: the poller skips that daemon and the card shows "waiting for the builder to ask" forever → surfaced in `/healthz` details, not hidden.
- Expired or moot Commands: `moot` card, inbox `moot` so `gm checkpoint wait` exits 4.
- Secrets: supervisor tokens live in the daemon env records (OGM-034); never in responses, logs or the web bundle.
- No migration (rows live in OGM-080's table; `checkpoint_json` is updated in place).
- Accessibility: tiles are buttons with `aria-label` = option label, 64 px minimum, keyboard focusable; the recommended mark is text, not colour alone; reduced motion respected.
