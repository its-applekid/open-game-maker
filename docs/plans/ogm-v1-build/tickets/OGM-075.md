## Outcome

Opening `/g/:gameId` on a phone or desktop mounts the game's latest build in a separate-origin iframe through `@gm/host`; Play and Edit switch modes; in Edit the host-owned rail, palette, inspector (with "This skeleton" / "All skeletons" scope labels), tools, gizmo overlay and snap preferences drive the game from its manifest, every change lands as a transaction on the branch's log with an honest Saved indicator, undo and redo work across the session, a build finishing while editing shows the re-apply card before switching, and the screen shows draft vs published plus an update indicator.

## Context and evidence

The prototype editor lives inside the game (`ui-v0/site/js/dungeon.js`) with a whole-map JSON undo stack and `postMessage('*')` (E09-4, E08-15); V1 moves the editor to the host over the design log (D-LOG) and a validated bridge (E04-16). B7 §3 fixes the editor vocabulary (category kinds `items | tools | panel`, tools `select | place | brush | sculpt | erase | path`, gizmo vocabulary, `control.scope`, `editorPrefs` for snap, `validatePlacement`, `setSelection`). E08-1 fixes the transaction shape and E08-16 the lease (per `(gameId, branchId)`, 15 s heartbeat, silent takeover between the owner's devices). E08-4 names this ticket as the owner of the re-apply card. Resolved and not to be reopened: `Transaction.origin` is `actor` + `kind` (E04-16); the working set is a cache, the log is truth (E08-2); the host polls gamepads, the game never does (E04-13); the games origin is one shared origin `:10000/g/<gameId>/<buildId>/` (D-GAMES-ORIGIN), so dev uses a second localhost port to stay cross-origin (T09 §6).

## Scope

- Route `/g/:gameId` with `?v=:branchId` (default `main`) and `?mode=play|edit` (default `play`), as the auto-collected module `apps/web/src/routes/game/route.tsx`.
- `GameFrame`: creates the iframe through `@gm/host` (OGM-028) with the build URL from the branch's latest tested build, sends `hello` with `mode`, `build: 'draft' | 'published'`, `playerIndex: 0`; rejects any message whose origin is not the games origin; forwards `settings` and `viewport`.
- Play/Edit bar: mode toggle (`mode.set`), back to `/games`, title; `manifest.editor.playLabel` when declared.
- Platform HUD: pause (`lifecycle.pause/resume`), save slots (auto + 1–3) over the `save.write`/`save.restore` bridge messages and the saves routes in `packages/contracts/saves.ts`, achievements list from the manifest with "(test)" toasts in drafts, settings (mute, volume, text scale, reduce motion) persisted per device and broadcast as `settings`.
- Editor framework from the manifest: rail (`palette.categories[]` with `kind`), palette (`items[] {prefab, label, thumbnail, hint}`), inspector (controls with scope labels; `count.semantics`; pinned global groups), tools, gizmo overlay drawn from `editor.screen`/`worldToScreen`, hint strip, snap prefs in `editorPrefs` (per device, not undoable), drag-to-place with a ghost coloured by `editor.validatePlacement`.
- Transactions: each intent (set, invoke, reset, place, delete, duplicate, a whole stroke or drag) becomes one `Transaction` built with `packages/design-log` apply/invert, posted to `POST /games/:g/branches/:b/transactions` with `baseRev` and `leaseToken`; 409 refetches head and replays; 423 drops to read-only; the Saved indicator shows `saved | saving | not saved, retrying`.
- Lease: acquire on entering Edit, heartbeat 15 s, release on leave; another device of the same user takes over silently; the old tab becomes read-only.
- Branch stream: subscribe to the branch's transaction SSE; transactions from another session apply through `design.apply`; undo/redo is per session over the session's own transactions with coalescing (R34).
- Edit while building: the job stream's "building" state shows in the top bar; when `Build.status = 'tested'` arrives, fetch the `ReapplyReport` (route owned by OGM-042; on 404 switch without a card) and show the card (carried / renamed / needs a choice / conflict / dropped) before switching the frame to the new build.
- Draft vs published badge; update indicator polling `GET /games/:g/published` with an ETag every 60 s and on `visibilitychange` (route owned by OGM-045; 404 hides the indicator).
- Focus zones (top bar, rail, palette, canvas, inspector) registered with OGM-071's focus-zone module; the canvas zone captures directions for the reticle; every drag has a stepper equivalent (WCAG 2.5.7).
- `window.__ogmHost.game` (behind `?test`): `{ bridgeState, headRev, saved, mode, selection }` for e2e.
- `apps/web/src/routes/game/extras.ts`: an empty `gameExtras` array of `{ id, placement: 'topbar' | 'hud' | 'overlay', Component }` that OGM-077 and OGM-078 append to.

## Failure, security, migration and accessibility cases

The games origin is cross-site: no cookie reaches the frame; the build URL carries no token (public draft builds are addressed by content hash). An origin mismatch, a payload over 256 KB or an unknown `t` is dropped by `@gm/host` and counted in `__ogmHost.game.dropped`. Lease loss mid-drag loses only that drag; the indicator says so. SSE disconnect reconnects from `headRev`. The frame failing `ready` within 10 s shows a retry, never a blank screen. No secrets in the app bundle; API calls go through the `/api` proxy. No migrations. Targets: 64 px primary (Play, Edit, Back, Finish), 44 px secondary; focus ring is thick and not colour-only; every gizmo has an inspector stepper; `prefers-reduced-motion` disables ghost animation.
