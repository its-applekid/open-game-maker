## Outcome

From a game, the creator opens Versions and sees `main` plus up to four more versions, each with its derived number and latest build; "New version from here" forks the current branch at its head; any version switches the game screen and plays or edits on its own. Releases shows what is published, lets the creator publish from `main` with the derived version and an editable changelog assembled from the jobs' change notes, and roll back to an older release after a dialog that counts the saves it would affect. Merge walks only the real conflicts with side-by-side previews and per-conflict choices (or keep all of mine), builds a preview, and lands as one transaction.

## Context and evidence

A version is a Git branch plus a fork point in the log; cap 5 active, archive never delete (E08-8, A1). Agent code jobs run on `main` only; the UI copy says "Builders work on the main version" (E08-9, D-BRANCH-BASE). Version numbers follow Kevin's counter scheme, derived, never stored (E08-7, D-VERSION). Publish pins `(buildId, snapshotId)`, folds through the commit service behind the content gate, moves one pointer by CAS (E08-5, R90); drafts on a public repo are visible in Git, so Publish says these words will be public (E08-19). Rollback is a new release; saves on newer schemas become `incompatible_after_rollback`; the dialog counts them (E08-6, R92). Merge: three conflict kinds, per-conflict or all-mine resolution, one merge transaction, preview build first (E08-10, R38, AE3). Resolved: A5's semver bump rule is superseded by D-VERSION; the GC-and-rebuild path is dropped (D-ARTIFACTS); publish only from `main` (A3).

## Scope

- Routes `/g/:gameId/versions`, `/g/:gameId/releases`, `/g/:gameId/merge/:planId?` as auto-collected modules under `apps/web/src/routes/game/{versions,releases,merge}/route.tsx`, plus one `gameExtras` entry (`placement: 'topbar'`) in OGM-075's `routes/game/extras.ts` linking to Versions and Releases.
- Versions: list `Branch` rows (name, derived version, `latestBuildId` status, `status`), current marked; "New version from here" (`POST` the branches route with `{ name, fromBranchId, fromRev: headRev }`), disabled at 5 active with the count shown; Switch (sets `?v=` and returns to `/g/:gameId`); Play and Edit per row; Archive with confirm; the "Builders work on the main version" line on non-main rows.
- Releases: published release (version, date, changelog); Publish enabled only when `branchId === 'main'` and the latest build is `tested`: dialog with the derived next version, the assembled changelog in an editable textarea, the public-words line when the repo is public, then `POST /games/:g/publish { buildId, changelog }`; release history; Rollback per older release: dialog with the affected-saves count from the route's confirm payload, then confirm; errors from the content gate are shown verbatim (asset name and rule, AE5).
- Merge: start from a version row ("Bring into main" or "Bring main in"); `MergePlan` summary (auto count, conflicts count, `code` status); conflict list with kind labels (`both_changed`, `delete_vs_edit`, `control_removed`); each conflict shows ours/theirs values and two `GameFrame`s (OGM-075) in play mode on the preview docs with `editor.select` on the entity, stills as fallback when a frame cannot mount; choices `ours | theirs | both | value`; "Keep all of mine"; Preview (requests the preview build, shows its status), Land, Abandon; a `code: { conflictJobId }` links to that job's chat (OGM-076).
- Update of the game screen's badge after publish (invalidate OGM-075's published query).

## Failure, security, migration and accessibility cases

Gate refusal on publish (402/409/422 with the asset and rule) is shown verbatim and leaves the dialog open; a CAS conflict (409 on the pointer) refetches and asks again; a preview build failing shows the failure and keeps the plan `resolving`; side-by-side frames that fail `ready` fall back to stills or to text values. No tokens in the client; all writes go through `/api` with the session cookie; the UI never holds a GitHub credential. No migrations. 64 px for Publish, Land, Switch, Play; 44 px for Archive, Abandon; dialogs trap focus; conflict cards are keyboard-navigable; the two frames are labelled "Mine" and "Theirs" for screen readers.
