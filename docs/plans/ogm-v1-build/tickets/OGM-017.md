## Outcome

Under `/api/v1/admin/*` a family admin can list and manage members and peer admins, list and revoke invites, flip the friends allowlist, set each member's daily allowance and the family reset zone and unit label, set the concurrency slots and the platform cap (visible to every admin), list, delist and relist the family's games, read Drive intake status and reports, and read the mail outbox; every route goes through `authorize()`, the owner cannot be removed or demoted, and a table test covers every route against owner, admin, member and other-family admin.

## Context and evidence

R3 and E01-10: admins manage members, invites, allowances, concurrency, the Drive folder and oversight, and cannot edit or take over another adult's game; the owner is an admin who cannot be removed. E01-12/E01-13: slots and the platform cap are admin settings (not hidden), the allowance is per member with a family reset zone and friendly unit. E01-17 and D-MAIL: the admin-inbox mail sender needs a place where an admin sees the links. R84 and E11-16: the admin UI shows intake status and reports read-only; the folder id stays in the operator's TOML (`scripts/drive-sync/drive-sync.example.toml`), never in the API. Resolved: A12 drops the child-only cell suppression; admin oversight is family-scoped for adults.

## Scope

- `services/api/src/admin/routes.ts` (prefix `/api/v1/admin`), every route `authorize(actor, <action>, { familyId })`:
  - members: `GET /members`, `PATCH /members/:userId { role?: 'admin'|'member', capability?: 'creator'|'player' }`, `DELETE /members/:userId` (`admin.members.manage`; owner immutable → 409; a non-owner admin cannot demote another admin, owner can).
  - invites: `GET /invites`, `DELETE /invites/:id` (`admin.members.manage`; delegates to OGM-012).
  - family settings: `GET /settings`, `PATCH /settings { friendsAllowed?, resetZone?, unitLabel?, microUsdPerUnit?, platformCapMicroUsd?, slots? }` (`admin.settings.set`; `resetZone` validated against `Intl.supportedValuesOf('timeZone')`).
  - allowances: `GET /allowances`, `PUT /allowances/:userId { dailyMicroUsd }` (`admin.budget.set`).
  - budget overview: `GET /budget` → per-member remaining today, family day total, platform cap, queued and running jobs (`admin.budget.set` read).
  - games: `GET /games?includeDelisted=1`, `POST /games/:id/delist`, `POST /games/:id/relist` (`game.delist`).
  - intake: `GET /intake` → drops from `assets-local/inbox/queue.jsonl` joined with each drop's `intake.json` (status, collection, licence, confirmed_by, date) and `manifest.json` problems count; read-only; path from `OGM_INTAKE_DIR` (`admin.settings.set` read).
  - mail outbox: `GET /mail?unopened=1`, `POST /mail/:id/opened` (`admin.members.manage`; delegates to OGM-011's `listOutbox`/`markOpened`).
- `services/api/src/admin/intake-status.ts`: a tolerant reader of the T05 §4 files (missing files → empty list, never 500).

## Non-goals

- The React admin screens and charts (OGM-079); build-analytics reads (OGM-014 owns `/api/v1/analytics/*`); job controls such as cancel or raise-cap (OGM-013/OGM-033 own `/api/v1/jobs/*`); the intake processing itself and `intake.json` writing (OGM-064); any write to the Drive folder or the TOML.

## Contract and invariants

Consumer of OGM-010/012/013 contracts: `FamilyBudgetSettings`, `Allowance` from `packages/contracts/budget.ts`; `Actor`/`authorize` from `packages/policy`; do not redefine. Defined here (response shapes, Zod in `services/api/src/admin/shapes.ts`, not in `packages/contracts` because only OGM-079 consumes them):
```ts
export const MemberRow = z.object({ userId: Id, email: z.string(), role: z.enum(['owner','admin','member']), capability: z.enum(['creator','player']), joinedAt: IsoTime, dailyMicroUsd: MicroUsd, remainingMicroUsd: MicroUsd });
export const BudgetOverview = z.object({ familyDayMicroUsd: MicroUsd, platformCapMicroUsd: MicroUsd, resetsAt: IsoTime, unitLabel: z.string(), microUsdPerUnit: MicroUsd, slots: z.object({ new_game: z.number().int(), edit: z.number().int() }), inUse: z.object({ new_game: z.number().int(), edit: z.number().int() }), queued: z.array(Id), members: z.array(MemberRow) });
export const IntakeDrop = z.object({ dropId: z.string(), name: z.string(), time: IsoTime, status: z.enum(['queued','imported','awaiting-license','blocked','duplicate']), collection: z.string().nullable(), license: z.string().nullable(), confirmedBy: z.string().nullable(), problems: z.number().int() });
```
Invariants: every route resolves the admin's own `familyId` from the principal and never accepts a `familyId` parameter; owner rows return 409 `owner_immutable` on any role change or removal; `platformCapMicroUsd` is returned on `GET /settings` and `GET /budget` to every admin (spec §8.3: no hidden cap); intake reads never write.

## Acceptance and verification

- `pnpm --filter @ogm/api test -- admin`: the policy table (every route × owner / admin / member / other-family admin → expected status) passes and flipping any expectation fails; owner demotion and removal → 409; an admin demoting a peer admin → 403, the owner doing it → 200; `resetZone: 'Mars/Olympus'` → 400; `PUT /allowances/:userId` changes `remaining` as read back from OGM-013's `remaining()`; `GET /budget` shows `inUse` matching jobs in slot-holding states; the intake fixture yields two drops with the right statuses and `problems: 2`, and a missing `OGM_INTAKE_DIR` yields `[]`; `GET /mail?unopened=1` lists the magic link created by an invite in the test. ## Failure, security, migration and accessibility cases

No new tables or migration. Intake files are untrusted input: parsed line by line with Zod, bad lines counted in a `parseErrors` field, paths from `queue.jsonl` are only opened if they resolve under `OGM_INTAKE_DIR` (realpath check; no traversal). Settings writes are single transactions; `slots` lower than current in-use jobs is allowed (new admissions queue; nothing is cancelled). `maintainer` actions on another family are refused unless `audit` is set, and are logged with the request id. No UI.
