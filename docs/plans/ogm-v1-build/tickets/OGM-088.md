## Outcome

Pressing "Talk it through" in the creation flow files a short scope ticket in the game's repo; its worker, loading `gm-scope-options`, holds the scope conversation with the creator through the build chat (text or dictation), ends by writing the agreed scope as a file in the workspace, and the creation flow then sees `scope: agreed` with a plan it can submit to admission; when a voice key exists, the voice session's `scope` target points at the same ticket so a confirmed draft reaches that worker.

## Context and evidence

No zero-spend LLM exists outside the coding agents: no provider keys on the host, model access only through the signed-in Codex and Claude CLIs that aiur drives (E06-17, A9). The build chat's text mode already talks to a ticket's worker through aiur messages (E06-13), so the scope conversation runs inside a short "scope" aiur ticket whose worker ends by writing the agreed scope (D-VOICE-ZERO). Tickets are GitHub issues with markers and labels, a spend cap and a `control todo` nudge (E02-8, T02 §4); workers get context through the `after_create` hook bundle (E02-10); merges stay outside aiur (E02-13).

Contradictions already resolved: (1) T06 §4 routed voice `scope` targets straight to admission because no scope worker existed; with this ticket the scope session has a live ticket and OGM-086 routes confirmed drafts to it, falling back to admission only when it has none. (2) The worker cannot call the API from the sandbox (D-SBX, E03-4), so "writing the agreed scope to the API" is an outbox line (`scope.agreed`, OGM-080's envelope) plus the file `.gm/scope/<session_id>.json` committed in the ticket's PR as the durable record; the relay delivers it at once, the PR closes the ticket normally. (3) T05 §4 assigns the `gm scope` namespace to this track and build-order.json lists no CLI surface for this ticket; the single agent-side writer `gm scope done` is added here as an adjacent file and flagged.

## Scope

- `services/api/src/scope/{routes,store,outbox}.ts`: `POST /api/v1/games/:gameId/scope/sessions { choices }` (creator; `choices` = the R20 fields genre, vibe, family, world, players, pov, plus free text) → creates a job of kind `scope` through admission (OGM-013; size class `small`, edit slot) → `{ sessionId, jobId }`; `GET …/scope/sessions/:id` → `{ status: "open"|"agreed"|"abandoned", ticket?, scope?: AgreedScope, chatJobId }`; `POST …/scope/sessions/:id/abandon`; outbox handler `scope.agreed` → validate `AgreedScope`, store, mark `agreed`, system chat row "Scope agreed", notification trigger; `scopeSessions.get()` exported for OGM-086.
- `services/builder/src/scope/{template,file}.ts`: the scope ticket body (summary of the choices, "## Scope", "## Acceptance: `.gm/scope/<session_id>.json` written with `gm scope done`", "## Load skills\n- gm-scope-options", markers `<!-- gm-job:<jobId> gm-ticket:scope gm-scope:<sessionId> gm-sig:<hash> -->`), labels `complexity:1`, `feature:gm-<jobId>`, `agent:todo`, spend cap = the small reservation, `nudgeTodo`; filed through OGM-031's intake so the job row gets `aiurIssueNumber` and the chat mirror flushes (OGM-080 `flushPending`).
- `packages/gm-cli/src/commands/scope/done.ts`: `gm scope done --file .gm/scope/<id>.json [--job]` → validates against `AgreedScope`, appends a `scope.agreed` outbox line with the JSON as payload, prints the session id.
- Hook bundle addition (OGM-036's `.gm/context/job.json` gains `scope_session_id` for scope jobs; one field, documented here, written by OGM-031's bundle builder from the job row).
- Voice: `VoiceTarget{kind:"scope", session_id}` resolves to the session's ticket (OGM-086 reads `scopeSessions.get(session_id).ticket`).

## Contract and invariants

Consumer: copy `AgentOutboxLine` (OGM-080), the admission request/response (OGM-013, T01 §4), the ticket filing contract (OGM-031, T02 §4), `VoiceTarget` (OGM-085); do not redefine. Producer:

```ts
// packages/contracts/src/scope.ts (new family; one barrel line)
type ScopeChoices = { genre: string; vibe: string; family: string; world: string; players: "single" | "multi"; pov: string; other?: string };
type AgreedScope = { session_id: string; title: string; summary: string;
  scope: { included: string[]; excluded: string[] };
  tickets: { key: string; title: string; skills: string[]; dependsOn: string[]; acceptanceCriteria: string[] }[];   // T01 §4 plan.tickets
  complexity: 1 | 2 | 3 | 4 | 5; open_questions: string[]; ideas: string[] };                                        // the last two mirror record_summary
type ScopeSession = { id: string; game_id: string; creator_id: string; job_id: string; ticket?: string; status: "open" | "agreed" | "abandoned"; choices: ScopeChoices; scope?: AgreedScope; at: string };
// outbox line: { type: "scope.agreed", payload: AgreedScope }
```
Invariants: one open scope session per game at a time (a second request returns the open one); the worker never files the build job (the creator confirms the estimate in OGM-074 against admission, R12); the ticket's spend cap is the small reservation and its `max_agent_duration_minutes` is the daemon's edit setting; `AgreedScope.session_id` must match the job's session or the line is rejected; the chat for the session is the job's chat (no second stream); the scope file in the repo and the stored scope are the same bytes (the PR is the record).

## Failure, security, migration and accessibility cases

- Worker ends without writing the scope (budget exhausted, error): the session stays `open`; the job's friendly state (OGM-032) shows "out of budget"/"failed"; the creator can abandon and retry; no plan is invented.
- Duplicate `scope.agreed` lines (retries): idempotent on `session_id` + content hash.
- Secrets: the ticket body carries choices and markers only; diagnostics and context go through the hook bundle (R65), never provider keys.
- Migration: one timestamped file adding `scope_sessions`.
- Accessibility: not a UI ticket; the creation flow (OGM-074) renders the chat with 64 px controls.
