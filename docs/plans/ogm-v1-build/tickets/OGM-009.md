## Outcome

The three tested Python workers live at `scripts/py/{audio,maps,drive-sync}` with a per-tool `requirements.txt`, a documented venv path per tool in `scripts/py/workers.json` (the contract the `gm` CLI reads), compatibility symlinks at the old `scripts/{audio,maps,drive-sync}` paths so frozen prototypes and current skills keep working, `make test` running the venv-free drive-sync suite and `make test-py-models` running the 40 pytest cases in the audio venv on this host; `ci-python / python` runs `make test-py` plus a byte-compile of every worker on every PR.

## Context and evidence

`scripts/` holds 4,874 lines of Python in four groups, 67 tests, all passing: audio (35 pytest, torch/CLAP venv), maps (5 pytest, borrows the audio venv), drive-sync (27 unittest, stdlib only) and the untested one-off asset importers (E12-5). The venvs are heavy and machine-pinned (E12-6); CI cannot install torch, so the CI job runs only the stdlib suite and a byte-compile, and the model suites run on this host. D-STACK keeps Python only in `scripts/py/*` where it already works; `scripts/assets/*.py` stay where they are until `gm packs` replaces them (architecture §2). Six skills and several prototype tools reference the old paths (E12-8, E12-6), hence the symlinks. Resolved: `maps` has no venv of its own and will not get one (it needs the audio venv's numpy, Pillow and CLIP); its `requirements.txt` says so and `workers.json` points both at `scripts/py/audio/.venv`.

## Contract and invariants

Venv path contract (owner: this ticket; consumers OGM-065 `gm packs tag`, OGM-064 intake, OGM-002 `ogm-run drive-sync`):

```json
// scripts/py/workers.json
{ "version": 1,
  "workers": {
    "audio":      { "dir": "scripts/py/audio",      "venv": "scripts/py/audio/.venv",      "python": "scripts/py/audio/.venv/bin/python",      "requirements": "scripts/py/audio/requirements.txt",      "tests": "pytest", "ci": false },
    "maps":       { "dir": "scripts/py/maps",       "venv": "scripts/py/audio/.venv",      "python": "scripts/py/audio/.venv/bin/python",      "requirements": "scripts/py/maps/requirements.txt",       "tests": "pytest", "ci": false },
    "drive-sync": { "dir": "scripts/py/drive-sync", "venv": "scripts/py/drive-sync/.venv", "python": "scripts/py/drive-sync/.venv/bin/python", "requirements": "scripts/py/drive-sync/requirements.txt", "tests": "unittest", "ci": true }
  } }
```

Invocation stays `<python> -I <script> …` (T12 §4 signatures unchanged: `drive_sync.py run [--once] [--dry-run] | status`; `analyze.py`, `build_audio_cards.py`, `measure.py`, `tag_maps.py analyse|cards`). Make targets: `make test` = `make test-py`; `make test-py` = `python3 -I scripts/py/drive-sync/test_drive_sync.py` + `make py-compile`; `make test-py-models` = `scripts/py/audio/.venv/bin/python -I -m pytest scripts/py/audio scripts/py/maps -p no:cacheprovider` and fails loudly when the venv is missing. Check name: `ci-python / python`; `ci / required` is unchanged (aiur's `merge_policy.ci: wait` waits for every workflow on the head).

## Failure, security, migration and accessibility cases

- A `git mv` of a directory containing an ignored venv moves the venv on disk; if the agent's workspace has no venv (a fresh clone), nothing breaks and `make venv-audio` documents the rebuild (network; not CI).
- The symlinks must not be followed by CI globs in ways that double-count: `compileall scripts/py` targets the real directory only.
- Secrets: `drive-sync.example.toml` stays an example; the real TOML and key live in `~/.config/ogm` (E05-11) and `test_drive_sync.py` keeps refusing a config inside the repo.
- No migrations; no UI.
