## Outcome

`POST /api/v1/reports` stores a report, computes its signature, routes it deterministically to `game_repair`, `platform`, `editor_hint` or `stored`, attaches duplicates to the open signature instead of spawning work, keeps the diagnostic bundle in the private blob store and never on GitHub, admits a `kind: 'repair'` job through OGM-013 sharing edit slots at one third of a feature reservation only for reproducible crashes within the owner's allowance, and hands platform-bound reports to a pluggable `IssueWriter` whose V1 default is a stored operator queue.

## Context and evidence

E01-15 and B8 §6: one report button; the bundle goes to private storage; signature = hash(error type, normalised message, top in-game frames after source mapping, gameId), gameId omitted for platform signatures; platform if the frame is outside the iframe or the same signature repeats across two games; editor-fixable complaints are offered as an editor change at no agent cost; ambiguous cases go to game repair first; reports without an error are grouped and never auto-merged across families; repair = a `game_repair` job sharing edit slots at about one third of a feature's reservation, 2 attempts (D5: config until measured); platform bugs are filed without `agent:todo` by a write-only identity so user text never drives a daemon with platform write access (spec §5.10). D-COMMIT: only the commit service holds the GitHub credential, so a GitHub-filing `IssueWriter` must go through it. Resolved: which identity files platform issues is T03's call; this ticket exposes the seam and ships the stored queue (T01 §6 risk 12).

## Scope

- Tables `reports` (the `CreateReport` fields, `signature`, `route`, `reproduction` `crash_with_error|wrong_behaviour|not_reproducible`, `job_id`, `bundle_key`, `reporter_id`, `created_at`) and `report_signatures(signature PK, scope game|platform, game_id, count, first_at, last_at, open_job_id, platform_ref, status open|repaired|closed)`, plus `platform_issue_queue(id, title, body, labels_json, status pending|filed|dismissed, ref, created_at)`.
- `services/api/src/reports/signature.ts`: normalisation and SHA-256 signature; `classify.ts`: the rule table returning `{ route, reproduction, reason }`; `routes.ts`: `POST /api/v1/reports`, `POST /api/v1/reports/:id/bundle` (≤ 2 MB body → `BlobStore.put` under `private/reports/<reportId>`), `GET /api/v1/reports?gameId=` (owner or admin, `report.view`), `GET /api/v1/reports/:id/bundle` (admin; signed URL from OGM-005).
- `repair.ts`: for `game_repair`, build a `JobPlan` from redacted metadata only (release, signature, reproduction class, report id; no text, no frames, no bundle) and call OGM-013's `admit` with `kind: 'repair'`, `complexity: 2`, `idempotencyKey: 'repair:<signature>'`, `actor` = the game owner; on 402 the route becomes `stored` with `pendingBudget`.
- `IssueWriter` seam: `StoredIssueWriter` (rows in `platform_issue_queue`, default) and `CommitServiceIssueWriter` (only if `packages/contracts/commit.ts` carries a `file_issue` op at pickup; otherwise not implemented and noted in the PR).
- Repair policy constants in `services/api/src/reports/policy.ts`: `REPAIR_RESERVATION_FRACTION = 1/3` (applied through OGM-013's `repair` size-class rows), `REPAIR_ATTEMPTS = 2` (written into the plan's acceptance criteria for OGM-031/aiur), `WRONG_BEHAVIOUR_REPAIR_AT = 3` matching reports.

## Contract and invariants

Consumer of OGM-010: copy `CreateReport`, `CreateReportResponse`, `ReportRoute`, `ReportError`, `IssueWriter` from `packages/contracts/reports.ts`; do not redefine. Consumer of OGM-013: `admit(deps, CreateJobRequest, actor)`. Consumer of OGM-005: `BlobStore.put(key, bytes, { contentType })`, `signedGet(key)`.

Rules (first match wins): (1) `error` present and any top-3 frame `file` is outside the game's own source (matches `/^(https?:\/\/ogm2000\.netlify\.app|@ogm\/host|@gm\/host)/` or is not under the game origin `/g/<gameId>/`) → `platform`, scope `platform`; (2) `error` present and the game-scoped signature already exists for a different `game_id` → `platform` (cross-game repeat); (3) `error` present with ≥1 in-game frame → reproduction `crash_with_error` → `game_repair` (attach if the signature is `open` with `open_job_id`); (4) no `error`, `text` matches the editor-hint table (`too (fast|slow|hard|easy|big|small|loud|quiet)`, `(more|less|fewer) \w+`, `speed|volume|size|count` paired with a number word) → `editor_hint`; (5) no `error`, `text` present → `wrong_behaviour`, `stored`, counted per `(gameId, releaseId, normalised text)`; at `WRONG_BEHAVIOUR_REPAIR_AT` matching reports a repair is admitted; (6) otherwise `stored`, `not_reproducible`. Signature normalisation: lower-case, digits → `#`, hex runs ≥ 8 → `#`, whitespace collapsed; frames reduced to `file:fn`. Invariants: a report never spends unless (3) or (5)'s threshold applies and the owner's allowance admits it; a `platform` report never creates a job; the issue body for repairs contains only redacted metadata; bundle bytes are private (`private/` keys, admin-only signed reads); user text never reaches a daemon prompt (platform queue is operator-read).

## Failure, security, migration and accessibility cases

The bundle is accepted only as `application/octet-stream` or `application/json` up to `OGM_REPORT_BUNDLE_MAX_BYTES` (2 MB) and stored under a `private/` key; no listing route exists. A `BlobStore.put` failure stores the report without a bundle and returns 201 with `bundleKey` absent. Admission errors other than 402 return 502 `repair_admission_failed` with the report still stored. Players may file reports on games they can play (`report.file`); `report.view` is owner or admin. Rate limit 20 reports per user per hour. Timestamped migration. The report button's 64 px target is OGM-071's.
