## Contract and invariants

Consumer of `GmNet` (OGM-054), the room protocol (OGM-050), the verify report (OGM-090 `packages/gm-verify/report.ts`) and the skill pack layout (OGM-091); copy, do not redefine. The rules, verbatim from T07 §4.4:

1. Input never mutates the world directly: it becomes an `InputFrame` consumed by `applyInput(playerIndex, frame)` in the fixed step.
2. All per-player state lives in `players: Map<playerIndex, PlayerState>`; no singleton `player`.
3. Entity ids are host-minted, globally unique strings; never array positions or per-session counters.
4. Spawn points are design data (`design/spawns.json`), at least `maxPlayers` of them.
5. The host is authoritative; peers render snapshots and send inputs only; game logic never assumes a server.
6. `serializeSnapshot()/applySnapshot()` cover everything visible; transient effects are derived, not synced.
7. HUD reads `players.get(localPlayerIndex)`; camera rig follows the local avatar.
8. `tick(seconds)` and `render_game_to_text()` work with `players.length ≥ 2`.

The scenario, verbatim from T07 §4.5: "Two Playwright contexts against the local rooms service: (1) create room, invite, sign in as a second user, join, assert `welcome` within 2 s; (2) host places three entities, assert watcher's effective design equals host's at each rev; (3) host types a canary string in the build chat, assert it appears in no frame the watcher received; (4) Play, assert the peer is in `playing` within 500 ms; (5) peer sends input for 1 s, assert its avatar moved in the host's snapshot; (6) close the host context, assert `pausedForHost` then `ended: host-left` after the window (shortened by test config); (7) load a draft, assert both clients report `draft.ready` and the pin changed."

Invariants: the checker is deterministic (no model call, E10-19) and exits 1 naming the rule and file; the template ships no pack assets (grey-box only); the scenario binds and connects to `127.0.0.1` only, never to the public hostname; the canary is a random 24-character string generated per run and searched byte-wise in every received message (`received()` ring buffer of OGM-053, or the harness client's own buffer); step 3 in harness mode sends the canary through `presence.focusControlId` with `privateMode: true` and through a `design.tx` patch with path `['prompt', canary]`, both of which the room must zero or drop.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/gm-verify test -- two-client` runs the scenario against the template and the local rooms service: `welcome` ≤ 2,000 ms; watcher doc equals host doc at revs 1–3; canary absent from every received message (the test also asserts the canary was actually sent, so the guard is exercised); peer `playing` ≤ 500 ms after the host's `play()`; peer input for 1 s moves `players[1].p` in the host's `renderGameToText()`; host context closed → `pausedForHost` then `ended: host-left` within the shortened window; draft load → both `draft.ready`, `pin.buildId` changed. Report JSON has `clients: 2`, `renderer` string, `unchecked[]` listing `iPhone Safari`, `WAN latency`, and `sign-in` in harness mode. Each assertion fails if its server or client rule is removed (verified once by flipping `validateDesignTx` off locally; not committed).
- `skills/gm-multiplayer-ready/scripts/check.test.ts`: fixtures `good/` (the template) passes; `bad-singleton/`, `bad-spawns/`, `bad-ids/`, `bad-no-applyinput/` each fail naming the rule number.
- `gm new --template game-multiplayer` then `gm check`, `gm test`, `gm-sdk check` green; `pnpm -r typecheck`, `pnpm -r lint`.
### At-merge gate
- `ci / required` green on current main (the scenario runs on this host, not in CI; CI runs the checker tests and template typecheck).
### Human or e2e evidence
- Kevin's phone off Wi-Fi joining a room hosted on his laptop: the first WAN number, recorded in OGM-100's `acceptance.md`.

## Failure, security, migration and accessibility cases

Harness mode uses a fixture secret passed by env to a scenario-owned rooms process; it never reads `~/.config/ogm`. The scenario kills its rooms process and browsers on any failure (`finally`). A flaky `playing ≤ 500 ms` on a loaded host is reported with the measured value, not retried silently. No migration. Template HUD text is minimal and readable at phone size; touch targets are the host's.
