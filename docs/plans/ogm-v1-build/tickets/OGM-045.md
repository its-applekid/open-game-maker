## Outcome

`POST /api/v1/games/:g/publish {buildId}` on a `tested` build of `main` folds the working set into `design/design.json` through the commit service (`fold_design` then `release`, both behind the content gate), appends a `Release` row with the derived version and an assembled changelog, moves `games.publishedReleaseId` by compare-and-set and tags `gm/<gameId>/v<version>`; `POST …/rollback {releaseId}` creates a new `kind: 'rollback'` release pointing at the older `(build, snapshot)` with the count of saves that will become `incompatible_after_rollback`; `GET /api/v1/games/:g/published` answers with an ETag and 304 on `If-None-Match`; every tested build artifact is kept.

## Context and evidence

Effective design = build base doc ⊕ reduced overrides; overrides never touch source until Publish, when a deterministic fold writes `design/*.json` by a bot author through the commit service (E08-3, D-COMMIT). Publish pins `(buildId, overrideSnapshotId)` and moves one pointer separate from Git `main`; releases are append-only with a monotonic `seq`; two publishes race on CAS (E08-5; A3: only from `main` after a merge). Rollback is a new release row, nothing deleted, saves on newer schemas become `incompatible_after_rollback` lazily (E08-6). The version is Kevin's derived counter (E08-7, D-VERSION; `deriveVersion` from OGM-043). Changelogs come from `.gm/changes/<jobId>.md` notes and transaction labels with no model call (E08-18). Every tested artifact is kept; the GC-and-rebuild path is dropped (E08-20, D-ARTIFACTS). Drafts on a public repo are public from the first merge; the gate runs at merge and at fold (E08-19). Resolved here: the rights check at Publish is enforced by the commit service's publish gate (OGM-039) and pre-checked by this ticket with OGM-062's `gm check assets --publish`; the rebuild-from-tag path does not exist.

## Contract and invariants

Consumer: copy `Build`, `OverrideSnapshot`, `Release`, `ChangeNote`, `WorkingSet` from OGM-040's `packages/contracts/src/{releases,design-log}.ts`; copy `CommitOp`, `CommitResult`, `BoundaryVerdict` from OGM-035's `packages/contracts/src/commit.ts` (T03 §4: `fold_design {gameId, base, files}`, `release {gameId, sha, semver, changelog}`); copy `deriveVersion` from OGM-043. Do not redefine. Invariants: publish requires `build.status === 'tested'`, `build.branchId === main`, `authorize(actor,'game.publish')`, the rights pre-check passing; `fold` is deterministic (two folds of the same input are byte-identical; `OverrideSnapshot.sha256` = `sha256Canonical({entries, entityOps})`); `releases.seq` is `max(seq)+1` per game inside one SQLite transaction; the pointer moves only by `UPDATE games SET published_release_id=:new WHERE id=:g AND published_release_id IS :expected` (0 rows → 409 `pointer_moved`); a rollback release carries `restoresReleaseId`, the restored `buildId`/`snapshotId`, a new `seq` and a new version (major increments); nothing is deleted; `artifact` is always `'present'` in V1 (`'gc'` stays in the enum).

```http
POST /api/v1/games/:g/publish {buildId, changelog?}   → 201 Release | 409 {error:'not_tested'|'not_main'|'pointer_moved'} | 403 {verdict: BoundaryVerdict} | 422 {rights: [...]}
POST /api/v1/games/:g/rollback {releaseId}           → 201 Release & {affectedSaves: number | null}
GET  /api/v1/games/:g/published                      → 200 {releaseId, version, buildUrl, changelog}  ETag: "<releaseId>"  | 304 | 404 (never published)
```

## Acceptance and verification

### Agent gate
- `fold.test.ts`: byte-identical output for the same input across two runs and across key-order permutations; entries with status other than `carried`/`renamed` are excluded; entity creates and deletes are applied (create, delete, set order).
- `releases` API tests against the fake commit server: publish happy path (two commit ops in order, release row, pointer CAS, tag name); non-tested build → 409; build on a branch → 409 `not_main`; gate verdict `allowed:false` → 403 with the verdict and no row; rights pre-check failure (Synty asset, public repo; AE5) → 422 and no commit call; concurrent double publish → exactly one succeeds, the other 409 `pointer_moved`; rollback → new row with `kind:'rollback'`, same `buildId`/`snapshotId` as the restored release, major incremented, pointer moved, `affectedSaves` from OGM-046's counter or `null`; `GET /published` → ETag and 304; changelog assembly from two change notes plus three labels, with an email address stripped by the lint; every tested artifact remains `present` after rollback.

## Failure, security, migration and accessibility cases

Commit service unreachable or `ok:false` → no release row, no pointer move, the verdict surfaced verbatim (the creator sees "these words will be public" reasons; E08-19). `fold_design` succeeded but `release` failed → the fold commit exists on `main` without a release; publish is retried idempotently by `(gameId, buildId, snapshot sha)` and reuses the existing sha. Only `game.publish` holders publish; the service token for the commit client and the builder's token for `/internal/*` come from `packages/config` and never appear in responses or logs. Migrations are three timestamped files. Public drafts: creation copy is OGM-074's; this ticket returns the gate's reasons. No UI here; OGM-077 keeps 64 px targets.
