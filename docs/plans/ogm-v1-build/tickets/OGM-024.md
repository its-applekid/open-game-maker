## Outcome

`@gm/sdk/phaser` mounts a Phaser 4.2 game whose Scale Manager presents the declared logical size (`FIT` for `fixed`, `EXPAND` for `responsive`), maps scene lifecycle to `GameInstance` (`pause`/`resume`/`dispose`/`restart-scene`), yields its loop to the SDK clock in test mode, and ships three 2D camera presets (`topdown`, `side`, `fixed`) as `CameraRig`s; `templates/game-2d` (layout modelled on `phaserjs/template-vite-ts`) is a grey-box platformer scaffold that boots headless in Chromium on the GPU flags and under `GM_VERIFY_SOFTWARE_GL=1`, reaches `window.__ready`, answers `advanceTime`, `renderAt` and `renderGameToText`, and renders a non-blank still.

## Context and evidence

The 2D engine is Phaser 4.2 (release plan "Stack"; A4 §2 verified 4.2.1 stable, Scale modes `FIT`, `ENVELOP`, `RESIZE`, `EXPAND` present in source). No Phaser code exists in the repo (E04-19: the studio's 2D scenes are canvas/DOM); B15 §2 names `phaserjs/template-vite-ts` (MIT, Phaser 4) as the 2D base and B15 §6.2 makes `gm new` scaffold-only (boot, hooks, input map, grey-box level, no entities). The 2D rigs `topdown`, `side`, `fixed` are Phaser camera presets by decision (E04-12); the full rig set and the input merge are OGM-025. Resolved, do not reopen: simulation state is plain data stepped by the SDK clock and Phaser objects are views (A4 §10.1), so the sim is testable in Node without Phaser; Phaser's `TimeStep` is slept in test/capture mode and stepped once per `advanceTime`/`renderAt` (E04-3 "capture mode is exact"); the template's layout follows `template-vite-ts` by name, its files are written fresh (no network, no vendoring).

## Contract and invariants

Consumer: `GameModule`, `GameInstance`, `CameraRig`, `ViewId`, `ActionFrame` from OGM-020; `boot`, `Runtime`, `defineFeature` from OGM-022; copy, do not redefine. This ticket's public shape (`@gm/sdk/phaser`):

```ts
export function createPhaserGame(rt: Runtime, opts: { parent: HTMLElement; presentation: GameManifest['presentation']; scenes: Phaser.Types.Scenes.SceneType[]; test?: boolean }): Promise<{ game: Phaser.Game; renderOnce(): void; info(): RenderInfo }>;
export function bindLifecycle(rt: Runtime, game: Phaser.Game, levelKey: string): { pause(): void; resume(): void; dispose(): void; restartScene(data?: unknown): void };
export const cameraPresets: Record<'topdown' | 'side' | 'fixed', (scene: Phaser.Scene, cam: Phaser.Cameras.Scene2D.Camera) => CameraRig>;
```

Invariants: in test/capture mode Phaser's `TimeStep` never runs on its own (`game.loop.sleep()` after `create`), and one `renderOnce()` follows each `advanceTime`/`renderAt`; in live mode the SDK clock is advanced from the scene's `update(time, delta)` (`rt.clock.live(time)`) so there is one clock; the sim never reads Phaser objects (views only; `sim.test.ts` imports no Phaser); `pause()` halts within one step (A4 §5 `core.lifecycle`); the level's entities are `Record<id, …>` with stable ids; no `Math.random`/`Date.now` under `src/` (grep test); `camera-presets` implement every `CameraRig` member, with `worldToScreen` via `cam.getWorldPoint` inverse (`cam.worldView` arithmetic).

## Failure, security, migration and accessibility cases

A WebGL context failure makes Phaser fall back to `Phaser.CANVAS` when `type: Phaser.AUTO`; the wrapper uses `AUTO` and reports `backend: 'canvas'` so verify can flag it. `game.destroy` during a pending `restart-scene` is guarded by a `disposed` flag. The template declares actions `move` (axis) and `jump` (button) so the host overlay has ≥ 64 px primary targets (OGM-028 renders them); the scaffold itself draws no UI text. No secrets; no migrations.
