## Contract and invariants

Consumer of every lane's contract by use, not by code. The checklist (numbering is the contract; each item names its evidence):

1. Services: `ops/bin/ogm-status` shows every `ogm-*` unit active and every listener on `127.0.0.1`; evidence: command output. (R69)
2. Ingress: from Kevin's phone on cellular, `https://<funnel host>:8443/healthz` returns 200; evidence: phone screenshot + `curl` from the tailnet. (R69, OGM-006)
3. Sign-in on a phone: age screen → passkey or magic link → games picker; evidence: phone recording clip. (R1, R2)
4. GitHub connect: creator connects a GitHub account; a new game creates a repo with `.aiur/*`, labels, `ci.yml`, `.claude/skills/gm-*`, links, `AGENTS.md`, `skills.lock`; evidence: `gh repo view`, `ls -la .codex/skills`. (R6, R62; AE7)
5. Daemon: on the first admitted job `ogm-aiur@<slug>` starts and `aiur status` lists the ticket as todo within one poll; evidence: `systemctl --user status`, `aiur status` output. (R61; AE7)
6. Budget offers: a request over today's allowance offers trim / split / queue / ask; choosing queue creates `start: at_reset` and the ticket is filed at the reset with spend cap = reservation; evidence: API JSON, the issue's spend cap. (R11, R12, R26; AE1)
7. Make a game by text: scope chat ends in an admitted job; evidence: clip. (R20, R21, R88)
8. Stills arrive: at least one `gm chat post` still and one clip appear in the build chat during the build; evidence: chat screenshot, `report.json` with the renderer string naming the Intel GPU. (R22, R102)
9. Gates: the build's PR shows `gm check` and `gm test` green and `ci / required` green; evidence: PR checks screenshot, `gm test --json` output (3,600 ticks, round-trip). (R103; AE6)
10. Assets and rights: the game's `assets.lock.json` exists; with a Synty asset in a public-repo publish attempt, `gm check assets --publish` exits 1 naming the asset and the commit service refuses the fold; evidence: command outputs. (R53; AE5)
11. Play the draft on the phone: the draft loads from the games origin in the iframe, sound plays after the first tap; evidence: phone clip; `unchecked` list in the report. (R40, R46, R111)
12. Edit while a second build runs: an override applied through the bridge is visible at once while a job is `building`; evidence: clip + the job state. (R30–R33)
13. Re-apply report: after the second build is tested, the report classifies overrides (carried / renamed / dropped) and the editor shows the card; evidence: screenshot. (R33; AE2)
14. Branch: "New version from here" creates a branch; both versions play; evidence: clip. (R37)
15. Merge: a `both_changed` conflict is listed and everything else auto-merges; evidence: merge plan JSON. (R38; AE3)
16. Invite and room: a family member joins by link as a watcher; the watcher's design equals the host's at each rev; a canary typed in the build chat never appears in any frame the watcher receives; Play moves both within one round trip; evidence: the two-client scenario's report. (R70–R76; AE4)
17. Host leaves: the session ends with progress saved; evidence: room log. (R77)
18. Publish: a tested build on `main` folds to `design/*.json`, tags `gm/<gameId>/v<version>`, moves the pointer; the update indicator shows; rollback creates a new release; evidence: `git tag`, release rows. (R90–R92)
19. Bug button: a planted crash → report → repair ticket with a redacted body → promise test; evidence: issue body head, `gm test` promises line. (R68)
20. No money: `aiur` usage accounts show subscription runs only; no provider key in any env file; evidence: `grep -L` over `~/.config/ogm/env/`, usage output. (R14)

Then: requirement disposition table (every R-ID → ticket(s) → merged yes/no → note), and a "Deferred" list copied into `deferred-findings.md`.

Invariants: no check passes on hearsay; each Result is `pass`, `fail` or `blocked:<gate>`; a `fail` names the owning ticket and is filed as rework before this ticket closes; the head SHA is the same for every item in one run.

## Acceptance and verification

### Agent gate
- `acceptance.md` has 20 numbered items, each with Evidence, Result, Head SHA, Date filled; no Result is empty; the disposition table lists every R-ID in `requirements.md` (a 10-line script asserts the set equality).
- `python3 -I docs/plans/ogm-v1-build/tools/dispositions.py` runs and its output is what the file contains.
### At-merge gate
- `ci / required` green on current main at the tested head; the head SHA in `acceptance.md` is an ancestor of `main` at merge.
### Human or e2e evidence
- Kevin performs items 2, 3, 11 on his own phone (real iPhone Safari: sign-in, play, sound) and the recording is the evidence; the Executor performs the rest and watches the clips.

## Failure, security, migration and accessibility cases

- A gate unresolved (Funnel, GitHub App): the item is `blocked:<gate>` and the ticket stays open; nothing is marked pass by substitution.
- Evidence never includes secrets, tokens, cookies or the family member's email beyond a placeholder; phone recordings are trimmed to the app.
- Accessibility: item 3 and 11 note the 64 px targets and that captions/read-aloud defaults are on (A12) as observed, not measured.
- No migrations; no product UI changes.
