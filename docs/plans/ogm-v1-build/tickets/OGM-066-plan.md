# OGM-066 plan — Style families and family enforcement in search

## 1. Problem frame

C1 saw Synty goblins beside a Kenney hero "look like two different games"; C2 §2 answers with style families: the creator picks a family, the lockfile records it, and search stays inside it unless an agent logs an exception. Nothing of that exists in code (E05-15). This ticket writes the curated family file with a schema and a coverage check, makes `gm assets search` default to the game's family, and serves the families to the creation flow through one API route.

Requirements trace: R55 → `style-families.json` with the seven C2 families, views and coverage; one family per game enforced in search by default with logged exceptions; Kenney families first. R20 → the creation flow's family step reads `GET /api/catalog/style-families` (OGM-074 renders it).

Repository conventions: pnpm workspace; package scripts `build`, `test`, `typecheck`, `lint`; Vitest; no Playwright; the API route lives in `services/api` (Hono, binds `127.0.0.1` per OGM-010); no secrets (the blob signing key is read by `packages/blob-store` through `packages/config`, not here); no new dependencies; PR first line `Closes #<issue>`; `## Local tests` with policy, tested head SHA, base, selection, commands and results.

## 3. Implementation units

### U1. The data file and its schema

Goal: the seven families as validated data with real pack ids.

Files: Create `packages/asset-cards/data/style-families.json`, `packages/asset-cards/src/families.ts`, `packages/asset-cards/test/families.test.ts`, `packages/asset-cards/test/fixtures/catalog-ids.json` (sorted pack ids from `catalog.json`, generated by `scripts/families-coverage.ts --emit-ids`).

Approach: `families.ts` defines `StyleFamilySchema` (Zod; `id` enum of the seven, `views` from the `pov_fit` enum, `packs.primary` non-empty, refinement `creation_choice → coverage.characters && environment && props`), `loadFamilies()` (reads the JSON next to the compiled file via `import.meta.url`), `familyFor(packId)` (reverse map over primary and extras), `isCreationChoice`. Data: chunky-low-poly (Kenney 3D kits; views iso/topdown/follow/orbit), detailed-low-poly (`synty-polygon-*`, `synty-sidekick-goblin-fighters`, `synty-animation-goblin-locomotion`; views follow/orbit/fps/iso; `creation_choice: false`, note "FBX only until Blender"), simple-low-poly (`synty-simple-buildings`, `synty-simple-props-items-icons`; false), pixel-art (`kenney-tiny-dungeon`, `kenney-tiny-town`, `kenney-tiny-farm`, `kenney-tiny-battle`, `kenney-pixel-platformer*`, `kenney-micro-roguelike`, `kenney-roguelike-*`, `kenney-1-bit-*`, `kenney-pico-8-*`, `kenney-pixel-shmup`; views topdown/side), flat-cartoon (`kenney-platformer-pack-remastered`, `kenney-platformer-assets-*`, `kenney-toon-characters`, `kenney-space-shooter-*`, `kenney-topdown-shooter` if present else omit, `kenney-rpg-tiles-vector`, `kenney-abstract-platformer`, `kenney-jumper-pack`, `kenney-physics-assets`; views side/topdown), isometric-2d (`kenney-isometric-miniature-*`, `kenney-isometric-tiles-*`, `kenney-isometric-medieval-town`, `kenney-isometric-modular-*`; views iso), sketch (`kenney-sketch-town`, `kenney-sketch-town-expansion`, `kenney-sketch-desert`, `kenney-scribble-dungeons`, `kenney-scribble-platformer`; views side/topdown). `extras` for 2D and 3D families: `kenney-ui-pack`, `kenney-game-icons`, `kenney-input-prompts`, `kenney-interface-sounds`, `kenney-ui-audio`, `kenney-rpg-audio`, `kenney-impact-sounds`, `kenney-music-jingles` and the Sidetrax music packs as `any`-family audio (listed once under a top-level `shared: {ui: [], sfx: [], music: []}` key rather than repeated per family). Every id is checked against `catalog-ids.json`.

Interface sketch: as in the ticket.

Test scenarios:
- Given the file, when parsed, then seven families and every pack id ∈ fixture ids (and on this host ∈ `catalog.json`).
- Given a family with `creation_choice: true` and `coverage.props: false`, then the schema rejects it.
- Given `familyFor('kenney-tiny-dungeon')`, then `pixel-art`.
- Given the `collection_tags.jsonl` seeds, when compared, then the test prints disagreements as a warning table (not a failure) for curation.

### U2. Coverage computation and report

Goal: `coverage` is measured from cards, not typed.

Files: Create `packages/asset-cards/scripts/families-coverage.ts`; Modify `packages/asset-cards/package.json` (`families:coverage`, `families:emit-ids`); Test in `test/families.test.ts`.

Approach: `computeCoverage(index, family)`: over cards whose collection id's pack segment ∈ `packs.primary ∪ extras ∪ shared.*`: `characters` = any `model/character|creature` or `sprite/character` or `anim/*`; `environment` = `model/kit|nature|building` or `sprite/tile|background` or `texture/*`; `props` = `model/prop|weapon|food|vehicle` or `sprite/prop|item`; `ui` = `ui/*`; `sfx` = `audio/sfx/*`; `music` = `audio/music/*`. Before OGM-065 lands, 3D/2D asset cards are `draft` with kind/subkind from extensions (OGM-064) and the legacy packs have none at all: fall back to the collection card's `collection_info.counts` keys (`model/character` etc., written by `build_collection_cards.py`) so the report works on today's library. The script loads the index (`loadIndex(root)`), computes coverage for each family, rewrites the JSON in place (stable key order), prints a table, exits 1 if a `creation_choice: true` family lost characters/environment/props. OGM-067's `gm packs index --families` calls the same function.

Interface sketch (CLI): `pnpm --filter @ogm/asset-cards families:coverage [-- --root assets-local] [--check]`.

Test scenarios:
- Given the fixture index with Mini Dungeon (characters, kit, props) and no UI, when computed for chunky-low-poly restricted to that pack, then `{characters: true, environment: true, props: true, ui: false, sfx: false, music: false}`.
- Given `--check` and a creation-choice family missing props, then exit 1.

### U3. Search default and the logged exception

Goal: inside a game repo, search stays in the family unless an exception is logged.

Files: Modify `packages/gm-cli/src/commands/assets/search.ts`; Test `packages/gm-cli/test/search-family.test.ts`.

Approach: before building the `SearchQuery`, if `--family` is absent, read `assets.lock.json` from `cwd` (OGM-062's `readLock` if merged; otherwise a minimal JSON read of `.family`, replaced at integration); when a family is known and `--any-family` is absent, set `q.family = lock.family` and `q.familyMode = 'strict'` (the `search()` predicate is `style_family ∈ {family, 'any'}`; add `familyMode` to `SearchQuery` in `packages/asset-cards/src/query.ts`, default `'strict'` when `family` is set); `--any-family` requires `--reason` (exit 2 otherwise) and emits `assets.family_exception {family, reason, words, kind}`; print a one-line note `family: <id> (lockfile); use --any-family --reason to widen` on stderr when the default applied and stdout is a TTY.

Interface sketch (CLI): `gm assets search <words> [--family <id>] [--any-family --reason "<why>"] …`.

```ts
// packages/asset-cards/src/query.ts (one field added)
export type SearchQuery = { /* OGM-060 fields */ family?: StyleFamilyId; familyMode?: 'strict' | 'prefer' };  // strict: style_family ∈ {family, 'any'}
// packages/asset-cards/src/families.ts
export function inFamily(card: ResolvedCard, family: StyleFamilyId): boolean;   // shared with OGM-062's use rule
```

Execution note: add `inFamily` to `families.ts` first and have both the search predicate and (at integration) OGM-062's `rules.ts` import it, so the two never diverge.

Test scenarios:
- Given a temp repo with `family: pixel-art` and the fixture index, when searching `orc`, then no chunky card; with `--any-family --reason "no pixel orc exists"`, the orc appears and one event line with the reason exists; `--any-family` alone exits 2.
- Given no lockfile, then no default and no event.

### U4. `GET /api/catalog/style-families`

Goal: the creation flow's data source.

Files: Create `services/api/src/catalog/routes.ts`, `services/api/test/catalog.test.ts`.

Approach: Hono router in the OGM-010 shape (`export const routes = new Hono().get('/style-families', handler)` mounted at `/api/catalog` by the directory scan); handler loads families once (module-level cache), joins each pack id to its collection card title from the index (`loadIndex(config.OGM_ASSETS_ROOT)`; cached with the index's `built` stamp), resolves `thumbnailUrl` by looking up the collection card's `previews.thumb` blob hash in the index (`previews.blob` set by OGM-067) and calling `blobStore.signedGet(hash, endOfDay)`; `null` when absent or when the collection's audience is private; sets `ETag` from a hash of the JSON and answers 304 on match; `Cache-Control: public, max-age=300`.

Interface sketch: `GET /api/catalog/style-families → 200 StyleFamilyApi[]`; `StyleFamilyApi` exported from `@ogm/asset-cards`.

Test scenarios:
- Given the fixture index and families, when requested, then seven entries, `creationChoice` false for the two Synty ones, packs carry `name` from the card title, ETag present, second request with `If-None-Match` → 304.
- Given no blob for a thumb, then `thumbnailUrl: null`.
- Given a private collection with a blob, then `null`.
