## Contract and invariants

Workspace layout (owner: this ticket; every package ticket consumes):

```yaml
# pnpm-workspace.yaml
packages:
  - "apps/*"
  - "packages/*"
  - "services/*"
  - "skills/*"
  - "templates/*"
```

- Package names: `@ogm/<dir>` for apps, services and platform packages; `@gm/sdk`, `@gm/host` for the engine side (architecture §2).
- Every package ships its own `package.json` with scripts `build`, `test`, `typecheck`, `lint` (missing ones are skipped by `--if-present`) and its own dependencies; the root `package.json` holds only tooling devDependencies and is not edited by later tickets except to add a workspace script.
- Check name `ci / required` is the only merge gate; later lanes add separate workflow files, never new jobs in `ci.yml`.
- `.gitignore` is a superset of today's: `assets-local/`, `prototypes/*/site/assets/`, `prototypes/*/.netlify/`, both venvs, `__pycache__/`, `docs/research/v0.5/schemas/tools/node_modules/` all stay.

## Failure, security, migration and accessibility cases

- A wrong glob in `.gitignore` could expose `assets-local/` (licensed bytes) or a serial: the check-ignore test above runs in CI through `pnpm lint` (U4 adds it as a script).
- `corepack enable` can be missing on a runner: the workflow falls back to `npm i -g pnpm@10.33.0`.
- No secrets exist in this ticket; `.env*` are ignored, `.env.example` is allowed (OGM-003 writes it).
- No migrations, no UI.
