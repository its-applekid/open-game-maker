## Outcome

An admin opens `/admin` and manages the family: members and peer admins (the owner cannot be removed), invitations, each member's daily allowance in the friendly unit and the reset zone, concurrency slots and the visible platform cap, the oversight list of games with delist and abuse actions, and a read-only Drive intake status; `/admin/builds` lists builds with cost and retries, and a build opens a timeline of aiur phases with the nine-activity breakdown inside `implement`, cost, retries and verification results, with roll-ups per game and per member over time.

## Context and evidence

Admin scope and limits come from R3 (admins cannot edit or take over another adult's game) and A12; the API is OGM-017's, policy-checked server-side (R5). Build analytics are categories, timings and counts joined to aiur run ids, never prompt or source text (E01-18, C2 §1, R66); the read routes are OGM-014's (`GET /api/v1/admin/builds/:jobId/timeline` merging aiur phases `dispatch → workspace_setup → agent_spinup → implement → build_test → pr_opened → pr_ready → review_pause → rework_start → ci_result → pr_merged` with OGM activities). Intake status is read-only over the Drive listener's `queue.jsonl` and `intake.json` through OGM-017; the folder id stays in the operator's TOML (E05-11, R84, A6). Amounts are micro-dollars shown in the friendly unit (D-BUDGET-UNIT). Resolved: cell suppression and reading-grade limits are out of V1 (A12); admin visibility follows the oversight scope (E01-18).

## Scope

- Route module `apps/web/src/routes/admin/route.tsx` with nested `/admin` (oversight list), `/admin/members`, `/admin/invites`, `/admin/budgets`, `/admin/builds`, `/admin/builds/:jobId`, `/admin/intake`; a guard that reads the session's role from OGM-072's `lib/api/auth.ts` and redirects non-admins to `/games` (the server still enforces).
- Members: list with role; make or remove peer admin; remove member (not the owner, not self); each action a confirm.
- Invites: create a `member` invite bound to an email (the family allowlist switch for `play` invites shown as a toggle, A2); list with state; revoke.
- Budgets: per-member allowance (friendly unit, edited as units and sent as micro-dollars), reset zone select, concurrency (creation and edit slots), platform cap shown and editable; today's remaining per member read-only.
- Oversight: games across the family (owner, visibility, published version, last build), Delist and Flag abuse actions with confirm; no editing of another adult's game.
- Intake: the listener's status (last poll, pending, downloaded, skipped, rejected, failed drops) and intake reports, read-only; no folder id shown.
- Builds: list (game, member, kind, state, cost in units, retries, duration) with filters by game and member; detail: horizontal timeline of aiur phases with the activity blocks nested inside `implement`, a per-activity bar of minutes, cost, retries and repair attempts, verification results; roll-ups: minutes by activity per game and per member over a selectable window (7 / 30 / 90 days) as plain SVG bars with labels (colour never the only cue).
- Phone layout: tables become cards under 600 px; 64 px primary actions.
- `window.__ogmHost.admin = { route, lastTimeline }` behind `?test`.

## Failure, security, migration and accessibility cases

A 403 from any admin route shows "not allowed" and refetches the role; partial analytics (missing aiur usage for a run) renders "unknown", never 0 (planning-contract rule carried over); stale intake status shows its `observed_at`. No secrets or tokens in the client; the role check is advisory, the server decides. No migrations. Tables have header associations; bars carry text values; colour is paired with labels; 64 px primary and 44 px secondary targets; `prefers-reduced-motion` honoured.
