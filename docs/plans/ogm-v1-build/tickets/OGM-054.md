## Outcome

`@gm/sdk` exposes `gm.net` to game code: host/peer role, `localPlayerIndex`, `players`, `onPlayerJoined/Left`, `onInput` on the host, fixed-rate `sendSnapshot` from the host and `applySnapshot` with SDK-owned interpolation on peers, `sendEvent/onEvent`, a host-owned seeded RNG and clock, camera rig and HUD slice bound to `localPlayerIndex`; a single-player game is the same game with one host and no bridge traffic; every behaviour has a fixture test and the two templates compile against it.

## Context and evidence

E04-15: multiplayer client hooks are V1; the SDK owns snapshot interpolation; every template implements `MultiplayerHooks`. E07-11: the prototype loop already separates input, simulation and render (`dungeon.js` `keys`/`updatePlay(dt)`/`frame()`/`tick(sec)`), but is keyed by a singleton `player`; the conversion is `players: Map<playerIndex, PlayerState>` plus `applyInput(playerIndex, frame)`. E07-12: `playerIndex` is stamped by the room; the SDK derives "my camera follows my avatar" from `localPlayerIndex`; each client reads only its own devices. E04-13: the host app is the only gamepad reader; the SDK merges host `input.frame` with in-iframe keys into one `ActionFrame` per player (OGM-025). Resolved, do not reopen: the wire form of input is T07's `InputFrame` (≤ 256 B, `axes`/`buttons`), encoded from `ActionFrame` by declared-action order; snapshot `state` is opaque to the room and interpolated by the SDK on numeric `p`/`r` leaves of `entities` by default; no client prediction, no Colyseus Predict (E07-2).

## Scope

- `packages/sdk/src/net/`: `index.ts` (the `gm.net` API), `roles.ts` (role/`localPlayerIndex`/`players` from `net.players` and `net.role` bridge messages, `onPlayerJoined/Left` diffing), `input-codec.ts` (`ActionFrame` ↔ `InputFrame` using the manifest's declared action order; `axes` for `{x,y}`/number actions, `buttons` bitmask for booleans; 256 B guard), `host.ts` (host loop: `onInput(playerIndex, frame)` from `net.input` into the fixed step, `sendSnapshot` every N ticks at 20 Hz from `GameInstance.mp.snapshot()`, `sendEvent`), `peer.ts` (`applySnapshot` with an interpolation buffer of the last two snapshots rendered 100 ms behind, `onEvent` in `seq` order), `codec.ts` (JSON ↔ `Uint8Array` with the 64 KiB and 16 KiB caps), `bind.ts` (camera rig `attach(target, localPlayerIndex)` and `hud(localPlayerIndex)` wiring).
- Integration with OGM-022's runtime: the net module is created by the core with the bridge port, the fixed-step clock, the seeded RNG; the host owns seed and tick; peers do not advance simulation, they render interpolated state; `renderGameToText().players` lists every player.
- Single player: `players = [local]`, `role = 'host'`, no `net.*` messages sent; `gm-sdk check` keeps passing on both templates (OGM-029 consumes).

## Contract and invariants

Consumer. Copy `MultiplayerHooks` from OGM-020 `packages/contracts/src/game.ts` (T04 §4) and `InputFrame`, `LIMITS`, `net.*` payloads from OGM-050 `packages/contracts/src/room.ts`; do not redefine. The obligations this ticket meets, verbatim from T07 §4.3:

> What the SDK must expose to game code (T04 defines names; these are the obligations): `net.role`, `net.localPlayerIndex`, `net.players`, `onPlayerJoined/Left(playerIndex)` (host spawns/despawns), `onInput(playerIndex, frame)` on the host, `sendSnapshot(bytes)` from the host at a fixed rate, `applySnapshot(bytes)` with SDK-owned interpolation on peers, `sendEvent/onEvent`, a seeded RNG and clock the host owns, camera rig bound to `localPlayerIndex`, and a per-player HUD slice. Single-player is the same game with `players.length === 1` and `role === 'host'`.

And the hooks every game implements, from T04 §4 (`@gm/sdk/mp`, OGM-020 owns the type):

```ts
export interface MultiplayerHooks {
  spawn(playerIndex: number, playerId: string): void;                   // host-minted ids, spawn points
  despawn(playerId: string): void;
  snapshot(): { tick: number; state: unknown };                         // host client, 20 Hz (A7 R12)
  applySnapshot(s: { tick: number; state: unknown }): void;             // peers; the SDK interpolates between two snapshots
  hud(playerIndex: number): HudModel;                                   // per-player HUD, private fields never included
}
```
Public API this ticket defines (names final for templates and skills):
```ts
export interface GmNet {
  readonly role: 'host' | 'peer'; readonly localPlayerIndex: number;
  readonly players: ReadonlyArray<{ playerIndex: number; name: string; connected: boolean }>;
  onPlayerJoined(cb: (playerIndex: number) => void): () => void; onPlayerLeft(cb: (playerIndex: number) => void): () => void;
  onInput(cb: (playerIndex: number, frame: ActionFrame) => void): () => void;      // host only
  sendEvent(e: unknown): void; onEvent(cb: (e: unknown) => void): () => void;      // reliable, ordered, ≤ 16 KiB
  readonly snapshotHz: 20; readonly interpolationDelayMs: 100;
}
```
Invariants: inputs for the local player on the host never go through the wire; a peer never advances the simulation; `applySnapshot` is called by the SDK once per render frame with the interpolated state, never with a raw wire snapshot; snapshots are emitted on the fixed-step tick (every 3rd tick at 60 Hz); `seq` gaps in events are reported through `renderInfo()` counters, snapshots out of order are dropped; `renderGameToText()` works with `players.length ≥ 2` (rule 8 of `gm-multiplayer-ready`).

## Failure, security, migration and accessibility cases

The SDK never sees a grant or a socket; it trusts `playerIndex` only as stamped in `net.input` by the host app from the server. Snapshot or event payloads over the caps are refused at `sendSnapshot`/`sendEvent` with a once-per-session warning and a `renderInfo()` counter, never silently truncated. A peer that receives no snapshot for 2 s freezes the last state and raises `net.stalled` through the SDK event path for the HUD. No migration. Touch targets are the host's (OGM-028); the SDK's HUD slice carries no layout.
