## Outcome

On the API, `POST /auth/age` with a birth month and year issues a signed `ogm_age` cookie for adults and returns 403 storing nothing for anyone under 18; sign-up by magic link, passkey registration and the Google start all refuse without that cookie; a session cookie and a bearer session token both resolve to a `user` principal; magic links go to an admin inbox by default; `docs/ops/netlify-proxy.md` holds the exact `_redirects`, `trustedOrigins`, `rpID` and Google redirect values the web app and ingress tickets copy.

## Scope

- `services/api/src/auth/*`: Better Auth instance on the Drizzle adapter (SQLite), plugins `magicLink`, `passkey`, `bearer`; Google social provider enabled only when `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are present; mounted at `/auth/*` through the route scanner.
- Age gate: `POST /auth/age { birthMonth, birthYear }` → 204 + `ogm_age` (HMAC-signed, `SameSite=Lax`, `Secure`, `HttpOnly`, 24 h) or 403; Better Auth before-hooks on sign-up, magic-link send and social sign-in require a valid cookie; on user creation `age_band = 'adult'` and `age_attested_at` are copied to the user row.
- Principal resolver registered into OGM-010's registry: session cookie or `Authorization: Bearer <session token>` → `{ kind: 'user', userId, familyId, platformRole, capability }` (family fields read from OGM-012's tables when present, else `familyId: ''`, `capability: 'player'`, `platformRole` from the `OGM_MAINTAINER_EMAILS` allow-list).
- `POST /api/v1/auth/ws-token` → `{ token: 'ogw1.…', expiresAt }` (HMAC with `OGM_WS_TOKEN_SECRET`, 5 min) and `verifyWsToken()` for services that cannot read cookies.
- `MailSender` interface; `AdminInboxMailSender` writing `mail_outbox` rows; `SmtpMailSender` (nodemailer) selected when `SMTP_URL` is set.
- `packages/db`: Better Auth tables (`user`, `session`, `account`, `verification`, `passkey`) plus `user.age_band`, `user.age_attested_at`, and `mail_outbox`, as one timestamped migration.
- `docs/ops/netlify-proxy.md`.

## Contract and invariants

Quoted from T01 §4 (producer: this ticket):
```http
POST /auth/age { "birthMonth": 1-12, "birthYear": 1900-2026 } → 204 + cookie `ogm_age=<signed band>` | 403 (nothing stored)
```
Sign-up, magic-link and the Google OAuth start require the cookie.

Defined here:
```ts
// services/api/src/auth/age.ts
export type AgeCookie = { band: 'adult'; attestedAt: string; exp: number };       // value: base64url(json) + '.' + base64url(hmac)
export function isAdult(birthMonth: number, birthYear: number, now: Date): boolean; // 18th birthday month reached
// services/api/src/auth/mail.ts
export interface MailSender { send(m: { to: string; subject: string; text: string; html?: string }): Promise<{ id: string }> }
// services/api/src/auth/ws-token.ts
export type WsTokenClaims = { sub: string; familyId: string; exp: number; nonce: string };
export function signWsToken(c: Omit<WsTokenClaims,'exp'|'nonce'>, secret: string, ttlSec?: number): { token: string; expiresAt: string };
export function verifyWsToken(token: string, secret: string, now?: number): WsTokenClaims | null;
```
Config values (names only; values in `~/.config/ogm/env/ogm-api.env`): `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (= `https://ogm2000.netlify.app`), `OGM_APP_ORIGIN`, `OGM_AGE_COOKIE_SECRET`, `OGM_WS_TOKEN_SECRET`, `OGM_MAINTAINER_EMAILS`, optional `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SMTP_URL`, `SMTP_FROM`. Invariants: no password method is enabled; `trustedOrigins = [OGM_APP_ORIGIN]`; passkey `rpID = 'ogm2000.netlify.app'`, `origin = OGM_APP_ORIGIN`; a refused age check writes no row and no log line with the birth values; the user principal's `familyId` is never guessed.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/api test -- auth`: `isAdult` table (18 today, 18 next month, 17, 120); `/auth/age` 204 sets a cookie that `verify` accepts and 403 inserts no row; a magic-link request without the cookie is 403 and with it enqueues one `mail_outbox` row whose text contains the link; a tampered cookie is refused; the session resolver yields a `user` principal from both the cookie and `Authorization: Bearer`; `ws-token` round-trips and expires; the Google provider is absent from `GET /auth/...` provider listing when the client id is unset. ## Failure, security, migration and accessibility cases

Under-18 attempts leave a cookie `ogm_age=refused` (unsigned marker, 365 d) so the screen is not retried, and nothing else (B9 §3). `BETTER_AUTH_SECRET`, cookie and token secrets come only from the unit's env file; the sandbox never sees them (D-SBX). Rate-limit `/auth/age` and magic-link sends per IP and email (10/h). Migration is one timestamped file; the Better Auth generated SQL is reviewed for SQLite types. Google missing (GATE-GOOGLE-OAUTH open) degrades to magic link + passkey, never an error at boot. No UI here; the screens' 64 px targets are OGM-072's.
