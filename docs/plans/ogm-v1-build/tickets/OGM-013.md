## Outcome

`POST /api/v1/jobs` admits, queues or refuses a job deterministically: a slot check (1 new-game + 3 edit per family, repairs on edit), a reservation by size class, a per-member daily allowance that resets at the family's local midnight, four offers on 402, an admin-visible platform cap, and a hard cap written to the job row and mirrored to aiur's per-ticket spend cap through `AiurClient.setSpendCap` once the ticket is filed; queued-at-reset jobs start themselves and emit `job.started`; reservations are released on terminal states.

## Context and evidence

E01-12 and spec §8.3: slots default 1 creation + 3 edits per family, repairs share edit slots (D3), reservation = p80 by kind and complexity, pause and ask an admin at 1× the reservation, stop at the hard cap, one platform cap that is explicit and admin-visible (not hidden; §8.3 reconciled with B8). E01-13 and D-BUDGET-UNIT: under subscriptions the only unit is aiur's `api_equivalent` USD, stored as integer micro-dollars, shown in a friendly unit, reset at local midnight per family (A4). E01-4 and E02-4: aiur has `PUT /:issue/spend-cap`, enforces it and ends in `agent:budget-exhausted`, so no sidecar or watchdog exists (D-JOB-BUS); the cap can only be set after the issue exists (404 before), hence the order file → cap → `agent:todo`. E01-14: the voice tools queue through this same route with `start: at_reset`. Resolved: B8's 1.5× threshold is configuration, not policy; the hidden-cap prohibition is satisfied by making the platform cap a visible setting.

## Scope

- Tables: `jobs` (the `Job` contract row), `family_budget_settings`, `allowances`, `budget_ledger` (reservation/release/usage/adjustment rows), `size_classes` (seeded).
- `services/api/src/jobs/state.ts`: pure `transition(state, event)` for `queued → admitted → filed → running → paused_budget | done | failed | cancelled` plus `paused_budget → running` (admin raise) and `queued → cancelled`.
- `services/api/src/jobs/admission.ts`: `admit(request, actor)` implementing T01 §4 exactly; idempotency by `(creatorId, idempotencyKey)`; D-BRANCH-BASE `branchId !== 'main'` → 409 `branch_not_main`.
- `services/api/src/budget/{allowance.ts,reset.ts,ledger.ts,settings.ts}`: remaining = daily allowance − today's reservations − today's reconciled usage beyond reservations, in the family's zone; platform cap = `platformCapMicroUsd` over the family's day.
- `services/api/src/jobs/spend-cap.ts`: `markFiled(jobId, { repo, issueNumber })` → writes `aiurRepo`, `aiurIssueNumber`, calls `aiur.setSpendCap(issue, usdString(hardCapMicroUsd))`, stores `aiurSpendCapMicroUsd`, transitions to `filed`; `raiseCap(jobId, amountMicroUsd)` for admins.
- `services/api/src/jobs/scheduler.ts`: every 60 s start `at_reset` jobs whose `startAt` has passed and promote `queued` jobs when a slot frees; emits `job.started` and `job.changed`.
- Routes: `POST /api/v1/jobs`, `GET /api/v1/jobs?gameId=`, `GET /api/v1/jobs/:id`, `PATCH /api/v1/jobs/:id` (edit a queued plan), `POST /api/v1/jobs/:id/cancel` (queued only here; running cancel is OGM-033), `POST /api/v1/jobs/:id/raise-cap` (admin).
- Exported functions for siblings: `markFiled`, `markRunning`, `markPaused(reason)`, `markTerminal(state)`, `recordUsage(jobId, microUsd, runId)`, `releaseReservation(jobId)`.

- Accepts job `kind: "scope"` (small size class, edit slot) for OGM-088's scope session.

Invariants this ticket owns: `hardCapMicroUsd = round(reservation.amountMicroUsd × settings.hardCapMultiplier)` (default multiplier 1.0, so aiur's trip is the 1× pause; admins raise); a job is counted against a slot while in `admitted|filed|running|paused_budget`; `queued` jobs never reach GitHub and hold no slot; `at_reset` jobs hold their reservation against tomorrow's allowance and start at `resetsAt`; remaining allowance never goes negative on admission (402 instead) but may after reconciliation (OGM-033 writes usage; the ledger shows it); platform cap default = sum of member daily allowances; every state change emits `job.changed`; the first transition out of `queued` by the scheduler emits `job.started`; terminal states release the unused reservation with one `release` ledger row. Seeded `size_classes` (micro-USD p50/p80, confidence low): `small 500000/1500000`, `medium 1500000/4000000`, `large 4000000/9000000`, `huge 9000000/20000000`; `repair` kind uses one third of the matching class (B8 §6); size class from complexity: 1→small, 2→medium, 3→large, 4–5→huge; `new_game` is at least `large`. Defaults for `FamilyBudgetSettings`: `resetZone` = host zone, `unitLabel` = `"energy"`, `microUsdPerUnit` = 100000, slots `{ new_game: 1, edit: 3 }`, `hardCapMultiplier` 1.0. Default daily allowance per member 5000000 until an admin sets one.

## Failure, security, migration and accessibility cases

`setSpendCap` failure after filing leaves the job `admitted` with `aiurIssueNumber` set and `aiurSpendCapMicroUsd NULL`, returns the error to the caller (OGM-031), and the job never gets `agent:todo` until the cap is stored (fail closed, E02-4). The scheduler runs one tick at a time (a guard flag) and tolerates a missed tick. Allowance arithmetic is integer only. Admission is wrapped in one SQLite transaction (`BEGIN IMMEDIATE`) so two requests cannot both take the last slot. Only admins may `raise-cap`; the creator never sees dollars (unit conversion is OGM-018/OGM-074's). Timestamped migration with seed rows. No UI.
