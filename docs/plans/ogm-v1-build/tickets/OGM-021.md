## Outcome

`packages/iframe-bridge` exports `openHostBridge(iframe, opts)` and `openGameBridge(opts)`; two jsdom windows on different origins complete the hello, transfer a `MessagePort`, exchange id-correlated requests and replies, and the unit suite proves the origin check, the 256 KB cap, the 120 msg/s limit and the unknown-type drop.

## Context and evidence

The decision log keeps the engine–editor contract message-based; A4 §4 rule 5 says hand-write roughly 150 lines (hello with origin check, port transfer, `id` correlation) because Comlink proxies arbitrary calls and Penpal is 567 stars (E04-1). The prototypes post with `'*'` and check only `e.source` (E04-5, E12-4); the real host is cross-origin (D-GAMES-ORIGIN, `:10000/g/<gameId>/<buildId>/`), so every message needs an origin check and a schema. The bridge knows no game concepts: it takes a validator and a message handler; the Zod unions come from OGM-020. Resolved, do not reopen: the wire is a JSON string (so the cap is one `length` check before parse and binary rides as base64, OGM-020 amendment 1); constants `BRIDGE_MAX_BYTES` and `BRIDGE_MAX_MSGS_PER_S` are read from `@ogm/contracts`, not redefined.

## Scope

- Host side: `openHostBridge(iframe, { gameOrigin, validate, onMessage, hello })`: waits for the iframe's `window.postMessage` hello whose `event.origin === gameOrigin` and `event.source === iframe.contentWindow`, replies with the `hello` envelope and a transferred `MessagePort`, then speaks only on the port.
- Game side: `openGameBridge({ hostOrigin, validate, onMessage })`: posts the hello to `window.parent` with `targetOrigin = hostOrigin`, accepts the port only from a message whose `origin === hostOrigin`, resolves `ready` once the port is open.
- Both: `send(envelope)`, `request(envelope) → Promise<reply>` correlated by `replyTo`, `close()`; inbound: length ≤ `BRIDGE_MAX_BYTES` else drop + count, token bucket at `BRIDGE_MAX_MSGS_PER_S` else drop + count, `validate(raw)` returning `null` drops + counts; `stats()` exposes the three counters; one `error` envelope per second at most when dropping.
- Zero game or editor imports; the package depends on `@ogm/contracts` for the two constants and the `Envelope` type only.

## Contract and invariants

Consumer of OGM-020 `packages/contracts/src/bridge.ts` (`Envelope`, `BRIDGE_MAX_BYTES`, `BRIDGE_MAX_MSGS_PER_S`); copy, do not redefine. This package's own public shape:

```ts
export type Validator = (raw: unknown) => { v: 1; id: string; t: string; payload: unknown; replyTo?: string } | null;
export interface Bridge {
  ready: Promise<void>;
  send(env: Envelope<string, unknown>): void;                       // throws BridgeError('too_large') before posting
  request<R>(env: Envelope<string, unknown>, timeoutMs?: number): Promise<R>;   // resolves on a message whose replyTo === env.id
  close(): void;
  stats(): { dropped: { tooLarge: number; rateLimited: number; invalid: number }; sent: number; received: number };
}
export function openHostBridge(iframe: HTMLIFrameElement, opts: { gameOrigin: string; validate: Validator; onMessage: (env) => void; hello: Envelope<'hello', unknown> }): Bridge;
export function openGameBridge(opts: { hostOrigin: string; validate: Validator; onMessage: (env) => void; helloPayload: unknown }): Bridge;
```

Invariants: no message is delivered to `onMessage` before `ready`; a hello from any other origin or source is ignored silently (never answered, so a probe learns nothing); after the port is open, `window.message` listeners are removed; the wire is `port.postMessage(JSON.stringify(env))` and the receiver checks `typeof data === 'string' && data.length <= BRIDGE_MAX_BYTES` before `JSON.parse`; `request` rejects with `BridgeError('timeout')` after `timeoutMs` (default 5000) and with `BridgeError('closed')` on `close()`; counters only ever increase.

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/iframe-bridge test` proves: hello from the wrong origin is ignored and `ready` stays pending; hello from the right origin and source transfers a port and resolves `ready` on both sides; a 262,145-char string is dropped and counted (`tooLarge`), a 262,144-char one delivered; 121 messages in one second drop the 121st (`rateLimited`) and the 122nd after a 1 s refill is delivered; `validate` returning `null` drops and counts (`invalid`); `request` resolves on `replyTo` and rejects on timeout; `close()` rejects pending requests. ## Failure, security, migration and accessibility cases

A hostile frame posting hellos is never answered; after handshake nothing on `window.message` is read, so later injected messages cannot reach the game. Oversized or flooding peers are throttled without exceptions escaping to the caller. No secrets: the bridge carries no tokens (room grants stay in the host app, E07-4). No migrations, no UI.
