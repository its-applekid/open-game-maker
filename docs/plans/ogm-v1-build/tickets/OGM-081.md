## Outcome

From inside a build, `gm chat post --job $GM_JOB --clip shots/phone/run.mp4 --poster shots/phone/t0.png --text "first pass of the jump"` prints a message id and the clip appears in the creator's chat; `gm checkpoint open … --option a=Chunky --media a=<id> --recommend a` writes the candidates to the chat and prints the exact `emit_event` call the agent makes to raise the aiur Command; `gm checkpoint wait <id>` blocks until the creator answers and prints the chosen option id.

## Context and evidence

The design skill already says "post a screenshot (or a short clip) with one line at each visible milestone" but names no command (E06-14); `gm` does not exist anywhere in the repo (E05-20, E10-16). Direction checkpoints map onto aiur Commands raised by the worker with `decision.requested`; a blocking Command holds only that worker, so "only dependent work pauses" (E06-15). Candidates are lineups, presets or ≤10 s clips of existing scaffolds, never separate agent builds (E06-16, D-BUILD-CHAT).

Contradictions already resolved: (1) T06 §4 wrote that `gm checkpoint open` "emits `decision.requested` through the aiur agent tools and returns the Command id". Verified at aiur `0f692a45b`: `emit_event` is an MCP tool bound to the runner session (`src/lib/aiur/agent_tools/mcp.ex`, `emit_event.ex`); there is no shell path and the sandbox has no network (E03-4). So the command prepares the Command (candidates posted, payload printed) and the agent's own `emit_event` call raises it; OGM-082 correlates the Command to the checkpoint by a marker in the payload. (2) `gm progress --media` (T10 §4, E10-13) and `gm chat post` are one function: this ticket owns `commands/chat/` and exports `postChat()`; OGM-090's `gm progress` imports it and adds the activity event.

## Scope

- `packages/gm-cli/src/commands/chat/post.ts`: `gm chat post --job <id> --text "<one line>" [--image <png>] [--clip <mp4> --poster <png>]` → copies media into `.gm/outbox/media/<sha256>.<ext>`, appends one `AgentOutboxLine` (`type: "chat.post"`, ULID id) to `.gm/outbox/chat.jsonl`, prints the id (`--json` prints the line). Exports `postChat(opts): Promise<{ id }>`.
- `packages/gm-cli/src/commands/checkpoint/open.ts`: `gm checkpoint open --job <id> --question "<q>" --option <id>=<label> … [--recommend <id>] [--media <id>=<chat message id>] [--blocking]` → appends a `checkpoint.open` line (checkpoint id `cp_<ulid>`, options, media ids, recommend, blocking) and prints the checkpoint id plus the `emit_event` tool-call JSON (name `decision.requested`, options with descriptions, `recommendation.option_id`, `blocking`, `kind: "direction_checkpoint"`, `authority: "supervisor_allowed"`, `reversibility: "reversible"`, marker `<!-- gm-checkpoint:cp_… -->` in `context.long_context_markdown`).
- `packages/gm-cli/src/commands/checkpoint/wait.ts`: `gm checkpoint wait <cp_id|decision_id> [--timeout <s>]` → polls `.gm/inbox/checkpoints/<id>.json` every 2 s; prints the option id; exit 3 on timeout, 4 when the checkpoint is `moot`.
- Job context: `--job` defaults to `$GM_JOB`, then `.gm/context/job.json` (`job_id`), else exit 2 with the cause. Workspace root = the git toplevel of the cwd.
- Activity event: when `$GM_EVENTS_FILE` is set, append `{event:"chat.post"|"checkpoint.open", job_id, ts, payload:{kind}}` (E05-19).

- Also owns `gm progress "<line>" [--media <file>]` (the activity marker and show-as-you-go post; T10 §4) as a thin alias over the same outbox line kind as `gm chat post`, so the skills have one command for markers and one for media.

## Contract and invariants

Consumer of OGM-080: copy `BuildChatMessage` and `AgentOutboxLine` from `packages/contracts/chat.ts`; do not redefine. The `chat.post` payload this ticket writes: `{ kind: "text"|"image"|"clip", text?: string, file?: ".gm/outbox/media/<sha>.<ext>", poster?: ".gm/outbox/media/<sha>.png" }`. The `checkpoint.open` payload (producer: this ticket; consumer OGM-082):

```ts
type CheckpointOpenPayload = { checkpoint_id: `cp_${string}`; question: string;
  options: { id: string; label: string; media_id?: string }[];   // 2–5 options; media_id = a chat message id in this job
  recommend?: string; blocking: boolean };
```
Printed `emit_event` call (the agent copies it verbatim into its tool call; shape per aiur `.agents/skills/aiur-agent/emit-and-subscribe.md` "Requesting an operator decision"):
```json
{ "name": "decision.requested", "message": "<question>",
  "payload": { "question": "<question>", "blocking": false, "kind": "direction_checkpoint",
    "authority": "supervisor_allowed", "reversibility": "reversible", "urgency": "normal",
    "context": { "short_summary": "Direction checkpoint for the creator", "long_context_markdown": "<!-- gm-checkpoint:cp_… -->\nOptions are previews already posted in the build chat." },
    "options": [ { "id": "a", "label": "Chunky", "description": "Use the chunky low-poly family" } ],
    "recommendation": { "option_id": "a", "reason": "Closest to the vibe chosen at creation" },
    "consequence_of_delay": "Independent work continues; the dependent step waits for the answer." } }
```
Invariants: option ids are `[a-z0-9_-]{1,32}`, 2–5 of them, unique; `--media` ids must have been printed by `gm chat post` in this workspace (checked against `.gm/outbox/chat.jsonl`); `--blocking` is off by default (E06-15); the outbox line is written with one `O_APPEND` write ≤ 64 KiB; the command never opens a socket; media paths are always inside `.gm/outbox/media/`; exit 2 on refusal with a one-line cause and the suggested command (T05 §4 convention).

## Acceptance and verification

### Agent gate
- `pnpm --filter @ogm/gm-cli test -- chat`: `post --clip --poster` copies both files under `.gm/outbox/media/` by sha256, appends one line validating against `AgentOutboxLine`, prints the id; a missing `--job` with no `.gm/context/job.json` exits 2; a clip over 25 MiB exits 2 naming the limit. Each fails without the command.
- `pnpm --filter @ogm/gm-cli test -- checkpoint`: `open` with two options and one `--media` writes a `checkpoint.open` line and prints JSON whose `payload.context.long_context_markdown` contains `gm-checkpoint:cp_`; `--media` naming an unknown id exits 2; one option exits 2; `wait` returns the option id when the inbox file appears and exits 3 after `--timeout 1`.
### At-merge gate
- `ci / required` green on current main.
### Human or e2e evidence
- None here; OGM-082's e2e covers open → answer → wait.

## Failure, security, migration and accessibility cases

- Agent forgets the `emit_event` call: the checkpoint card still appears (OGM-082 shows "waiting for the builder to ask") and `wait` times out with a message telling the agent to make the call; the skill text (T10) makes the call mandatory.
- Outbox dir missing: created on first use (`mkdir -p`); write errors are exit 1 with the path.
- No secrets: the command reads no tokens; it never leaves the workspace. Media copied, not moved, so later `gm run` overwrites do not change what was posted.
- No migration. No UI (64 px rule not applicable).
