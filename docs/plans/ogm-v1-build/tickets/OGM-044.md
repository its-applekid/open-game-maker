## Outcome

Given branch B forked from `main` at rev 40, `main` changed `entities.door1.props.locked` to true at rev 45 and B changed it to false at rev 12, `POST /api/v1/games/:g/branches/main/merges {sourceBranchId: B}` returns a `MergePlan` with exactly one `both_changed` conflict and every other change in `auto` (AE3); resolving it and landing produces one `kind: 'merge'` transaction on `main`, marks B `merged`, and `POST …/merges/:id/rollback` applies the inverse as a new transaction.

## Context and evidence

The three-way merge is per stable id and per field: base = fork point, ours, theirs; different paths merge automatically; same value merges; conflicts are `both_changed`, `delete_vs_edit`, or `control_removed` when a build retired a control the other side tuned; the result is one undoable transaction, previewed before landing (E08-10, C2 §8). With entities as a map, every patch path is `['entities', id, …]` so last-write-per-path reduction is exact; stroke patches reduce per chunk key (E08-10). Resolved here: because agent code jobs run on `main` only and branches never diverge in Git in V1 (E08-9, D-BRANCH-BASE), `MergePlan.code` is always `'clean'` in V1 and `{conflictJobId}` stays reserved; the "preview build" is the target's `latestBuildId` with the merged working set applied through the bridge (no agent job, no Git); landing a branch into `main` records the merge in Git through `fold_design` only at the next Publish (OGM-045), not here. The voice tool shape (`list_conflicts`, `resolve_conflict`, `resolve_all`) is documented and mapped 1:1 to routes; `voice_converse` has no host tool port yet (E06-8), so OGM-077's screen is the V1 caller.

## Contract and invariants

Consumer: copy `MergePlan`, `MergeConflict`, `FieldChange`, `SideDelta`, `Transaction`, `Branch` from OGM-040's `packages/contracts/src/{branches,design-log}.ts`; do not redefine. Algorithm (fixed, from T08 §4): (1) base = `replay(target)` at the source's `forkPoint.parentRev`; ours = `sideDelta(source txs since fork)`, theirs = `sideDelta(target txs since fork)`, entity create/delete as tombstones, stroke patches reduced per chunk key; (2) per path: only one side changed → take it; both changed to deep-equal values → take it; otherwise `MergeConflict` (`both_changed`; `delete_vs_edit` when one side deleted the entity the other edited; `control_removed` when the other side's build retired the control); (3) `auto` patches plus resolved conflicts become one `Transaction{kind:'merge'}` on the target, previewed first, landed on confirm; rollback applies its inverse as a new transaction.

```http
POST /api/v1/games/:g/branches/:target/merges {sourceBranchId}      → 201 MergePlan(status:'planned'|'resolving')
POST …/merges/:planId/conflicts/:conflictId {resolution}            → 200 MergePlan   resolution: 'ours'|'theirs'|'both'|{value}
POST …/merges/:planId/resolve-all {resolution:'ours'|'theirs'}       → 200 MergePlan
POST …/merges/:planId/preview                                        → 200 {previewBuildId, doc, rev}   status 'previewing'
POST …/merges/:planId/land                                           → 200 {rev}  (409 unless every conflict is resolved)
POST …/merges/:planId/rollback                                       → 200 {rev}  (landed only)
```

Invariants: a plan is computed from the logs at creation and carries `baseRev`; landing re-checks that the target's head has not moved past the plan's recorded target head (409 `target_moved`, replan); exactly one transaction lands per plan; `'both'` is valid only for `delete_vs_edit` (keeps the entity and the edit); `{value}` must pass `validateValue` for the control; the merge transaction's `label` is "Merged <source name> into <target name>"; `status` moves `planned → resolving → previewing → landed | abandoned` and never backwards.

## Failure, security, migration and accessibility cases

A plan older than its target's head cannot land (replan, never silently rebase). Plans are per game and only `game.edit` holders of that game read or mutate them (OGM-012 policy). The merge transaction uses the service lease path (`leaseToken 0`, `kind:'merge'`) but still carries the caller's `sessionId` so a stale editor cannot land. Patches are validated with OGM-040's `validatePatches` so nothing outside `globals`/`entities` reaches the log or the room relay. One timestamped migration. No secrets. Screen accessibility is OGM-077's (64 px primary targets for Keep mine / Use theirs).
