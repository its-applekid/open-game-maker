## Outcome

`ops/bin/ogm-ingress.sh` applies the serve/funnel map (8443 → API with `/ws/rooms` and `/ws/voice` mounted to the rooms and voice ports; 10000 → games host), leaves port 443 untouched, is idempotent and has `--dry-run` and `--off`; `docs/ops/ingress.md` records the origin map, the `_redirects`/`_headers` lines OGM-070 writes, the hand step Kevin runs, and the outside check; after the gate, `curl https://applekid.tailee0e71.ts.net:8443/healthz` from a phone off the tailnet returns the health JSON.

## Context and evidence

Tailscale 1.104.2 is installed, MagicDNS is on, the node has a cert for `applekid.tailee0e71.ts.net` and Funnel capability on 443/8443/10000; no Caddy, nginx, certbot or cloudflared exists and no domain is owned, so Tailscale is the whole reverse-proxy and TLS story at zero cost (E11-5). Port 443's root path already serves another app tailnet-only, so OGM takes 8443 (API, WebSockets, blobs) and 10000 (games origin) and leaves 443 alone. `OperatorUser` is `applekid`, so this account cannot change serve/funnel until Kevin runs `sudo tailscale set --operator=orangekid` (GATE-TS-OPERATOR). Cookies must stay first-party on `ogm2000.netlify.app`: `/api/*` and `/auth/*` are Netlify 200 rewrites to 8443; WebSockets go direct with short-lived tokens because Netlify proxies carry no upgrades (E11-6, D-ORIGIN). Resolved: Funnel on (invites need the public hostname; tailnet-only is the documented fallback); no per-game subdomains without a domain (E11-7, D-GAMES-ORIGIN); every service binds 127.0.0.1 and Tailscale is the only listener on the public side (E11-11).

## Scope

- `ops/bin/ogm-ingress.sh [--dry-run] [--off] [--tailnet-only]`: reads the four ports by name from `~/.config/ogm/env/{api,rooms,voice-host,games}.env` (grep, never sourcing secrets), runs the `tailscale serve`/`funnel` commands for 8443 and 10000, verifies with `tailscale serve status`, never touches 443.
- `ops/test/ingress.sh`: fake `tailscale` on PATH records every invocation; asserts the exact command set, idempotence, that `--off` removes only 8443/10000 mounts, and that no invocation names 443.
- `docs/ops/ingress.md`: the origin map, the Netlify `_redirects` and `_headers` lines (copied by OGM-070), the CSP `connect-src`/`frame-src` entries, Kevin's hand step, the outside `curl` check, bandwidth and timeout caveats, the tailnet-only alternative.

- The serve map includes `--set-path /ws/voice http://127.0.0.1:40400` for the voice host (OGM-085) and `/ws/rooms` for OGM-051, both on 8443.

## Contract and invariants

Ingress map (owner: this ticket; consumers OGM-010, OGM-051, OGM-085, OGM-007, OGM-070, OGM-100):

```
https://ogm2000.netlify.app/                       Netlify static app (OGM-070)
https://ogm2000.netlify.app/api/*   -> _redirects:  /api/*   https://applekid.tailee0e71.ts.net:8443/api/:splat   200
https://ogm2000.netlify.app/auth/*  -> _redirects:  /auth/*  https://applekid.tailee0e71.ts.net:8443/auth/:splat  200
wss://applekid.tailee0e71.ts.net:8443/ws/rooms/*   rooms (OGM-051), token auth, no cookies      -> 127.0.0.1:$OGM_ROOMS_PORT
wss://applekid.tailee0e71.ts.net:8443/ws/voice/*   voice host (OGM-085), token auth              -> 127.0.0.1:$OGM_VOICE_PORT
https://applekid.tailee0e71.ts.net:8443/*          everything else: API, /blobs/*, /ws/chat SSE  -> 127.0.0.1:$OGM_API_PORT
https://applekid.tailee0e71.ts.net:10000/g/<gameId>/<buildId>/   games origin (OGM-007)         -> 127.0.0.1:$OGM_GAMES_PORT
https://applekid.tailee0e71.ts.net/ (443) and :80  untouched (pre-existing tailnet-only serves)
```

Netlify `_headers` additions for the app (documented here, written by OGM-070): `Content-Security-Policy` with `connect-src 'self' https://applekid.tailee0e71.ts.net:8443 wss://applekid.tailee0e71.ts.net:8443` and `frame-src https://applekid.tailee0e71.ts.net:10000`.

Invariants: mount paths are passed to the upstream unchanged (rooms and voice mount under `/ws/rooms`, `/ws/voice` themselves; verified on the first real run and recorded in the doc); every upstream is `127.0.0.1`; the script prints ports but never an env value other than ports; `--off` never removes the 443/80 mounts.

## Refreshable implementation notes

Create `ops/bin/ogm-ingress.sh`, `ops/test/ingress.sh`, `docs/ops/ingress.md`. The command set (default; `tailscale serve --help` on 1.104.2 is the authority at pickup): `tailscale serve --bg --https=8443 http://127.0.0.1:$OGM_API_PORT`, `tailscale serve --bg --https=8443 --set-path=/ws/rooms http://127.0.0.1:$OGM_ROOMS_PORT`, `tailscale serve --bg --https=8443 --set-path=/ws/voice http://127.0.0.1:$OGM_VOICE_PORT`, `tailscale serve --bg --https=10000 http://127.0.0.1:$OGM_GAMES_PORT`, then `tailscale funnel --bg 8443 on` and `tailscale funnel --bg 10000 on` (skipped with `--tailnet-only`); `--off` runs the matching `… off` forms. Env names from OGM-003 (`OGM_API_PORT`, `OGM_ROOMS_PORT`, `OGM_VOICE_PORT`, `OGM_GAMES_PORT`). Refreshable against 9508c1c.

## Failure, security, migration and accessibility cases

- Public exposure: Funnel makes 8443/10000 reachable by anyone; sign-in and tokens are the protection (OGM-011/052); `--tailnet-only` exists for Kevin's stricter choice (T11 §6 risk 1).
- Netlify proxy timeouts and credit cost per GB: only JSON goes through the proxy; blobs, game bundles and sockets go direct (E11-6); documented.
- If Tailscale strips the `--set-path` prefix, rooms and voice see `/` instead of `/ws/rooms`: the first real run records the behaviour and the two services mount accordingly (deferred question with default in the plan).
- A stray `0.0.0.0` listener on the host is not ingress but is reachable over IPv6 (E11-11): `ogm-status` (OGM-008) flags it; nothing here binds.
- No secrets in the script's output; no migrations; no UI.
