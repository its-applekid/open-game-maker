# Thumbnail scenes

Style-picker illustrations are generated from asset cards. They are private-library artifacts, not source assets: keep scene JSON, vendor references, frames, stills, and loops under ignored `assets-local/` paths.

## Tiers

| Tier | Purpose | Required output |
|---|---|---|
| A | Static picker art | One specimen per compatibility set and pack; one 1024 px and one 256 px square diorama per world |
| B | Living picker art | The same world scene as a four-second 1024 px H.264 MP4 and 256 px looping GIF |
| C | Promotion | A later trailer renderer; documented here for precedence but not implemented by the SmallScaleInt pilot |

Prefer a generated diorama. A fetched store screenshot or GIF is a local `vendor-metadata` fallback only; it is not game-shippable content.

## Output layout

Set outputs use these keys relative to the asset-library root:

```text
sets/<set-id>/previews/specimen.png
sets/<set-id>/previews/diorama.<world>.scene.json
sets/<set-id>/previews/diorama.<world>.1024.png
sets/<set-id>/previews/diorama.<world>.256.png
sets/<set-id>/previews/diorama.<world>.1024.mp4
sets/<set-id>/previews/diorama.<world>.256.gif
```

A pack specimen is `packs/<pack-id>/previews/specimen.png`. A pack collection card points its `previews.diorama` and `previews.loop` at its world's set outputs; it does not copy the generated bytes. A style-set entry contains the set specimen plus a world-keyed still/loop map. These are private bucket keys and the public catalog API must not expose or sign them.

## Tier A specimens

The selector reads cards, sorts by card id, and greedily chooses the card that covers the most unseen dimensions. Set specimens cover world, pack, and `kind/subkind`; pack specimens cover `kind/subkind`. Card id breaks ties. A pack with no renderable card is an error rather than an empty cell.

Frames are drawn on a neutral `#c8c3b8` grid with no labels. Each source pixel is preserved using an integer scale and nearest-neighbour sampling. Input order must not affect selected cards or PNG bytes.

## Diorama contract

`packages/contracts/schemas/thumbnail-scene.v1.json` is the emitted schema. A scene contains only versioned asset-card ids; it never embeds a source path or URL. The renderer resolves each id through the selected asset root and rejects traversal or symlink escapes.

The pilot constants are fixed:

- 1024×1024 canvas; 256×256 derivative.
- 2:1 isometric grid, 128×64 pixels, origin `[512, 256]`, elevation 32 pixels.
- `(x, y, z)` projects to `[512 + (x - y) × 64, 256 + (x + y) × 32 - z × 32]`, plus the declared integer pixel offset.
- Pixel snapping and nearest-neighbour scaling; opacity 1; source-baked lighting with white tint and no relighting.
- Exactly one ground layer, three to six props, and two or three characters; exactly one hero and at least one enemy. The hero anchor projects to `[512, 512]`.
- Four seconds at 24 fps: 96 source frames. Each animated layer advances independently through its card clip and phase; static layers do not move.
- MP4 uses H.264, `yuv420p`, and fast-start metadata. GIF is 256 px, nearest-neighbour, and loops forever.

Layers are drawn by `z_order`, projected anchor Y, then layer id. That order is independent of the JSON array order. A still always uses each layer's declared frame at time zero.

## Store references

Before composing a world, fetch the artist's public itch page media for each pack. Review the creator listing to establish the page-to-pack mapping, then run:

```bash
node apps/web/tools/thumbnail-scene.mjs fetch-store \
  --root assets-local \
  --pack <pack-id> \
  --page https://<creator>.itch.io/<page>
```

The fetcher accepts a plain HTTPS `*.itch.io` creator page and verified images from `img.itch.zone`. It bounds redirects, response sizes, media count, and request time; sends no credentials; verifies content type and file signature; ignores purchase links; and atomically writes `packs/<pack-id>/store/media.json`. Existing metadata survives a failed refresh.

Use store media to judge the artist's framing, character/tile pairing, palette, and motion. Do not trace it into source art, publish it, or add its URLs to committed files.

## Render commands

Build or refresh `index/cards.index.json`, then generate a specimen from its `cards` array:

```bash
node apps/web/tools/thumbnail-scene.mjs specimen \
  --root assets-local \
  --cards assets-local/index/cards.index.json \
  --target-kind pack \
  --target-id <pack-id> \
  --output packs/<pack-id>/previews/specimen.png
```

For the set, use `--target-kind set --target-id <set-id>`. Render each validated scene with:

```bash
node apps/web/tools/thumbnail-scene.mjs render \
  --root assets-local \
  --scene assets-local/sets/<set-id>/previews/diorama.<world>.scene.json \
  --output sets/<set-id>/previews/diorama.<world>
```

The renderer binds an ephemeral server to `127.0.0.1`, blocks browser egress, writes stills before encoding, and atomically replaces final video outputs only after both encodes succeed. Install `ffmpeg` with `sudo apt install ffmpeg` when it is absent.

## Later-set survey

- Kenney's 918×515 sheets can be cropped when a representative composition already exists.
- KayKit's 1920×1080 logo sheets may be cropped when they show the actual set rather than branding alone.
- Synty has only store tiles; its animation-heavy sets need rendered dioramas.
- LimeZu interior previews are useful crop candidates when the room composition represents the pack.
- SmallScaleInt, TinyRPG, Quaternius, and Synty animation packs need rendered dioramas so characters, tiles, props, and motion are judged together.

Record set-specific visual findings under `docs/plans/ogm-v1-build/asset-qa/`. Do not turn a local render inspection into an approval claim; final curation remains an operator review.
